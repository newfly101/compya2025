# Claude 작업환경 재정비

작업 도구(Claude Code 에 붙는 확장)를 **정리하고 · 겹치는 것을 줄이고 · 무료인 것만 골라 붙인** 결과.

---

## 1. 왜 했나

| 문제 | 어떤 증상으로 나타났나 |
|---|---|
| 비슷한 도구가 같은 요청에 동시 반응 | "이 화면 디자인 손봐줘" 한 마디에 디자인 스킬 3종이 전부 후보 — 매번 다른 게 걸려 결과가 들쭉날쭉 |
| 규칙과 실제가 어긋남 | `CLAUDE.md` 는 `docs/convention/frontend.md` 를 공식 참조로 선언했는데, 에이전트 4곳은 `.claude/conventions/fe-code-base.md` 를 읽고 있었다 |
| 폐기물이 검색에 계속 걸림 | 폐기 표시만 하고 안 지운 파일 4,900여 줄이 grep 때마다 같이 나옴 |
| 죽은 연결이 살아있는 척 | 로컬 Figma 연결이 응답 없는 상태로 등록만 남아, 어느 Figma 가 진짜인지 헷갈림 |
| 정체불명 파일 더미 | `.claude/skills/` 의 3,384줄이 스킬 등록도 안 됐고 참조되지도 않는 상태로 방치 |

**제약** — 돈이 드는 것은 붙이지 않는다. 전부 무료로만 구성.

---

## 2. 도구 구성 — 기존 대비

| 갈래 | 이전 | 이후 | 달라진 점 |
|---|---|---|---|
| 디자인 레퍼런스 | 없음 | **Inspo** | 참고 화면을 말로 설명받는 대신 실제 사례를 받아온다 |
| 브라우저 | `claude-in-chrome` 만 | + **Playwright** | 반복 검사에서 매번 같은 결과가 나온다 |
| 그림 | `dataviz` · `artifact-diagramming` | + **Archify** | 독립 HTML 구조도가 가능해졌다 |
| 모션 | `ui-ux-pro-max` 의 프리셋으로 대용 | + **emil-design-eng** | 애니메이션 전용 판단 기준이 생겼다 |
| 과잉구현 억제 | 없음 | **Ponytail** | 새로 짜기 전에 있는 것부터 찾게 한다 |
| 외부 연결 | 계정 커넥터 5 + 죽은 로컬 1 | 계정 커넥터 5 + Inspo + Playwright | 죽은 연결 제거, 살아있는 것만 남음 |

### 붙인 것 — 5종, 전부 무료

| 이름 | 형태 | 범위 | 라이선스 |
|---|---|---|---|
| Inspo | 외부 연결 | 모든 프로젝트 | MIT |
| Playwright | 외부 연결 | 모든 프로젝트 | Apache |
| Archify | 스킬 | 전역 | MIT |
| emil-design-eng | 스킬 | 전역 | 무료 |
| Ponytail v4.10.0 | 플러그인 | 사용자 | MIT |

### 안 붙인 것 — 사유를 남긴다

| 이름 | 사유 |
|---|---|
| Mobbin · Refero · Nicelydone | 유료 구독 전제 |
| Lazyweb | 검색은 무료지만 쓸 만한 기능이 월 $19 |
| InspoAI (inspoai.io) | 이름만 비슷한 별개 서비스. 무료인 Inspo 로 대체 |
| Graphify | 무료지만, 읽을 범위를 좁히는 일은 이미 `CLAUDE.md` 가 한다 |
| OmniRoute | 도구 검색 기능을 꺼버려 나머지 구성과 정면 충돌 |

이름 정정 — `layweb → Lazyweb` · `포니테일 → Ponytail` · `옴니라우트 → OmniRoute` · `그래피파이 → Graphify`.

## 3. 향상된 점

| 항목 | 이전 | 이후 |
|---|---|---|
| 같은 요청에 반응하는 도구 | 디자인 3종이 동시 후보, 정답 미정의 | 요청별 단일 정답을 표로 확정 (`.claude/conventions/tool-routing.md`) |
| 도구 고르는 기준 | 없음 | 다섯 갈래를 비용 순으로 정렬 — 컨벤션 문서로 되면 스킬로 내려가지 않는다 |

| 폐기물 | 활성 폴더에 4,900여 줄 | 0 |
| 죽은 외부 연결 | 1건 등록 | 0 |
| 정체불명 파일 | 3,384줄 | 0 — 참조 문서로 성격 확정 |
| 켜진 디자인·모션 스킬 | 3종 | 4종 (모션 1종 추가, 형제 스킬 12종은 끔) |

## 4. 누락이었던 것 — 수정 내역

| 무엇이 누락이었나 | 어떻게 고쳤나 |
|---|---|
| 에이전트가 `CLAUDE.md` 선언과 다른 컨벤션을 읽음 | `fe-code-base.md` 내용을 `docs/convention/frontend.md` 해당 항목에 흡수, 참조 6곳을 새 경로로 교체 |
| 폐기 선언만 하고 파일은 남김 | 폐기 에이전트 4개 · `figma-plugin.md` · `responsive-pc-first.md` · `plugin-code` 삭제 |
| 짝이 없어진 반응형 문서 | `responsive.md` 의 고유 항목 4개만 `responsive-mobile-first.md` 에 흡수 후 삭제 |
| 설정 폴더에 컴포넌트 가이드 | `badge-components.md` 를 `docs/convention/` 으로 이동 |
| 응답 없는 로컬 Figma 연결 | 연결 해제 + 권한 허용 목록 3개 항목 제거 |
| 스킬도 참조 문서도 아닌 더미 | `.claude/references/` 로 옮겨 참조 문서로 성격 확정, `.claude/skills/` 폴더 제거 |
| 라우팅 규칙이 어디에도 없음 | 규칙 파일 신설 + `CLAUDE.md § 1.1` 에서 링크 |

## 6. 손대지 않기로 한 것

| 대상 | 왜 그대로 두나 |
|---|---|
| `impeccable` 두 벌 (`~/.claude/skills/` · `~/.agents/skills/`) | 중복이 아니라 **의도된 2벌**이다. 같은 버전을 설치기가 동시에 깐 것으로, 앞쪽은 슬래시 커맨드·도구 권한이 붙은 Claude Code 전용 빌드이고 뒤쪽은 범용 빌드다. 한 벌로 합치면 `/impeccable` 호출과 권한 설정이 사라진다 |
| 에이전트 모델 지정 | `CLAUDE.md` 의 정책 표와 실제 설정이 이미 전부 일치 |
| 계정 커넥터 5종 | 정상 동작 중 |

## 7. 남은 것

|---|---|
| 세션 재시작 필요 | Inspo · Playwright 는 연결 확인까지 끝났지만, 도구 목록은 Claude Code 를 다시 켜야 올라온다 |
| github 커넥터 실패 | 계정 커넥터 `claude.ai github` 가 HTTP 422 로 연결 실패 중. 이번 범위 밖 |

| 한 달 뒤 재검토 | Inspo 로 못 찾은 사례가 3건 이상 쌓이면 유료 결제를 다시 본다. 그때도 **하나만** 켜고 Inspo 는 끈다 |
