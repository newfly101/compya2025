# 0010 레전드 콘텐츠 흐름 재설계

## 배경

레전드 관련 화면이 3개(재료 검색·재료 보유 현황·스킬 기록)로 늘었는데 서로 이어져 있지 않았다.

- 서랍 메뉴 '컨텐츠' 가 평평한 9개이고 '내 재료 보유 현황' 항목이 없다. 이름도 화면마다 다르다("레전드 재료 평점표" · "레전드 재료 보유 현황" · "내 레전드 스킬 기록").
- 홈 퀵아이콘 7개가 고정이라 이용자가 자주 쓰는 화면을 고를 수 없다.
- 로그인이 필요한 화면의 처리가 세 방식으로 갈린다(라우트 가드 · 화면 안 모달 · 메뉴 모달). 모달 코드도 두 군데에 복사돼 있다.
- 보유 현황은 "읽는 화면"과 "고치는 화면"이 한 몸이라 첫 화면에서 표까지 약 640px, 누를 것 22개였다(`ui-critique.md`). 홈 '오늘 히스토리 모드' 카드는 기획만 있었다.

## 목표 흐름

```
홈 ─▶ 재료 검색 / 내 보유 현황 ─▶ 스킬 기록 ─▶ (이후) 덱 공유
 │      (누구나)   (열람 누구나·기록 로그인)  (로그인)
 └ 내 컬렉션 카드 · 오늘 히스토리 · 이번 주기 일정 · 바로가기
```

## 결정 (최종, 2026-10-03 코드 기준)

| 항목 | 내용 |
|---|---|
| 이름 | 서랍·홈 카드·바로가기: **재료 검색** · **내 재료 보유 현황** · **내 레전드 스킬 기록**. 상단바 제목은 세 화면 모두 "레전드 재료", 탭 라벨은 [재료 검색 \| 내 보유 현황 \| 스킬 기록]. 주소는 바꾸지 않는다. 본문 부제는 없다 |
| 공용 머리 | 상단바 아래 **공용 탭 3개**(탭마다 고유 주소, 관리·편집 주소에서도 해당 탭 켜짐) → **'이 페이지 활용 가이드' 아코디언**(공용 `GuideAccordion`, 본문 항상 DOM). 화면 사이 텍스트 링크(→ ←)는 없다 |
| 필터 | 세 화면 모두 **검색이 필터 영역 안**(공용 `FilterSection` + `SearchInput`, 검색창 3벌 → 1벌)이고 칩 줄은 **항상 펼침**. 다른 화면의 공용 접이식 필터는 그대로 |
| 조회와 관리 분리 | **조회 화면은 읽기 전용, 관리는 별도 주소.** 보유 현황: `/legend-collections` 검색 줄 `[검색][선호][관리]` → `선호` 는 모달(최대 10명 · 후보 검색 · `전체/타자/투수` · 순위 끌기 · 액자 토글), `관리` 는 `/legend-collections/manage`(같은 머리, 검색 줄 `[검색][취소][저장 (N)]`). 스킬 기록: `/legend-collection-skills` 목록 행 → `/legend-collection-skills/:legendId/edit`. 새 주소는 noindex, 비로그인 직접 진입은 같은 주소의 안내 화면 + 공용 로그인 모달. 이탈 차단은 관리·편집 화면에만 |
| 상태의 원천 | 보유·액자 상태는 **보유 현황 관리 화면에서만** 바꾼다. 스킬 기록은 읽기만 하고 "보유 현황 기준 N명 · 보유 현황에서 바꾸기 →" 를 둔다. 액자 레전드는 스킬 등록만 |
| 보유 현황 표 | 열 `#` \| 레전드 \| **선호** \| 상태 \| 획득일 \| 보유(레전드 1.6, 나머지 1:1, 레전드만 왼쪽). 선호·획득일 없는 행은 항상 뒤. `상태` 머리는 미보유 먼저 → 액자 먼저 → 보유중 먼저 순환. 표 위 요약 줄은 **왼쪽 집계 · 오른쪽 정렬 기준**(재료 검색도 같은 패턴) |
| 선호 보기 | 상태 칩 줄 `전체 \| 액자 O \| 액자 X \| 선호 N`(선호 칩은 로그인 시, 단일 선택). `?tab=mine` 은 선호 칩이 켜진 채, `?prefs=1` 은 선호 모달이 열린 채 열린다. 첫 저장 뒤 "선호 레전드를 골라 볼까요?" 확인창 → `?prefs=1` |
| 콘텐츠 영역 | 보유 현황은 **레전드 기록만**. "이번 주기 일정"은 **홈 섹션(로그인 + 선호)으로만** 본다 |
| 홈 | 히어로 → 바로가기(로그인 시 편집: 서랍 메뉴 전체 중 최대 8개, 드래그 순서, localStorage) → 공지 → 오늘 히스토리 모드(선호 레전드) → 이번 주기 일정 → 내 컬렉션(비로그인은 로그인 유도 카드) → 기존 섹션. '최근 편집 바로가기'는 두지 않는다 |
| 서랍 메뉴 | '레전드 재료' 아래 하위 3개. 접이식·기본 펼침(sessionStorage). 로그인 항목은 비로그인에게도 보이고 누르면 공용 로그인 모달 |
| 로그인 처리 | 안내 모달 **공용 1벌**(`global/ui/loginRequiredModal`, 사유 3종). 메뉴·버튼 = 모달 / 주소 직접 진입 = 안내 화면 / 라우트 가드 = 역할 제한 화면만. 로그인 뒤 **쿼리·해시까지** 원래 화면으로 복귀 |
| 마이페이지 | "내 선호 레전드" 링크 → `/legend-collections?tab=mine`(`users` REQ-USR-09) |
| 측정 | 참여율 측정 이벤트는 이번에 하지 않는다 |

## 되돌린 결정 (같은 브랜치 안에서 뒤집힌 것)

| 처음 결정 | 최종 | 이유 |
|---|---|---|
| 공용 탭 4개 + `/legend-collections/goals` 선호 설정 페이지 | 탭 3개, 선호는 모달 | 선호는 필터(`선호 N` 칩)로 보면 충분하고 페이지 분리는 과하다 |
| 필터 칩 묶음 기본 접힘, 검색만 상시 노출 | 검색은 필터 영역 안, 레전드 3화면은 접기 없음 | 접힌 머리 요약이 오히려 판독 부담 |
| 가이드를 `?` 아이콘 버튼으로 축소 | 탭 아래 아코디언 | 아이콘만으로는 무엇이 펼쳐지는지 알기 어렵다 |
| 본문 부제(화면 역할 한 줄) 추가 | 삭제 | 탭 라벨과 가이드가 역할을 알린다 — 표까지 세로 거리를 줄이는 것이 우선 |
| 보유 현황 `내 목표` 탭 + 주기 일정 카드 | 상태 칩 `선호 N`, 일정은 홈 전용 | 콘텐츠 영역 분리(보유 현황 = 레전드 기록만) |
| 명칭 "목표 설정" · 마이페이지 "내 레전드 목표" | "선호 설정"(모달) · "내 선호 레전드" | 목표라는 말이 기능(선호 레전드 리마인드)보다 크다 |
| 재료 검색 상단 '내 보유 현황' 버튼(REQ-LS-07) | 두지 않음 | 공용 탭이 역할을 대신한다 |
| 관리 화면 상단 고정 "저장 안 한 변경 N · 취소 · 저장" 바 | 검색 줄 `[검색][취소][저장 (N)]` | 머리 영역을 늘리지 않는다 |

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| 한 화면에서 편집 모드만 토글 | 같은 표가 모드로 모양이 바뀌는 혼재(읽기/쓰기)가 남아 머리 영역이 계속 크다. 증상(높이)만 줄이고 뿌리를 못 고친다 |
| 로그인 필요 항목을 비로그인 메뉴에서 숨긴다 | 기능이 있는 줄 모르면 로그인할 이유도 없다 |
| 모든 로그인 필요 화면을 라우트 가드로 통일 | 이용자가 이유 모른 채 홈으로 튕긴다 |
| 바로가기 설정을 처음부터 서버 저장 | BE·DB 신규 작업(🔴 DB 승인). 사용 패턴을 본 뒤 옮겨도 늦지 않다 |
| 내 컬렉션 요약용 BE 집계 API | 기존 `GET /api/legend-collections` · `GET /api/legend-collection-skills` 응답으로 합성 가능 |

## 영향

기능 축 MINOR(홈 카드·메뉴·바로가기 설정 신규, 조회·관리 경로 분리 — 전면 UX 개편으로 보지 않는다). 플랫폼 무영향. BE 변경 없음. spec 버전: home 1.1.0 · users 1.1.0 · authentication 1.1.0 · legendCollections 1.3.0 · legendCollectionSkills 1.2.0 · legendStats 1.1.0(같은 브랜치 개정이라 유지).
