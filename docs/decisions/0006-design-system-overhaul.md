# 0006 디자인 시스템 전면 정리

## 배경

밝은톤 테마를 얹으려 했더니 막혔다. 색 토큰은 CSS 변수로 깔려 있었지만 컴포넌트가 토큰을 우회해 직접 박은 색이 테마의 실질 장벽이었고, 간격·글자 크기는 절반 가까이가 정해진 값을 안 거쳤다. 기준 문서 `DESIGN.md` 자체도 코드와 어긋난 서술(그림자 "2건" vs 실측 13건)과 내부 모순(의미 고정 규칙 vs Badges 절)을 갖고 있었다. **코드보다 기준을 먼저 고쳐야 했다.**

## 진행 순서

1. **전면 감사** — SCSS 130파일 grep 전수 실측 (토큰 정합 · 색/타이포 · 구조/그림자/죽은 코드)
2. **기준 정정** — 간격 "8배수" → "짝수px + 4배수 권장", 의미 색 → 상태·분류·등급 3축
3. **규칙 확정** — 분류 팔레트 4색, 표 글자 12px, 테마는 `prefers-color-scheme` 단일
4. **코드 교정** — 20개 커밋
5. **화면 검증** — 480px 다크/밝은톤 Playwright 실측 4회차

## 결정

| 영역 | 결정 | 왜 |
|---|---|---|
| 간격 | 짝수px 만, `1px` 은 선·테두리 전용, 4배수 권장 | 480 단일 폭에서 8배수는 과함, 홀수는 격자 이탈 |
| 글자 크기 | `9·10·11·12·13·15·17·22·28` 아홉 단계, rem 지정 | 브라우저 글자 확대 반영(접근성) |
| 표 글자 | `12.5px` → **12px** | 행 높이는 토큰 고정(38px)이라 무관, 위험은 `nowrap` + 4px 패딩의 열 폭. 작아지는 방향만 안전, 13px 은 열 폭 재확인 필요라 기각 |
| 색 3축 | 상태(성공·주의·위험) / 분류(4색, 상한 5) / 등급(게임 본편 색 그대로, 별도 팔레트) | 같은 초록·빨강이 "성공"과 "신규"로 이중 사용됨. 등급은 순서 척도라 순서 없는 분류색으로 풀면 "S 가 왜 분홍인가"가 영원히 안 풀린다 |
| 분류 빨강 | `NEW` 에만. 분류 빨강 = 불투명 채움, 상태 빨강 = 글자·테두리·아이콘 | 형태로 갈라 공존 |
| `HOT` | 폐기 | 색 배정 없음 |
| 회색 묶기 | `BETA`·`준비중`·`공식`·태그명 → `cat-neutral` 하나 | 살아있는 표시 8개가 5색 상한 초과. BETA 가 덜 튀는 건 의도 |
| 보라 제외 | 분류에 보라 없음 | 보라 비중 이미 19.3% (조명 규칙 10% 의 2배), 브랜드 "활성·선택" 뜻과 충돌 |
| 그림자 | 화면 덮는 판(모달)만. 링·발광은 `border`/`outline` | 그림자 금지 규칙과 포커스 링 충돌 해소 |
| z-index | 9단계 토큰 + 표 내부 sticky 전용 로컬 스케일 2개 | raw 숫자 금지 |
| 테마 | 기기 설정 따라가기, 토글 없음 | |

분류 팔레트: `--color-cat-new #dc2626`(공용) · `-route #7dd3fc/#075985` · `-mark #f472b6/#9d174d` · `-neutral #9ca3af/#4b5563`, 알파판 `-dim` 18%. 최악 대비 4.77~5.65, 두 테마 통과.

## 배운 것

**감사 기록과 실측이 다른 이유는 셋이고, 원인이 다르다.**

| 유형 | 사례 | 교훈 |
|---|---|---|
| 진짜 오기 | 12.5px 7→17곳, "참조 0건" `AdminCheckbox`·`SectionHeader` 가 실제론 살아있음 | 삭제 전 재grep 필수 — 믿고 지웠으면 관리자 표·홈 섹션이 깨졌다 |
| 센 대상이 다름 | "151건" = 위반이 아니라 px 총량, 17파일 vs 14파일 | 숫자 옆에 무엇을 센 건지 적는다 |
| 판정이 달라짐 | 리터럴 색 120건 "위반" → 전수 확인 결과 0건 | grep 은 존재만 안다. 위반인지는 맥락 |

**정적 검사가 못 잡은 결함 3건** — 밝은톤 표 hover(1.01:1), 로그아웃 버튼 중복, 히트맵 빗금. 셋 다 코드만 읽어선 안 보인다. 색이 "존재한다"와 "구분된다"는 다른 질문이다.

**리터럴 → 토큰 전환의 함정** — 선수 카드 링을 전역 테두리 토큰으로 바꿨다가 다크에서 검은 링이 흰 테두리로 극성이 뒤집혔다. 토큰의 다크 값이 원래 리터럴과 같은지 먼저 확인.

## 후속

- 등급 축 값 — 게임 본편 등급 색 확보 후 기입 (미정)
- `PinnedBadge.mustread`·`hot` 코드 제거 — community 동결 해제 후
- 보라 비중 19.3% — 이번 범위 밖, 별도 트랙
- 값의 원천을 `global/styles/**` 토큰 파일로 확정, `DESIGN.md`·`design.json` 은 파생 (`.claude/rules/fe/fe-design.md`)
- `text-muted`(흰 38%)·`danger`·`brand-violet` 텍스트가 카드·엘리베이트 배경 위에서 본문 기준(4.5:1) 미달(3.30~4.25:1) — 이번 라운드는 그림자·간격·글자 스케일 교정만 다뤘고 이 대비값은 손대지 않았다. 작은 글자(11px 이하)에 쓰는 자리가 많아 남는 위험
- `historyLegend.tokens.scss`의 `--color-hl-card-bg`(`#171422`)와 `players.tokens.scss`의 `--color-pe-skeleton`(`#171622`) — 1px 차이가 의도된 구분인지 오타인지 확인 안 됨
