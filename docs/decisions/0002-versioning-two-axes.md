# 0002 버전을 두 축으로 센다

## 배경

버전을 하나로만 세면 "이용자가 체감하는 변화"와 "개발자만 체감하는 변화"가 한 숫자에 섞인다. 예를 들어 FE 에 TypeScript(자바스크립트에 타입을 더한 언어)를 새로 들이는 일은 화면상 아무것도 안 바뀌지만 개발 방식은 완전히 달라진다. 반대로 신규 화면 오픈은 코드 구조는 그대로인데 이용자에게는 큰 변화다. 하나의 SemVer(`MAJOR.MINOR.PATCH`)로는 이 둘을 구분해 표기할 수 없다.

## 결정

버전을 **두 축**으로 따로 센다.

| 축 | 식별자 | 누가 체감하나 | 기록 위치 |
|---|---|---|---|
| 기능(Release) | `vMAJOR.MINOR.PATCH` | 이용자·운영자 | CHANGELOG `Added/Changed/Fixed` |
| 플랫폼(Code) | `platform-MAJOR.MINOR` | 개발자 | CHANGELOG `Platform` |

두 축은 **독립**이다. 기능 버전이 올라도 플랫폼 버전은 그대로일 수 있고 반대도 된다. 표기는 항상 `v2.1.0 (platform-2.0)` 처럼 기능 버전을 앞에, 플랫폼 버전은 괄호 안에 둔다.

**기준선**: 현재 운영 상태를 `v2.0.0 (platform-2.0)` 으로 선언한다. 판단표·커밋 표기 규칙은 `rules/common/commit-version.md` 로 옮겼다 — 이 결정 기록은 "왜 두 축인가"만 남긴다.

## 왜 (대안과 비교)

| 대안 | 문제 | 판정 |
|---|---|---|
| SemVer 하나만 쓴다 | TypeScript 도입 같은 개발자 전용 변화와 신규 화면 같은 이용자 체감 변화가 같은 숫자에 섞여, 버전만 보고는 "무엇이 바뀌었나"를 알 수 없다 | 기각 |
| 플랫폼 축을 안 만들고 커밋 메시지로만 구분한다 | 릴리스 노트·태그 자동 집계가 안 된다 | 기각 |
| 두 축을 만들되 완전히 별개 저장소·별개 태그 체계로 관리 | 저장소 하나에 배포 단위도 하나라 과한 분리 | 기각 |

## 과거 표기 → 새 표기 대응표

분기점 커밋 `5966fb55` 이전에는 커밋 본문의 `버전 영향:` 줄이 지금과 다른 4갈래 표현을 썼다. 과거 커밋은 고치지 않고 아래 표로 해석한다.

| 과거 표기 | 새 표기로 해석 |
|---|---|
| `버전 영향: 기능 무영향 / 플랫폼 무영향` | 그대로 유효 |
| `버전 영향: 없음 (동작 불변) / 플랫폼 무영향` | `기능 무영향 (동작 불변) / 플랫폼 무영향` |
| `버전 영향: 없음 (운영 로그) / 플랫폼 무영향` | `기능 무영향 (운영 로그) / 플랫폼 무영향` |
| `버전 영향: 무영향 (스키마 파일 정리, 운영 DB 변경 없음)` | `기능 무영향 / 플랫폼 무영향 (스키마 파일 정리)` |

## 영향받는 곳

- `rules/common/commit-version.md` — 판단표·커밋 `버전 영향:` 표기 규칙의 단일 원천
- `.claude/conventions/release-procedure.md` — 태그·브랜치·릴리스 절차
- 모든 커밋 본문 — `버전 영향: 기능 {값} / 플랫폼 {값}` 줄 필수

## 관측 — 아직 두 축으로 안 잡히는 사례 (❓ 미정)

2026-09-28 작업 중, 기능 축·플랫폼 축 어느 쪽으로도 신호가 안 잡히는 변경이 나왔다.

| 변경 | 기능 축 표기 | 플랫폼 축 표기 | 실제로는 |
|---|---|---|---|
| 서버 오류 코드 문자열 `AUTH_USER_BLOCKED` → `AUTH_FORBIDDEN` 변경 | PATCH | 무영향 | FE `client.js` 가 그 문자열을 그대로 갖고 있어, 서버만 먼저 배포하면 권한 부족 안내가 깨진다 |
| 없는 주소 응답 500 → 404 변경 | PATCH | 무영향 | 응답 상태 코드에 기대는 화면이 있으면 영향받는다 |

둘 다 표기상 평범한 PATCH 인데 실제로는 **서버와 화면을 같이 배포해야 하는 변경**이다. 지금 표기로는 릴리스 시점에 이걸 걸러낼 방법이 없다.

❓ 거론된 방향 둘 다 미채택: (1) 세 번째 표기 자리를 추가한다(`… / 동반 배포 필요 (client.js)`), (2) 괄호 사유에 `(동반 배포 — 파일명)` 을 쓰는 약한 규약만 둔다. `rules/common/commit-version.md` § 3 은 임시로 (2)를 쓰고 있다.
