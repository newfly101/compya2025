## 2. 색 3축 제안 근거

`semantic-color-proposal.md`·`color-typography.md` 근거.

**세 축으로 나눈 이유** — 상태(성공·주의·위험)와 분류(신규·인기·베타…)를 한 팔레트에 얹은 게 근본 원인이었다. 상태는 개수가 고정(3~4색)이고 사용자 행동을 바꾸는 신호, 분류는 계속 늘어나고 시선만 끄는 신호라 성질이 다르다. 실측 결과 빨강 한 색에 네 가지 뜻(위험·신규·인기·필독), 초록 한 색에 다섯 가지 뜻(성공·네이버·마일리지 분류·등급 표시·팁)이 걸려 있었다. 등급은 S/A/B/C/D 처럼 **순서가 있는 척도**라 순서 없는 분류색으로 풀면 "S 등급이 왜 분홍인가"가 영원히 안 풀려 분류와 분리된 별도 팔레트로 뺐다(값은 게임 본편 등급 색 체계 그대로, 프로젝트가 새로 정하지 않음).

**대비 기준** — WCAG 2.1, 본문 텍스트 4.5:1 · 큰 글자/UI 비텍스트 요소 3:1. 알파 채움(18%) 위 글자는 **합성 배경 = 0.18×전경색 + 0.82×배경색**으로 계산해 채움이 배경을 글자색 쪽으로 끌어올리는 실제 조건을 반영했다.

**미달이었던 값(정리 전)** — 배지 채움 7색 중 5색이 흰 글자 기준 4.5:1 미달(한정·보상·신규·인기·이벤트), 분류·강조로 쓰이던 13색 전부가 밝은 배경에서 미달(1.51~3.76:1), 다크 테마 실측에서는 `text-muted`(카드·엘리베이트 배경 위 2개 조합)·`brand-violet` 텍스트·`danger` 텍스트 총 4개 조합이 본문 기준 미달 또는 근접 미달이었다. 죽은 배지 변종 삭제 + 분류 4색 적용 반영 후에는 미달 잔존 0건(`community` 동결 도메인과 등급 축 값 미정 두 곳만 판정 보류).

## 3. 분류 팔레트 결정

`cat-palette-apply.md` 근거.

**결정** — `--color-cat-new`(NEW 전용) · `--color-cat-route`(마/히) · `--color-cat-mark`(중요) · `--color-cat-neutral`(BETA·준비중·공식·게시판 태그명) 4색 확정, 5색 상한에 1칸 여유. `-dim`(18% 알파) 컴패니언 토큰은 기존 `-danger-dim`/`-warning-dim`/`-success-dim` 관례를 따라 추가.

**근거** — (1) 회색 묶기: 살아있는 표시 8개가 5색 상한을 넘어 `BETA`·`준비중`·`공식`·태그명을 `cat-neutral` 하나로 묶었다. BETA가 덜 튀는 것은 의도된 결과. (2) 보라 제외: 보라 비중이 이미 19.3%로 조명 규칙 상한(10%)의 2배라 분류에 보라를 더하면 규칙이 더 깨지고, 브랜드의 "활성·선택" 뜻과도 충돌한다. (3) 분류 빨강은 `NEW`에만 허용하고 **형태로** 상태 빨강과 가른다 — 분류 빨강은 불투명 채움 + 흰 글자로만 나타나고, 상태 빨강(`--color-danger`)은 채움 없이 글자·테두리·아이콘으로만 쓰인다. (4) `community` 도메인이 동결이라 `PostRow.jsx`가 직접 호출하는 `mustread`(필독) 변종은 값·호출부를 그대로 두고 살아있는 호출부(`중요`→`mark`, 마일리지 NEW→`catNew`)만 새 variant로 옮겼다.

**적용 화면** — 서랍(Drawer) 메뉴, 홈 화면 자유게시판 태그, 공지사항 목록("중요"/"공식"), 레전드 재료 화면("마"/"히"). 재색칠 8용례 중 회색 계열 3건은 값이 같아 자동 치환, 5건은 화면 확인 필요. 검증은 `npx vite build` 통과 확인.

## 4. 표 글자 실측

`table-font-check.md` 근거.

**측정 방법** — 브라우저 실측은 Playwright 공유 브라우저(profile 점유 중)가 7회 재시도에도 접속 불가해 막혔고, 다른 세션 작업을 건드리지 않기 위해 프로세스를 강제 종료하지 않았다. 대신 코드 정적분석으로 판정했다 — 행 높이는 글자 크기와 무관하게 토큰(`--hl-row-h`/`--ls-row-h` 등 `38px`, 헤더 `32px`)으로 고정돼 있고, 실제 위험은 셀의 `white-space: nowrap` + 좌우 패딩 4px이 만드는 열 폭이다.

**결과·결정** — `12.5px → 12px` 확정. 작아지는 방향이라 열 폭이 밀리지 않고 아홉 단계 규칙도 통과한다. `13px`은 커지는 방향이라 열 폭 재확인이 필요해 기각했다. 전파 경로는 `mixins/_table.scss`의 `data-table-skin` 믹스인을 거치는 historyLegend·legendStats·players(StatsTable) 3도메인 + mileage(TargetListTab 믹스인 경유, MileageScreen 6곳은 믹스인 없이 직접 하드코딩) 총 4도메인. 화면 실측은 0건(스크린샷 없음) — 교체 작업 후 화면 확인은 여전히 권장 사항으로 남는다.
