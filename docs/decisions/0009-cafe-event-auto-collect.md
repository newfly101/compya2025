# 0009 공식 카페 이벤트 글 자동 수집 · 사이트 내 본문 게시

> 상태 `accepted` (2026-09-30) — 운영자가 아래 결정 두 가지(본문 재게시 방식 · DB 컬럼 4개)를 승인했고, 코드(PR #41)와 DB 반영이 끝났다. 규칙은 events·admin spec 의 REQ 로 옮겨졌고 이 문서는 배경·근거 기록으로 남는다.

## 배경

지금 이벤트·쿠폰 등록은 전부 손으로 한다 — 공식 카페에서 운영자 계정(GM드리미) 글을 찾아 이름·마감일·쿠폰 번호를 옮겨 적고, 배너를 내려받아 다시 올리고, 글 주소를 외부 링크로 넣는다. 거의 매일 반복되고, 카드를 누르면 카페로 넘어가 이용자가 돌아오지 않는다(이탈).

## 결정 (제안)

1. 매일 **11:01(한국 시간)** 에 서버가 GM드리미의 새 글을 1회 확인한다. 이벤트 글은 보통 10~11시에 올라오기 때문이다.
2. `[이벤트]` 글은 제목에서 이름과 마감 시각을, 본문에서 필요한 부분만 잘라 **초안**으로 저장한다. 이때 초안은 공개 화면에 보이지 않는다.
3. 운영자가 어드민 "수집함"에서 미리 보고 **승인**해야 공개된다. 자동 공개는 하지 않는다.
4. 이용자는 이벤트 카드를 누르면 **사이트 안의 상세 창**에서 본문을 본다. 원문 링크는 보조 버튼으로 남긴다.
5. 새 글 본문에 **쿠폰 표**("쿠폰 번호" 칸이 있는 표)가 있으면 새 쿠폰 번호만 `site_coupons` 에 등록한다 — § 쿠폰.

## 수집 대상 · 시각

| 항목 | 값 |
|---|---|
| 카페 | 컴투스프로야구 공식 카페 (카페 번호 `27851354`, 주소 `com2usbaseball2015`) |
| 게시판 | "진행 중 Event" (`menuId 1`) 만 본다 — 전체 최신글 50건에는 운영자 글이 거의 없다 |
| 작성자 | GM드리미 — 닉네임이 아니라 **멤버 고유키**로 거른다(GM덕아웃·GM수여니 제외). 키는 설정 파일에 둔다 |
| 목록 API | `apis.naver.com/cafe-web/cafe-boardlist-api/v1/cafes/{카페}/menus/1/articles` — 로그인 불필요. (작성자별 목록 API 는 로그인 필요라 못 씀) |
| 상세 API | `apis.naver.com/cafe-web/cafe-articleapi/v2.1/cafes/{카페}/articles/{글번호}` — 로그인 불필요, 본문 `contentHtml` 포함. (v3 는 500) |
| 실행 | `@Scheduled(cron = "0 1 11 * * *", zone = "Asia/Seoul")` — 기존 통계 집계 배치와 같은 방식. 스케줄러는 이미 켜져 있다(`AsyncConfig`) |
| 수동 실행 | 어드민 "지금 수집" 버튼 — 11시 이후 글, 급한 공지용. 배치와 같은 코드를 부른다 |

## 제목 해석 규칙

분류 먼저: `[이벤트]` 로 시작하지 않거나 제목에 `모아보기`(여러 이벤트 합본)가 있으면 뺀다. 쿠폰 글은 제목으로 거르지 않는다 — 본문 구간을 못 찾으면 "구간 못 찾음"으로 떨어진다.

`[이벤트]` 머리말을 떼고, 끝의 괄호 안 `~M/D HH:mm` 을 마감 시각으로, 괄호 앞의 "이벤트" 단어를 뺀 나머지를 이름으로 쓴다.

| 원문 제목 | 이름 | 마감 |
|---|---|---|
| `[이벤트] 포스트시즌 트로피 제작 이벤트 (~11/8 23:59)` | 포스트시즌 트로피 제작 | 11/8 23:59 |
| `[이벤트] 추석 연휴 접속 보상 이벤트 (~9/26 23:59)` | 추석 연휴 접속 보상 | 9/26 23:59 |
| `[이벤트] 에픽 선수 승급 이벤트(~2027/2/28)` | 에픽 선수 승급 | 2027/2/28 23:59 |

- 연도가 없으면 글 작성일의 연도를 쓰고, 그 결과가 작성일보다 과거면 다음 해로 본다(12월 글의 `~1/5`).
- 시작 시각은 본문 "이벤트 기간" 줄의 시작일, 없으면 글 작성일.
- 제목에 마감이 없으면 본문 "이벤트 기간" 줄에서 찾고, 그래도 없으면 초안에 "마감 미확인" 표시 — 운영자가 채운다.
- 괄호가 둘인 제목(`(~9/28 23:59)(21:55 보상 지급 완료)`)은 **첫 번째** 날짜 괄호를 쓴다.

## 본문 추출 규칙

카페 본문은 문단·이미지·표가 "블록" 단위로 나열된 구조다. 글자 위치가 아니라 **블록 단위로** 잘라야 태그가 중간에 끊겨 깨지지 않는다.

- **시작**: "이벤트 기간" 이 들어간 첫 블록 (포함)
- **끝**: "감사합니다" 가 들어간 마지막 블록 **직전**까지
- 둘 중 하나라도 못 찾으면 본문 없이 초안만 만들고 "구간 못 찾음" 표시 — 운영자가 기존처럼 외부 링크로 등록

잘라낸 블록은 네이버 전용 스타일을 버리고 우리 태그로 다시 쓴다(허용 목록 방식 — 목록에 없는 태그는 전부 버림).

| 원문 블록 | 바꾼 결과 |
|---|---|
| 문단 | `<p>`, 굵게 `<strong>` 만. 색·글꼴 스타일 제거 |
| 이미지 | `<img src="(S3 주소)" loading="lazy" alt="">` |
| 표 | `<table>` 구조만 |
| 링크 | `<a target="_blank" rel="nofollow noopener">` |
| 🏆 같은 작은 아이콘·스티커 | 🟨 제거 |
| 동영상·투표 등 그 외 | "원문에서 확인" 한 줄로 대체 |

- 화면 모양은 우리 CSS 한 곳(`.event-body`)이 정한다. 정제는 두 번: 서버 저장 전(jsoup) + 화면 표시 전(DOMPurify) — 둘 다 이미 의존성에 있다.

## 이미지

- 본문 이미지와 배너(첫 이미지 → 카드 썸네일 `image_url`)를 서버가 내려받아 기존 S3 에 `events/{글번호}/` 로 올린다.
- 실측: 같은 이미지를 우리 도메인 Referer 로 요청하면 **403**, Referer 없이는 200 — 직접 표시는 불가, 서버가 받아 재업로드하는 것은 가능. 재업로드 필수 확정.

## 저장 (DB 변경 — 2026-09-30 승인·운영 반영 완료)

`site_events` 에 컬럼 4개 추가. DB 가 운영과 같은 인스턴스라 적용 즉시 운영에 반영됐다(`sql/v.2.0.0/applied/site_events_source_columns.sql`).

| 컬럼 | 형식 | 용도 |
|---|---|---|
| `source_article_id` | BIGINT NULL UNIQUE | 원문 글번호 — 중복 수집 방지 |
| `content_html` | MEDIUMTEXT NULL | 정제된 본문 |
| `content_hash` | CHAR(64) NULL | 원문 구간 해시 — 변경 감지 |
| `synced_at` | DATETIME NULL | 마지막 수집 시각 |

초안/승인 구분은 새 상태 컬럼 없이 기존 `is_visible` + `source_article_id` 로 한다 — 🟨 "수집됐고 아직 안 보임" = 초안.

## 원문 변경 · 실패 처리

- 같은 11:01 배치에서 **진행 중인** 수집 이벤트의 원문을 다시 읽어 해시를 비교한다. 달라졌으면 자동으로 덮지 않고 수집함에 "원문 변경됨" 표시 → 운영자가 재승인.
- 요청 실패 시 1회 재시도 후 수집함에 "수집 실패" 기록, 다음 날 재시도. 카페 내부 API 는 공개 약속이 아니라 바뀔 수 있다 — 수동 등록 경로는 항상 남긴다.

## 쿠폰

**새로 올라온 글만** 본다(운영자 결정 2026-09-30). "쿠폰 모아보기" 글(`1949641`)은 다시 읽지 않는다 — 이벤트와 같은 목록에서 새 글번호가 나오면, 본문에 "쿠폰 번호" 칸이 있는 표가 있는지 확인해 쿠폰으로 등록한다. 한 글이 이벤트이면서 쿠폰 표를 가질 수도 있다(둘 다 등록).

| 카페 표 칸 | `site_coupons` | 처리 |
|---|---|---|
| 쿠폰 번호 | `coupon_code` | 이미 있으면 건너뜀 — 컬럼에 UNIQUE 가 이미 있어 **DB 변경 불필요**. 영문 대문자·숫자가 아니면 경고 |
| 쿠폰명 | `title` | 칸 안 여러 줄은 한 줄로 이어 붙임 |
| 쿠폰 보상 | `detail` | 줄바꿈 유지 |
| 사용 가능 기한 | `expire_at` | `~ 9/30(수)` → 23:59:59. 연도 없으면 올해, 반년 넘게 과거면 다음 해 |
| 바로가기 링크 | (저장 안 함) | 실측 형식 `http://withhive.me/399/{쿠폰 번호}` — FE 가 번호로 만든다 |

- 기한이 이미 지난 쿠폰은 등록하지 않는다. 헤더 칸 수와 행 칸 수가 다르면(병합 셀) 경고
- 확정(2026-09-30) — 쿠폰은 번호·보상만 옮기는 사실 정보라 **승인 없이 바로 공개**(`is_visible` 기본 TRUE), 경고가 붙은 행만 숨김 초안으로
- **쿠폰 글 추적** — 쿠폰 글은 번호를 나눠 공개하고 글을 고쳐 추가한다(예: `2011166` 국제대회 쿠폰, "2차 쿠폰 추가"). 추가가 빈 칸 채우기인지 행 추가인지 모르므로, **쿠폰 표가 한 번이라도 나온 글은 제목 마감(없으면 표의 가장 늦은 기한)까지 매일 다시 읽어** 새 번호만 등록한다. 번호 형식이 아닌 칸("추후 공개" 등)은 등록하지 않고 다음 날 다시 본다. 🟨 추적 대상은 새 테이블 없이 같은 글의 이벤트 초안(`site_events.source_article_id`)으로 찾는다
- 실측(`2011166`): 개별 쿠폰 글도 같은 표 형식 — 2행 추출 성공. 이미 둘 다 공개된 상태라 미발행 칸의 실제 문구는 확인 못 함 ❓

## 이용자 화면

- 이벤트 카드 클릭 → 사이트 안 상세 창(모달): 배너 · 기간 · 남은 날 · 본문 · 하단 "출처: 컴투스프로야구 공식 카페" + [원문 보기] 버튼.
- 본문이 없는 이벤트(수동 등록·구간 못 찾음)는 지금처럼 외부 링크로 연다.
- 이 결정은 events spec 의 "상세 화면을 만들지 않는다"(§ 5, REQ-EVT-06)를 **바꾼다**. 상세 창은 별도 주소 없는 모달이라 크롤러 404 우려(원래 이유)는 생기지 않는다.
