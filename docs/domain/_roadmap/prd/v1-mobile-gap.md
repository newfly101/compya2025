## 2. 되살릴 것 — 구체 목록

퀴즈 관련 항목과, 서버가 이미 완성돼 있어 화면만 붙이면 되는 값싼 항목만 남는다. (커뮤니티는 신규 기능으로 분류되어 빠졌다 — § 1)

### 서버가 이미 완성이고 화면만 없는 것 (가장 싸게 되찾을 수 있음)

| 화면 | 무슨 기능이었나 | 서버 준비 상태 | 화면 작업 규모 |
|---|---|---|---|
| 관리자 첫 화면 주소 연결 | 관리자 메뉴 5개로 들어가는 입구. 화면은 완성돼 있는데 주소 목록에 없어 못 들어감 | 정적 화면이라 서버 불필요 | 작음 (주소 한 줄) |
| 회원 상세 · 역할/상태 변경 | v1 회원 상세 화면에서 하던 일. 지금은 "다음에 구현" 안내만 뜨는 빈 틀 | 완성 (`PATCH /admin/users/{id}/role`, `.../status`) | 작음 |
| 이벤트 이미지 올리기 | 관리자 이벤트 등록 시 이미지 파일 업로드. 지금은 이미지 주소를 손으로 입력 | 완성 (`POST /upload/events`), 프런트 호출 함수도 이미 있음 | 작음 |
| 퀴즈 관리 화면 | 퀴즈 목록·등록·수정·삭제. v1 관리자 화면 10개 파일이 통째로 삭제됨 | 완성 (`/admin/quiz` 전부). 프런트 데이터 연결 코드(store)도 삭제되지 않고 남아 있음 | 보통 (화면 + 주소) |

### 그 밖에 되살릴 것

| 화면 | 무슨 기능이었나 | 서버 준비 상태 | 화면 작업 규모 |
|---|---|---|---|
| 공지 삭제 | v1 관리자 공지 화면에 삭제가 있었다고 문서에 적혀 있음 | **없음** — 서버에도 프런트에도 삭제 기능이 없음. 근거 약함 (§ 5 참고) | 작음 (단 서버부터 필요) |

- 참고: 서버에는 있으나 **v1 에도 화면이 없던** 유휴 기능 — 코치 스킬 조회, 스킬 점수 설정(`/skills/coach`, `/skills/score-config`). 되살리는 게 아니라 새로 만드는 일이다.

## 3. 재기획할 것 · 보류

| 도메인 | 상태 | 이유 |
|---|---|---|
| playerCard | 보류 | 폐기 승인된 결정이었고, **로그인한 사용자 전용 컨텐츠로 새로 만들기 위해** 재작업이 필요해 지금은 손대지 않는다 |
| simulate | 보류 | 같은 이유 — 로그인한 사용자 전용 컨텐츠로 새로 만들기 위해 지금은 손대지 않는다 |

- kbo 는 "제거할 것" 으로 성격이 바뀌어 이 표에서 빠졌다 — § 1, § 7 참고

## 4. 근거가 없어 판단 못 하는 것

무엇을 모르는지만 적는다. 아래는 채우지 않았다.

- **home** — v1 첫 화면이 어떤 섹션으로 구성됐고 사용자가 무엇을 눌렀는지. 기획문서의 기능 항목이 통째로 "미작성" 이고, 남은 건 현재 코드 조사 결과뿐이다. 지금 모바일 홈이 v1 홈과 같은지 다른지 비교할 기준선이 없다
- **historyMode** — v1 에 있었다는 옛 화면 `LegendCalendar` 가 무엇을 하던 화면인지. 문서에 이름만 있고 "파일 없음 추정" 이라고만 적혀 있으며, 지금 레전드 모드 화면과 같은 기능이었는지 알 수 없다
- **kbo 의 "승부예측"** — v1 첫 화면 메뉴에 "KBO 승부예측" 이라는 이름이 있었던 흔적은 있으나, 예측·투표 기능이 실제로 만들어졌었는지 확인되지 않는다. 코드로 확인되는 것은 오늘 경기 목록·상세 조회뿐이다
- **`/kbo`, `/quiz` 의 실제 사용 여부** — 사용자에게 노출된 적이 있는지, 사용량이 있었는지는 코드 이력만으로 알 수 없다
- **dictionary 와 wiki 의 관계** — 두 화면이 같은 스킬 데이터를 쓴다는 것까지는 확인되나, wiki 가 dictionary 를 대체할 의도로 만들어졌다는 기록은 없다. 위 표의 "이미 대체됨" 은 데이터가 겹친다는 사실에 근거한 판정이며 **결정 기록이 아니다** (근거 약함)
- **community 가짜 데이터의 모양** — 화면에 박아둔 예시 데이터가 실제 서버 응답과 같은 모양인지 확인된 적이 없다. 서버 연결 작업 규모가 커질 수 있다

## 5. 조사 결과끼리 어긋난 곳

| 쟁점 | 한쪽 주장 | 다른쪽 주장 | 어느 쪽이 맞나 |
|---|---|---|---|
| community 서버 연동 | 기존 요약 문서 — "기능 전체 서버 코드는 다 돼 있음" | 현재 코드 조사 — 사용자 화면은 서버를 한 번도 부르지 않고 100% 가짜 데이터. 관리자 쪽도 프런트가 부르는 주소와 서버 주소가 다름 | **현재 코드 조사 쪽**. 파일 단위로 직접 확인했고, 어느 파일이 무엇을 불러오는지까지 짚었다. 기존 문서는 "서버에 기능이 존재한다" 와 "화면이 그것을 쓴다" 를 구분하지 않았다 |
| quiz 카드가 비는 원인 | 기존 요약 문서 — "주소 오타 때문" | 현재 코드 조사 — 프런트와 서버 주소가 맞아떨어짐. 오타 지점을 다시 찾지 못함 | **판정 보류**. 어느 쪽도 원인을 증명하지 못했다. 서버 내부 동작까지 확인하지 않았으므로, 고치기 전에 화면에서 실제 응답을 한 번 찍어보는 확인이 먼저다 |
| 공지 삭제 기능 | v1 기획문서 — 관리자 공지 화면에 삭제가 있었음 | 현재 코드 조사 — 서버에도 프런트에도 삭제가 없음 | **둘 다 사실일 수 있다**. v1 관리자 화면은 통째로 삭제됐으므로 그때 서버 삭제 기능까지 함께 정리됐을 가능성이 있다. 되살릴지 여부는 § 6 결정 기록 참고 |
| community PC 코드 분량 | 옛 기록 — "PC 전용 코드 40개 이상" | 실측 — 2개 (40 은 커뮤니티 도메인 전체 71개 파일을 착각한 수치) | **실측 쪽**. 기존 요약 문서가 이미 정정해 두었다 |
| quiz 의 성격 | 폐기 6종 목록에 없어 생존 도메인으로 분류됨 | 이력 조사 — 관리자 화면 10개 파일이 별도 커밋으로 삭제됨 | **양쪽 모두 맞다**. quiz 는 통째 폐기가 아니라 "관리자 화면만 삭제 + 홈 카드로 축소 생존" 이다. 위 표에서 되살릴 것으로 분류한 이유 |
| dictionary 와 wiki 의 관계 | 두 화면이 같은 스킬 데이터를 쓴다는 것까지는 확인되나, wiki 가 dictionary 를 대체할 의도로 만들어졌다는 기록은 없다. § 1 의 "이미 대체됨" 은 데이터가 겹친다는 사실에 근거한 판정이며 **결정 기록이 아니다** (근거 약함) | | **판단 보류 상태로 남음**. 다만 wiki 가 제거 대상으로 결정되어 **이 쟁점 자체는 무의미해짐** |

- 이번 조사에서 v1 기획문서의 주장 6건(도감 35개, 시뮬레이터 27개, 마이페이지 3개, 선수카드, KBO 16개, 커뮤니티 동결)을 이력으로 검증했고 **파일 수까지 전부 일치**했다. 문서의 사실 서술 자체는 믿을 만하다 — 문제는 서술이 없는 부분(§ 4)이다.
