## 2. 단계별 — 무엇이 달라졌나

**v0.1.0 (정적 팬사이트)** — React+Vite, mock data 로 홈/공지/쿠폰/이벤트/스킬변경 시뮬레이터/스킬 백과사전/히스토리모드(v1, 코드상 당시 명칭 `historyMode`)/팁게시판을 순차 오픈. SCSS+CSS Modules, PC 중심 설계 위에 모바일은 사후 패치. GTM·SEO·네이버 서치어드바이저 도입.

**v0.2.0 (서버·로그인 투입)** — Spring Boot 최초 투입, MariaDB+MyBatis 연동, 선수/스킬 조회 API. 네이버 OAuth+JWT 로그인, 마이페이지 신설, 실명·전화번호 미수집으로 DB 설계.

**v1.0.0 (domain 구조 + admin)** — FE `domains/`·BE `domain/` 구조로 동시 전환, 쿠폰·이벤트 DB화(admin CRUD 포함). 커뮤니티(게시판) 신규, 코치 스킬 백과사전 확장. 응답 포맷을 공용 GENERIC record 로 통일. Redis 캐시를 도입한 당일 VM 부하로 즉시 롤백.

**v2.0.0 (FE 아키텍처·토큰 재정립)** — "v2.0.0 구조화"로 전역 CSS 시맨틱 토큰·4px 그리드·브레이크포인트를 처음 확립, Header/Footer 재작성. 쿠폰·이벤트를 admin/public 분리 구조로 재작성, S3 이미지 업로드 연동. 선수카드(legend) 도메인 착수, 퀴즈 CRUD 전 계층 신규.

**v2.1.0 (DB V2 + BE 재작성)** — DB를 `site_`/`fun_` 접두로 분리하는 V2 스키마 도입. kbo 크롤러 추가(이후 폐기). notice/event/auth/community/quiz 를 v2.x 라벨로 BE 전면 재작성, Swagger 도입.

**v3.0.0 (1차 리뉴얼 — 모바일 전용)** — PC/모바일 이중 scss 병행 → PC scss 전면 주석 처리 → 도메인별(쿠폰→이벤트→공지→히스토리→커뮤니티) PC 파일 삭제 순으로 모바일 전용 재구현. 인증 모바일 재구현, GA 이벤트 연동.

**v3.1.0 (구 도메인 정리 + AI 워크플로우 + BE 보안)** — kbo·백과사전(dictionary) FE·profile·스킬변경 시뮬레이터·선수카드(FE)·admin v1을 전면 폐기(재기획 우선순위 밀림). `.claude/` agent·워크플로우 체계, `CLAUDE.md` 최초 작성. 인증을 STATELESS로 강화, refresh token(rotation) 도입, 시크릿을 `.env`로 분리. mobile-first 를 공식 컨벤션으로 선언(pc-first 폐기). wiki·admin v2·users(admin) 착수.

**v4.0.0 (2차 리뉴얼 — 정리·재건)** — wiki/skill(백과사전)/coach/kbo/크롤러 완전 삭제(135파일). DB를 v1→v2 이관(users/coupons/events/quiz). 선수 백과사전·확률공시 신설. 레전드 재료·레전드 스탯·히스토리모드(v2, 정식 명칭 `historyLegend`)를 새 스키마로 재건, v1 히스토리모드 폐기. 애드센스 최초 신청(정책 페이지·SEO 준비 착수).

**v4.1.0 (admin 재디자인 + 유저 개편 + 수익화, 리팩터 기준선)** — admin을 단일 셸+상단 탭으로 전면 재디자인. 유저 구조를 네이버 원본정보/자체 계정으로 분리. 선수 스킬 백과사전·마일리지(beta) 신설. 사용자 행동 통계 수집. 가이드 콘텐츠 12편, 광고 슬롯 전 도메인 배치, 카카오페이 후원 섹션 신설. FE/BE 배포를 GitHub Actions로 전환.

## 5. 인프라·DB 이력

**DB 스키마 단계**

| 단계 | 시점 | 내용 |

| V1 | 2026-01~ | 단일 누적 파일(`CREATE_TABLE.sql`) |

폴더명 "V2"에는 이름과 달리 V1 테이블 정의도 섞여 있다. kbo·wiki·skill 15개 테이블 DROP 스크립트는 작성됐지만 미실행 상태로 남아 있다.

> ⚠️ **운영 절차**: DDL을 작성하면 곧바로 운영 DB에 적용한다. **테스트 DB와 운영 DB가 같은 인스턴스**이며 별도 테스트 환경이 없다. DB 작업 시 항상 이 점을 염두에 둔다.

## 6. 현재(리팩터 기준선) 상태 스냅샷

`retro/v4.1.0`(`566cf3bd`, 2026-09-13) 시점 — 다음 모바일 퍼스트 재수립 작업이 시작하는 지점이다.

**공개 라우트(로그인 불요)**: 홈, 공지(목록/상세), 쿠폰, 이벤트, 확률공시(목록/섹션), 선수 백과사전, 레전드 스탯, 히스토리레전드(`/history-mode/legend`), 정책 4종(개인정보/이용약관/연락처/소개), 커뮤니티(동결·noindex), 마일리지(beta), 선수 스킬, 가이드(목록/상세).

**로그인 필요 라우트**: 마이페이지, admin(단일 셸+탭), admin 공지 작성.

**BE 컨트롤러**: 34개, `domain/{admin,analytics,community,coupon,event,notice,oauth,quiz,statistics}` + `fun/{historyMode,legendCard,legendStat,mileage,playerCard,playerSkill,team}` 패키지에 분산.

**DB 스키마 폴더**: `sql/V2`(지난 버전, V1 정의 포함) / `sql/V2_insert` / `sql/V3`(현재 운영 기준, refresh_tokens·히스토리모드·레전드·선수카드·선수스킬·통계 등) / `sql/V3_insert`. `sql/migration`·`updateData`·`cleanup` 폴더는 2026-09-13 재정리로 더 이상 존재하지 않는다.

**디자인 토큰**: 전역 토큰(`global/styles/variables/{_colors,_font,_spacing,_radius,_zindex,_breakpoints,_semantic}.scss`), admin 전용 토큰(`global/ui/admin/admin.tokens.scss`), 도메인 로컬 토큰(커뮤니티·히스토리레전드·레전드스탯·마일리지·선수스킬·선수백과 등 6개 도메인) — 이 시기부터 도메인이 자기 토큰을 갖는 방식이 자리잡았다.

## 8. 남은 확인

git 이력만으로는 **운영 DB에 실제로 반영된 날짜와 순서**를 검증할 수 없다. DDL 작성과 동시에 운영에 적용하는 절차 자체는 확인됐지만(§5), 커밋 시점과 실제 배포·반영 시점이 항상 일치한다는 보장은 git 로그만으로 증명되지 않는다.
