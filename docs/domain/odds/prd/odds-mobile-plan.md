# 확률 공시 모바일 화면 — 작업 계획

작성일 2026-08-21 · 도메인 `odds` · 상태 **작업 중**

---

## 1. 무엇을 하는가

게임 확률 공시 문서(게임법상 의무 공시)를 모바일 웹에서 볼 수 있게 만든다.

원본은 PC 시절에 만들어진 HTML 한 덩어리다. 흰 배경에 검정 글씨, 회색 테두리 표가
쉼 없이 이어진다. 이걸 지금 사이트의 어두운 배경·보라 계열 화면에 맞게 다시 배치한다.

**이번 단계 목표는 "일단 빠르게 올린다"** — 서버 없이 화면과 데이터만으로 동작시킨다.

---

## 2. 전체 진행 순서 중 지금 위치

```
  화면 설계 ──▶ 임시 데이터 ──▶ 화면 구현 ──▶ 요구사항·DB 확정 ──▶ 서버 설계 ──▶ DB ──▶ 실제 기능
   (완료)        (작업 중)       (작업 중)          (다음)
```

지금은 앞의 세 칸. 서버·DB 는 이번 범위가 **아니다.**

## 4. 확정한 결정 세 가지

### 4-1. 섹션 하나 = 페이지 하나

61개 항목을 한 화면에 전부 쏟으면 450행짜리 스크롤이 된다.
대신 **목록 화면**에서 원하는 항목을 고르면 그 항목만 있는 화면으로 넘어간다.

```
┌─────────────────────────┐        ┌─────────────────────────┐
│  ← 확률 공시            │        │  ← 선수팩 등급 확률      │
├─────────────────────────┤        ├─────────────────────────┤
│  선수팩                 │        │   ┌────┬────┬─────┐     │
│  선수팩 등급 확률     › │  탭 ▶  │   │등급│색상│확률 │     │
│  골든글러브, MVP 선수 › │        │   ├────┼────┼─────┤     │
│  올스타 선수          › │        │   │플래│황금│5~10%│     │
│                         │        │   └────┴────┴─────┘     │
│  장비·아이템            │        │  · 고급 선수팩도 동일   │
│  플래티넘 장비 확률   › │        ├─────────────────────────┤
│       ⋮ 총 61개         │        │  ‹ 이전     다음 ›      │
└─────────────────────────┘        └─────────────────────────┘
```

목록에서는 61개를 그냥 나열하지 않고 여덟 묶음으로 나눈다 —
**선수팩 13 / 장비·럭키백 10 / 고유능력 6 / 강화·등급 10 / 스카우트·드래프트 8 /
카드 조합 2 / 이벤트 9 / 스킨·마스코트 3**

상세 화면 아래에는 이전·다음 버튼을 둔다. 항목을 훑어볼 때 매번 목록으로 돌아가지 않도록.

### 4-2. 표는 열 개수에 따라 다르게 보여준다

| 표 종류 | 개수 | 처리 |
|---|---|---|
| 4열 이하 | 39개 | 화면 폭에 꽉 맞춰 고정. 좌우로 밀 필요 없음 |
| 5열 이상 | 6개 | 좌우로 미는 방식. 단 **맨 왼쪽 열은 고정**해서 지금 무슨 항목을 보는지 안 놓치게 |

대부분의 표가 한눈에 들어오고, 어쩔 수 없는 것만 예외 처리하는 방식이다.

### 4-3. HTML 을 데이터로 변환해서 쓴다

원본 HTML 을 그대로 화면에 밀어 넣지 않는다. 대신 **변환 프로그램**을 만들어
구조화된 데이터 파일로 바꾼 뒤, 화면은 그 데이터를 읽어 그린다.

```
  test-docs/*.html
        │
        │  scripts/parse-odds.mjs   ← 변환 프로그램
        ▼
  web/src/data/odds/*.json          ← 구조화된 데이터
        │
        ▼
  화면 컴포넌트가 읽어서 그림
```

**이유** — 새 문서가 와도 변환 프로그램만 다시 돌리면 된다.
그리고 나중에 서버를 붙일 때 이 데이터 구조가 그대로 서버 응답 형태가 된다.
즉 지금 만드는 임시 데이터가 **다음 단계 설계의 초안 역할**을 겸한다.

## 5. 데이터 생김새

```
문서
├─ 문서 번호 · 제목
├─ 머리말 (확률 페이지 공통 적용 사항)
├─ 분류 목록 (선수팩 / 장비·아이템 / …)
└─ 섹션 24개
   ├─ 번호 (s01 ~ s24)
   ├─ 제목
   ├─ 소속 분류
   └─ 내용 블록들  ← 원본 등장 순서 그대로
      ├─ 표   (머리행 · 데이터행 · 열 개수 · 폭 초과 여부)
      │     └─ 칸마다 — 글자 · 세로병합 수 · 가로병합 수 · 링크 주소
      ├─ 설명 (표 아래 붙는 조건 문구)
      ├─ 문단
      └─ 링크 (다른 확률표 페이지로 나가는 바로가기)
```

**순서를 지키는 게 중요하다.** 표 사이에 낀 설명 문구는 "이 확률이 어떤 팩에
적용되는지"를 알려주는 법적 고지라서, 표만 뽑고 문구를 버리면 안 된다.

## 6. 만들어지는 파일

| 위치 | 내용 |
|---|---|
| `scripts/parse-odds.mjs` | HTML → 데이터 변환 프로그램 |
| `web/src/data/odds/cpb2015_1_3.json` | 변환된 데이터 |
| `web/src/data/odds/index.js` | 데이터 진입점 |
| `web/src/domains/odds/mobile/` | 목록 화면 · 상세 화면 |
| `web/src/domains/odds/mobile/components/` | 표 · 설명문 · 이전다음 버튼 |
| `web/src/app/router/` | 주소 연결 (`/odds`, `/odds/{항목번호}`) |

화면 색은 새로 만들지 않고 사이트에 이미 있는 색 정의를 그대로 쓴다.
원본의 흰 배경·회색 테두리는 가져오지 않는다.

## 7. 이번에 하지 않는 것

- 서버 API — 데이터는 파일로만 존재한다
- 데이터베이스 설계 · 테이블 생성
- 관리자에서 확률 문서를 올리고 고치는 기능
- 문서 여러 개 사이 전환 (지금은 1개 기준. 데이터 구조는 확장 가능하게 잡아둠)
- 사이트 어디에서 이 화면으로 들어갈지 — **진입 경로 미정** (아래 참조)

## 8. 확인이 필요한 것

| 항목 | 내용 |
|---|---|
| **진입 경로** | 이 화면으로 어디서 들어가는가. 홈 하단 링크 / 공지 목록 안 / 별도 메뉴 중 미정. 지금은 주소를 직접 쳐서 접근 |
| **문서 추가 계획** | 연도별·게임별로 몇 개나 더 올라오는가. 개수에 따라 문서 선택 화면이 필요할 수 있음 |
| **갱신 주기** | 확률이 바뀔 때 문서를 새로 받는지. 잦다면 관리자 업로드 기능 우선순위가 올라감 |

## 10. 원본 문서를 다루며 발견한 함정

다음 문서를 받을 때 같은 함정을 다시 밟지 않도록 남긴다.
아래 다섯 가지는 전부 **실제로 화면이 깨진 뒤에** 발견한 것들이다.

| 함정 | 무슨 일이 벌어졌나 | 대응 |
|---|---|---|
| **제목 태그가 일관되지 않음** | 같은 등급의 제목이 두 가지 방식으로 쓰여 있다. 문서 뒷부분 770줄에는 한 방식이 아예 안 쓰여서, 항목 17개가 앞 항목 하나에 통째로 묻혔다 | 두 방식을 **같은 등급으로** 취급 |
| **제목에 글자 크기 꾸밈이 덧씌워진 경우** | 꾸밈이 한 겹 더 있는 제목 3개를 놓쳐서 본문에 묻혔다 | 꾸밈 태그는 전부 벗겨내고 글자만 보고 판단 |
| **머리행을 머리행 태그로 안 만듦** | 표 45개 중 32개가 머리행을 굵은 글씨로만 표현했다. 그대로 두면 머리행이 데이터 행처럼 보인다 | 첫 행이 전부 굵은 글씨면 머리행으로 인정 |
| **세로 병합** | 앞쪽 칸을 세로로 합친 표에서, 합쳐진 행은 칸이 적다. 이걸 왼쪽부터 채우면 **모든 값이 한 칸씩 밀린다.** 표 12개가 이렇게 깨졌다 | 병합 정보를 그대로 보존해 화면에서도 병합으로 그린다 |
| **바깥 페이지로 나가는 링크** | 이 문서에 없는 확률표 44개가 링크로만 걸려 있었다. 처음엔 글자만 남기고 주소를 버렸다 | 주소를 살려 새 창으로 연다 |

마지막 항목이 특히 중요하다. **링크 44개가 가리키는 확률표는 이 문서에 없다.**
운영 도메인의 별도 페이지들이며, 앞으로 받을 문서가 아마 그것들이다.

### 검사 방법

표가 제대로 변환됐는지 확인하려면 **병합을 펼쳤을 때 모든 행의 칸 수가 같은지**를 본다.
하나라도 어긋나면 그 표는 화면에서 밀려 보인다. 현재 45개 표 전부 통과 상태다.
