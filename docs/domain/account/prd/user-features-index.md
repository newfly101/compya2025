# 로그인 사용자가 할 수 있는 일 — 목차

컴프야펀은 지금 **조회 전용 사이트**다. 로그인을 받고 있지만 로그인해서 얻는 것이
사실상 없다. 이 문서는 「컨텐츠를 어떻게 쓰는가」가 아니라, 어느 정보 사이트에나 있는
**계정·플랫폼 기본기**의 목차만 뽑는다. 각 항목의 상세 설계는 다음 단계다.

---

## 1. 지금 할 수 있는 일 (실측)

로그인 사용자 전용 기능은 **딱 셋**이다.

| 할 수 있는 일 | 어디 | 비고 |
|---|---|---|
| 내 정보 보기 | 마이페이지 | 닉네임 / 이메일 / 마지막 로그인 |
| 닉네임 바꾸기 | 마이페이지 | 20자 제한, 중복 허용 |
| 탈퇴하기 | 마이페이지 | 1개월 보관 후 파기, 그 안에 재로그인하면 복구 |

- 로그인 수단은 **네이버 하나뿐**이다. 비밀번호라는 개념 자체가 없다
- 커뮤니티는 읽기 전용 동결, 퀴즈는 어드민 화면만 있다 — 사용자가 남길 흔적이 0
- 메뉴에 「로그인 필요」 표시가 붙은 화면은 선수 백과사전·확률 공시 둘뿐이고,
  드로어에서 안내 모달만 띄울 뿐 **주소를 직접 치면 그냥 들어가진다**
- 저장할 곳이 없으니 행동 통계(`docs/domain/analytics/prd/user-event-tracking.md`)에
  잡히는 것도 「보고 나갔다」뿐이다

---

## 2. 목차

### 묶음 하나 — 내 정보

| 항목 | 한 줄 설명 | 왜 필요한가 |
|---|---|---|
| 마이페이지 재구성 | 지금의 납작한 정보 나열을 「내 것들」이 모이는 허브로 | 저장·알림·설정이 생기면 들어갈 자리가 없다 |
| 프로필 다듬기 | 프로필 이미지 선택, 한 줄 소개 | 내 계정이라는 느낌의 최소 조건 |
| 내 활동 요약 | 가입일, 저장 개수, 최근 본 개수 | 로그인의 대가를 눈으로 보여주는 자리 |
| 표시 이름 규칙 | 닉네임 중복·금지어·변경 주기 | 지금은 중복 허용이라 남에게 보이는 순간 문제가 된다 |

### 묶음 둘 — 저장함 (담아두기 · 최근 본 것)

**그릇만 만든다.** 무엇을 담을지는 컨텐츠 기획의 몫이다.

| 항목 | 한 줄 설명 | 왜 필요한가 |
|---|---|---|
| 무엇이든 담는 저장함 | 종류(선수·쿠폰·이벤트·글…)와 식별자만 받는 단일 저장 구조 | 컨텐츠마다 따로 만들면 매번 다시 만들게 된다 |
| 저장 버튼 | 어느 화면에든 같은 모양으로 붙는 담기/빼기 | 일관된 조작이 학습 비용을 없앤다 |
| 내 저장함 화면 | 담은 것 모아보기, 종류별 탭, 빼기 | 담기만 하고 볼 곳이 없으면 의미가 없다 |
| 최근 본 것 | 자동으로 쌓이는 열람 기록, 직접 지우기 | 담는 습관이 없는 사용자도 로그인 이득을 본다 |
| 메모·정리 | 저장물에 메모 달기, 묶음(폴더) | 많이 담는 사용자에게만 필요 — 나중 |

### 묶음 셋 — 알림

| 항목 | 한 줄 설명 | 왜 필요한가 |
|---|---|---|
| 사이트 안 알림함 | 종 아이콘 + 읽음/안읽음 목록 | 재방문을 만드는 가장 싼 장치 |
| 알림 받을 거리 정하기 | 새 쿠폰 / 새 이벤트 / 공지 / 내 저장물 변화 | 전부 보내면 전부 끈다 |
| 알림 켜고 끄기 | 종류별 on/off | 끌 수 없는 알림은 이탈을 부른다 |
| 브라우저 푸시 | 사이트를 안 보고 있어도 알림 | 권한 요청 실패·모바일 제약이 커서 나중 |

### 묶음 넷 — 내 취향 설정

| 항목 | 한 줄 설명 | 왜 필요한가 |
|---|---|---|
| 내 구단 고르기 | 응원 구단 1개 저장 | 개인화의 출발점이자 가장 값싼 로그인 보상 |
| 시작 화면 정하기 | 로그인 후 첫 화면 지정 | 자주 쓰는 화면이 사람마다 다르다 |
| 보던 방식 기억하기 | 목록 정렬·필터·탭을 기기 간 유지 | 화면이 좁아 매번 다시 맞추는 게 특히 괴롭다 |
| 화면 모드 | 어둡게 보기 등 표시 옵션 | 있으면 좋지만 토대는 아니다 |

### 묶음 다섯 — 계정 안전 (로그인 수단 · 접속 기록)

| 항목 | 한 줄 설명 | 왜 필요한가 |
|---|---|---|
| 로그인 수단 추가 | 네이버 외 두 번째 수단 연결 | **네이버 계정을 잃으면 되찾을 길이 전혀 없다** |
| 연결된 수단 관리 | 연결 목록 보기, 해제(마지막 하나는 불가) | 수단이 둘 이상이 되는 순간 필요 |
| 접속 기록 보기 | 최근 로그인 일시·기기·지역 | 내 계정이 남에게 쓰였는지 알 유일한 수단 |
| 다른 기기 로그아웃 | 지금 로그인된 곳 끊기 | PC방·공용기기 대비 |

### 묶음 여섯 — 내 데이터 · 탈퇴 · 문의

| 항목 | 한 줄 설명 | 왜 필요한가 |
|---|---|---|
| 탈퇴 안내 보강 | 저장물·알림·기록이 어떻게 되는지 명시 | 저장 기능이 생기면 지금 안내 문구로는 부족하다 |
| 저장물만 지우기 | 탈퇴 없이 내 기록 비우기 | 개인정보 처리정지 요구에 대응하는 가벼운 수단 |
| 내 데이터 내려받기 | 내 저장·기록을 파일로 | 법적 의무는 아니나 신뢰 장치 — 나중 |
| 사이트 안 문의 | 문의 남기고 답변 확인 | 지금은 오픈채팅·이메일뿐이라 대화가 사이트 밖에 있다 |

## 3. 먼저 할 것 / 나중에 할 것

**판단 기준 셋** — ① 만드는 비용 ② 사용자가 바로 느끼는 가치 ③ 다른 기능의 토대가 되는가.
특히 ③을 우선한다. 저장함이 없으면 알림도 개인화도 보낼 거리가 없어 순서가 뒤집히면
전부 다시 만들게 된다.

### 먼저 — 토대

| 무엇 | 근거 |
|---|---|
| 무엇이든 담는 저장함 + 저장 버튼 + 저장함 화면 | 알림·개인화·활동 요약이 전부 여기에 얹힌다. 이것 없이는 로그인의 대가가 계속 0 |
| 비로그인 담기 + 로그인 시 옮겨주기 | 결정 2번에 따라 **저장함 첫 공개에 함께 들어간다.** 나중에 붙이면 담기 버튼 동작이 두 번 바뀐다 |
| 마이페이지 허브 재구성 | 새 기능이 들어갈 자리를 먼저 판다. 지금 구조엔 붙일 곳이 없다 |
| 로그인 경계 규칙 정하기 | 「조회는 누구나, 저장은 로그인」을 문서로 못 박아야 이후 화면마다 흔들리지 않는다. 결정 3번에 따라 **차단은 하지 않는다** |

### 다음 — 값싸고 바로 느껴지는 것

| 무엇 | 근거 |
|---|---|
| 최근 본 것 | 저장함 구조를 그대로 재사용. 담는 습관이 없는 사용자도 이득을 본다 |
| 내 구단 고르기 | 값 하나 저장인데 개인화의 시작점이 된다 |
| 사이트 안 알림함 | 저장함이 생긴 뒤라야 보낼 거리가 생긴다 |
| 표시 이름 규칙 | 닉네임이 남에게 보이기 시작하기 전에 정리해야 한다 |

### 그 다음 — 안전과 신뢰

| 무엇 | 근거 |
|---|---|
| 로그인 수단 추가 + 연결 관리 | 위험은 지금도 크지만 사용자 수가 적을 때 겪는 사고는 적다. 다만 미루면 미룰수록 이관 대상이 늘어난다 |
| 접속 기록 / 다른 기기 로그아웃 | 저장물이 쌓인 뒤에야 「지킬 것」이 생긴다 |
| 탈퇴 안내 보강 + 저장물만 지우기 | 저장 기능 공개와 **같은 시점**에 나가야 방침과 어긋나지 않는다 |
| 사이트 안 문의 | 답변 운영 부담이 생기므로 사용자가 늘어난 뒤 |

### 나중 — 있으면 좋은 것

| 무엇 | 근거 |
|---|---|
| 브라우저 푸시 | 권한 거절·모바일 제약으로 효율이 낮고, 알림함이 먼저 검증돼야 한다 |
| 메모·묶음 정리 | 많이 담는 소수에게만 필요 |
| 내 데이터 내려받기 | 요구가 실제로 생긴 뒤 |
| 화면 모드 | 토대가 아니고 손은 많이 간다 |

## 4. 결정이 필요한 것 — **결정 완료 (2026-09-11)**

| # | 갈림길 | 선택지 | 권고 | **결정** |
|---|---|---|---|---|
| 1 | 저장함을 어떻게 담을까 | ① 종류 무관 단일 저장함 + 종류별 탭 ② 컨텐츠마다 별도 목록 | **①** — 컨텐츠가 늘 때마다 다시 만들지 않아도 된다 | **① 단일 저장함 + 종류별 탭** |
| 2 | 비로그인 사용자도 담을 수 있게 할까 | ① 로그인해야만 담기 ② 브라우저에 임시로 담고 로그인 시 옮겨주기 | **②** — 담아본 사람이 로그인한다. 담기 버튼이 곧 가입 유도가 된다 | **② 담기게 하고 로그인 시 계정으로 옮김** |
| 3 | 「로그인 필요」 화면을 실제로 막을까 | ① 지금처럼 사실상 열어둠 ② 진짜로 막음 ③ 표시를 떼고 전부 공개 | **③ 또는 ①** — 막으면 검색 노출이 끊긴다 | **① 지금대로 둔다** (표시는 유지, 실제로 막지 않음) |
| 4 | 두 번째 로그인 수단을 붙일까 | ① 구글 추가 ② 카카오 추가 ③ 당분간 네이버만 | **①** — 계정 복구 경로가 없는 현재 상태가 가장 큰 위험 | **③ 당분간 네이버만** (보류) |
| 5 | 탈퇴하면 저장물은 | ① 즉시 삭제 ② 계정과 같이 1개월 보관 후 삭제 | **②** — 재로그인 복구 정책과 어긋나지 않는다 | **미결** — 저장함 설계 때 다시 묻는다 |

**미뤄둔 위험 (지금 하자는 게 아니라, 나중에 다시 보기 위한 기록)**

- **3번** — 표시와 실제가 다르다. 「로그인 필요」라고 써 붙였지만 주소를 직접 치면 들어가진다.
- **4번** — 계정 복구 경로가 없다. 네이버 계정을 잃으면 되찾을 길이 전혀 없다.

저장함 한 건의 상세 범위는 → [saved-items-scope.md](./saved-items-scope.md)

## 5. 안 하는 것 (이번 목차에서 뺀 것)

| 뺀 것 | 왜 |
|---|---|
| 컨텐츠를 어떻게 쓰는가 (조합 추천, 비교, 덱 짜기 등) | 사용자 머릿속에 이미 있다. 이 문서는 그릇만 만든다 |
| 비밀번호 변경·찾기 | 네이버 로그인뿐이라 비밀번호가 존재하지 않는다 |
| 출석·포인트·업적·랭킹 | 별도 기획이 이미 있다 → `docs/domain/gamification/prd/` |
| 커뮤니티 글쓰기·댓글 | 읽기 전용 동결 상태. 해제는 별도 결정 사안 |
| DB 스키마 / 화면 디자인 | 목차를 고른 뒤의 다음 단계 |
| 이메일 발송 기반 기능 | 발송 수단·비용 검토가 선행돼야 한다 |
