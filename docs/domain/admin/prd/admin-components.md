# 관리자 공용 부품 명세

> `admin-ui-design.md`가 정한 부품 목록(새로 13개 + 재사용 3종)을 상세화한다. 값은 전부 `DESIGN.md` 토큰 이름으로 지칭하며, 여기 없는 값은 쓰지 않는다.

## 목록 부품

### `AdminList` — 이 설계의 중심

**역할** — 화면이 넘긴 "항목 정의"를 받아 카드 목록으로 그린다. 화면 파일은 목록 마크업(`<ul>`, `<li>`, 카드 모양)을 직접 쓰지 않는다.

**항목 정의의 모양** — 화면은 두 가지만 넘긴다. (1) **데이터**: 화면이 이미 가진 목록 배열 그대로. (2) **필드 정의**: "어떤 값을 어떤 자리에 어떻게 보여줄지" 정하는 배열. 필드 정의 하나가 카드 안 한 줄에 대응한다.

| 필드 정의 항목 | 종류 | 필수 | 기본값 | 설명 |
|---|---|---|---|---|
| `key` | 문자 | 필수 | — | 데이터에서 꺼낼 값 이름 (예: `title`, `couponCode`) |
| `role` | 문자 | 필수 | `body` | 카드 안 자리 — `title`(제목줄, 카드당 1개) / `meta`(부제 설명) / `badge`(상태 배지) / `toggle`(노출 스위치) / `body`(일반 값) |
| `label` | 문자 | 아니오 | 없음 | 값 앞 이름표. `title`/`meta`는 보통 생략 |
| `format` | 문자 | 아니오 | `text` | `text`/`date`(날짜만 표시)/`percent`/`badgeVariant`(배지 3종 연결) |
| `hideOnNarrow` | 참거짓 | 아니오 | `false` | 좁은 화면에서 감출지 — 항목이 8~10개로 많은 화면(게시글 관리 등)에서 핵심 3~4개만 남기고 나머지를 감출 때 씀 |
| `order` | 숫자 | 아니오 | 배열 순서 | 카드 안 등장 순서 |

**나중을 막지 않는 이유** — 지금은 필드 정의를 세로로 쌓아 카드로 그리는 동작만 한다. 나중에 PC 폭에서 표(table)로 바꿀 때도 같은 필드 정의(키·자리·이름표·표시형식·순서)가 열 정의로 그대로 재사용돼 화면 쪽 코드는 손대지 않는다.

**받는 값**

| 이름 | 종류 | 필수 | 기본값 | 설명 |
|---|---|---|---|---|
| `items` | 배열 | 필수 | — | 목록 데이터 |
| `fields` | 배열(위 정의) | 필수 | — | 무엇을 어떻게 보여줄지 |
| `getRowKey` | 함수 | 필수 | — | 항목별 고유 키 |
| `renderActions` | 함수 | 아니오 | 없음 | 카드 하단 `RowActions`를 만드는 함수 |
| `onToggle` | 함수 | `toggle` 필드 있으면 필수 | 없음 | 노출 스위치 눌렀을 때 |

**상태·크기** — 기본(카드 슬레이트) / 종료·비활성(흐린 배경 + 보조 글자색, 지우지 않고 남김) / 불러오는 중·오류·빈 목록은 `ListStateView` 몫. 모서리 10px, 안쪽 여백 상하 20px 좌우 16px, 요소 간격 8px, 카드 사이 12px, 그림자 없음.

**변형·금지** — 변형 없음(필드 정의 조합으로만 화면마다 달라짐). 화면 파일 안 카드 마크업 직접 작성 금지, 그림자 금지, 표(table) 마크업은 지금 만들지 않는다(PC 단계로 미룸).

### `ListStateView`

**역할** — 목록이 비었거나 아직 안 왔거나 실패했을 때 카드 대신 보여줄 화면 하나로 통일.

| 이름 | 종류 | 필수 | 기본값 | 설명 |
|---|---|---|---|---|
| `status` | 문자 | 필수 | — | `loading`/`error`/`empty` |
| `message` | 문자 | 아니오 | 상태별 기본 문구 | 직접 지정 |
| `onRetry` | 함수 | `error`일 때만 | 없음 | "다시 시도" 동작 |

**상태·크기** — `loading`(안내 문구만, 스피너 없음) / `error`(얼럿 레드 문구 + `Button` 보조 변형의 다시 시도) / `empty`(보조 글자색 문구만). 카드와 같은 여백(상하 20px 좌우 16px), 가운데 정렬.

**쓰지 말아야 할 것** — 세 상태를 화면마다 다시 분기해서 만들지 않는다. 새 색 안 씀(오류=얼럿 레드 고정).

## 입력 창과 확인 창

### `AdminFormPanel`

**역할** — 등록·수정 입력 항목을 담는 "여는 방식"만 담당. 안의 내용은 이 부품이 모른다.

**여는 방식과 내용의 분리** — "아래에서 올라오는 창"이라는 여는 동작과 창 테두리(제목줄·닫기·여백)만 이 부품이 맡는다. 안에 들어갈 입력 항목은 화면이 `children`(`Field` 조합)으로 넘긴다. 나중에 "오른쪽에서 밀려나오는 패널"로 여는 방식만 바꿔도 안의 입력 구성은 그대로 재사용된다.

| 이름 | 종류 | 필수 | 기본값 | 설명 |
|---|---|---|---|---|
| `open` | 참거짓 | 필수 | — | 열림 여부 |
| `title` | 문자 | 필수 | — | 창 제목 |
| `onClose` | 함수 | 필수 | — | 배경 클릭·닫기 |
| `onSubmit` | 함수 | 필수 | — | 폼 제출 |
| `submitLabel` | 문자 | 아니오 | "저장" | 제출 버튼 글자 |
| `children` | 요소 | 필수 | — | `Field` 들 |

**상태·크기** — 열림(뒤 검은 막 55% + 아래에서 올라옴, 0.25s) / 닫힘(렌더 안 함) / 제출 중(제출 버튼 비활성 + "저장 중" 문구, 새 로딩 표시 안 만듦). 위쪽 모서리만 12px, 안쪽 여백 상하 20px 좌우 16px, 폭은 화면 틀 폭 그대로.

**쓰지 말아야 할 것** — 입력 항목 마크업을 이 부품에 미리 못박지 않는다. 그림자는 겹쳐 뜨는 판 값만 씀(새로 안 만듦).

### `ConfirmDialog`

**역할** — 삭제·비활성화·일괄 처리 전 확인. `window.confirm` 완전 대체.

| 이름 | 종류 | 필수 | 기본값 | 설명 |
|---|---|---|---|---|
| `open` | 참거짓 | 필수 | — | 열림 여부 |
| `title` | 문자 | 필수 | — | 확인 문구 |
| `description` | 문자 | 아니오 | 없음 | 보조 설명 |
| `confirmLabel` | 문자 | 아니오 | "확인" | 확인 버튼 글자 |
| `tone` | 문자 | 아니오 | `default` | `default`/`danger`(삭제류) |
| `onConfirm` / `onCancel` | 함수 | 필수 | — | 확인 / 취소 |

**상태·크기** — 열림(가운데, 뒤 막 55%) / 닫힘. 버튼 두 개(취소=보조, 확인=주요 또는 위험)는 `Button` 재사용. 모서리 8px, 화면 틀 기준 좌우 32px 여백의 상대 폭(고정 폭 아님), 안쪽 여백 상하 20px 좌우 16px.

**쓰지 말아야 할 것** — 화면마다 확인창 새로 만들지 않는다. 브라우저 기본 `confirm`/`alert` 금지.

## 버튼 · 입력 항목

### `Button`

**변형** — 주요(primary, 액션 인디고 — 저장·등록처럼 되돌리기 어려운 동작) / 보조(secondary, 리프티드 슬레이트 — 취소·다시 시도) / 위험(danger, 얼럿 레드 — 삭제).

| 이름 | 종류 | 필수 | 기본값 | 설명 |
|---|---|---|---|---|
| `variant` | 문자 | 아니오 | `secondary` | `primary`/`secondary`/`danger` |
| `size` | 문자 | 아니오 | `md` | `md`(44px)/`sm`(36px, 카드 안 좁은 자리) |
| `fullWidth` | 참거짓 | 아니오 | `false` | 폭 전체 |
| `disabled` / `loading` | 참거짓 | 아니오 | `false` | 비활성 / 제출 중(글자만 전환, 새 스피너 없음) |
| `onClick` | 함수 | 필수(제출용은 `type="submit"`) | — | 클릭 동작 |

**상태·크기** — 기본 / 눌림(opacity 0.85) / 초점(테두리 강한 단계) / 비활성(흐림, 클릭 막음) / 로딩(비활성 + 문구 전환). 기본 44px, 작은 자리 36px, 모서리 9999px(알약), 세로 쌓일 때 폭 전체.

**쓰지 말아야 할 것** — 그림자 금지. 네 번째 변형 새로 안 만듦. 13px 이하 글자에 색 강조 금지(굵기로).

### `Field`

**역할** — 라벨 + 입력 한 조합. 글자·숫자·날짜·선택·체크 다섯 종류를 한 부품이 처리.

| 이름 | 종류 | 필수 | 기본값 | 설명 |
|---|---|---|---|---|
| `label` | 문자 | 필수 | — | 라벨 |
| `type` | 문자 | 아니오 | `text` | `text`/`number`/`date`/`select`/`checkbox` |
| `name` / `value` / `onChange` | — | 필수 | — | 폼 값 이름 / 현재 값 / 변경 핸들러 |
| `options` | 배열 | `select`일 때 필수 | 없음 | `{value, label}` 목록 |
| `required` | 참거짓 | 아니오 | `false` | 필수 표시 |
| `error` | 문자 | 아니오 | 없음 | 오류 문구 |
| `placeholder` | 문자 | 아니오 | 없음 | 안내 문구 |

**상태·크기** — 기본(오버레이 슬레이트) / 초점(테두리 강한 단계, 빛번짐 없음) / 오류(테두리·문구 얼럿 레드) / 비활성(흐림). 입력 높이 36px, 모서리 8px. 체크박스는 라벨 전체를 눌러도 되게 최소 터치 자리 44px 확보.

**변형·금지** — 다섯 타입이 곧 변형(여섯 번째 타입이 필요해지면 이 표를 먼저 갱신). 한 줄에 입력 2개 배치 금지(모바일 1개, PC 단계에서만 2개). 화면 파일이 `<input>` 직접 안 씀.

## 검색 · 필터

**`AdminFilterBar`** — 검색창과 필터 칩 묶음을 배치하는 그릇. `search`(`SearchField`, 필수) / `filters`(`FilterChipGroup`, 아니오 — 유저 관리처럼 없는 화면 있음)를 받는다. 좌우 여백 16px, 검색창·칩 줄 간격 8px. 검색·필터 매칭 로직은 갖지 않는다 — 화면이 이미 걸러진 `items`를 `AdminList`에 넘기는 구조를 유지한다.

**`SearchField`** — 글자 입력을 받아 값 변화만 알린다(걸러내기는 화면 몫). `value`/`onChange`(필수), `placeholder`(아니오, 기본 "검색"). 높이 36px, 모서리 8px, 좌우 여백 12px, 폭 전체. 상태: 기본/초점/비활성. 자동완성 같은 새 기능은 지금 안 만든다.

**`FilterChipGroup`** — 여러 값 중 하나를 고르는 알약 버튼 묶음. `options`(`{value,label}` 배열, 필수), `value`/`onChange`(필수). 칩 높이 36px, 좌우 여백 12px, 모서리 4px, 좁을 때 가로 스크롤(줄바꿈 안 함). 상태: 기본(리프티드 슬레이트+보조 글자) / 선택됨(시그널 딥+흰 글자, 굵게) / 초점(터미널 바이올렛 외곽선). 선택 안 된 칩에 색 있는 테두리 넣지 않는다.

## 화면 틀과 머리말

**`AdminPageFrame`** — 화면 하나의 바깥 테두리·여백·최대 폭. `children`만 받는다. 지금은 공개 화면과 같은 폭 상한 값(이름 붙은 값, 현재 480px)을 그대로 참조하고 숫자를 새로 박지 않는다. 좌우 여백은 기존 규칙(16px, 320px 미만 12px) 그대로. 폭 숫자를 이 부품 밖에서 다시 적지 않는다. PC 최대 폭(1280px)은 지금 채우지 않고 자리만 비워둔다.

**`AdminPageHeader`** — 제목·한 줄 설명·총 건수·등록 버튼. 글로벌 상단바(뒤로가기+화면 이름)와 역할이 겹치지 않는다 — 상단바는 그대로 두고 이 부품은 그 아래만 맡는다.

| 이름 | 종류 | 필수 | 기본값 | 설명 |
|---|---|---|---|---|
| `title` | 문자 | 필수 | — | 화면 제목 |
| `description` | 문자 | 아니오 | 없음 | 한 줄 설명 |
| `count` | 숫자 | 아니오 | 없음 | "총 N건" 표시 |
| `actionLabel` / `onAction` | — | 아니오 | 없음 | 등록 버튼 글자/동작 — 없으면 버튼 자체를 안 그림(유저 관리처럼 등록 없는 화면 대응) |

**크기·금지** — 제목 Page Title(22px/700), 설명·건수 Caption(11px). 등록 버튼은 `Button` 주요 변형, 폭 전체 44px. `<h1>` 중복 생성 금지, 뒤로가기 버튼 넣지 않는다(상단바 몫).

**`AdminMenuCard`** — 관리자 홈·위키 관리 홈에서 하위 화면 진입 카드. `title`/`to`(필수), `description`/`count`(아니오). 카드 규격 그대로(모서리 10px, 여백 20px/16px), 모바일 세로 1열, 상태 기본/눌림. 두 홈 화면이 각자 카드를 새로 만들지 않고 이 하나로 통일한다.

## 되살릴 것 (노출 스위치)

`VisibleToggle`(`web/src/global/ui/visibleToggle/VisibleToggle.jsx`)은 컴포넌트 로직은 있으나 `VisibleToggle.module.scss`가 **전체 주석 처리돼 스타일이 없다.** 기존 주석 내용도 초록(`#22c55e`)·회색(`#6b7280`) 원시 색값이라 DESIGN.md와 안 맞는다 — 그대로 살리지 말고 다시 써야 한다. `visible`/`onChange`(필수), `disabled`(아니오)를 받는다.

| 상태 | 배경 | 손잡이 |
|---|---|---|
| 켜짐 | 아래 "정해야 할 것" 참고 | 오른쪽 |
| 꺼짐 | 리프티드 슬레이트 | 왼쪽 |
| 비활성 | 꺼짐 + 흐림 처리 | 그대로 |

트랙 폭 44px·높이 22~24px(터치 자리는 부모가 44px 보장), 전환 애니메이션 0.2s. 원시 색값을 그대로 되살리지 않는다.

## 공통 금지 사항

- 화면 파일 안에서 `<input>`/`<button>`/오버레이를 직접 꾸미지 않는다 — 전부 위 부품을 불러 쓴다.
- 그림자는 `AdminFormPanel`·`ConfirmDialog`처럼 화면에서 완전히 분리돼 뜨는 판에만. 카드·버튼·입력창·칩은 절대 금지.
- 원시 색값을 어디에도 직접 적지 않는다 — 항상 이름 붙은 색을 거친다.
- 글자 크기는 아홉 단계(9~28px) 밖의 값을 새로 만들지 않는다.
- 간격은 8pt 격자(4~48px) 밖의 값을 쓰지 않는다.
- 폭 숫자를 화면 파일에 직접 적지 않는다 — `AdminPageFrame`이 참조하는 이름 붙은 값 하나로만 통제한다.
- 누를 수 있는 요소는 최소 44px(칩·검색창 36px은 예외로 이미 확정).
- 보라 계열을 한 화면에서 10% 넘게 칠하지 않는다 — 버튼 여러 개를 동시에 주요 변형으로 만들지 않는다.
