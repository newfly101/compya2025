# (나중에 할 것) PC 화면 폭까지 지원하려면 — 지금 갖춰진 것과 없는 것

> ⚠️ **보류 안내**
> 이 문서의 내용은 **지금 작업 대상이 아니다.**
> 사용자 결정으로 PC 화면 폭 지원은 **나중으로 미뤄졌다.**
> 지금은 PC 브라우저로 접속해도 모바일과 똑같이 화면 가운데 좁은 폭(스마트폰 폭)으로 보이게 그대로 유지한다.
> 아래 실측 내용은 **나중에 PC 폭 지원을 하기로 결정할 때 그대로 꺼내 쓰는 자료**다.

> 기반 조사 문서. 설계안이 아니라 지금 코드에 있는 것 / 없는 것만 정리한다.
> 근거는 전부 `web/src/global/styles/`, `web/src/app/wrapper/mobile/`, `web/src/domains/community/` 코드 실측.

## 화면 폭 대응 장치

`web/src/global/styles/mixins/_media.scss` 에 화면이 넓어질 때 스타일을 바꿔주는 도구 6개가 정의돼 있다: 428px 이상, 768px 이상, 1024px 이상일 때 각각 적용, 그리고 427px 이하 전용 · 320px 이하 전용 · 고화질 화면 전용까지.

기준값은 `web/src/global/styles/variables/_breakpoints.scss` 에 320 / 375 / 428 / 768 / 1024px 다섯 단계로 이미 정의돼 있다.

**문제는 실사용이다.** 전체 scss 파일을 검색한 결과:
- 768px 이상 도구(`from-tablet`) — 실제로 쓰는 곳이 **딱 하나**, 서랍메뉴(Drawer) 컴포넌트뿐이다. 그런데 이마저도 "화면을 넓게 그린다"는 뜻이 아니라, 서랍메뉴가 480px 틀 밖으로 안 삐져나가게 위치만 바꿔주는 용도다.
- 320px 이하 전용 도구(`small-mobile`) — 글자 크기를 한 단계 줄이는 용도로 3곳에서 쓰임 (historyMode 화면, 홈 히어로 영역, 공지 상세 화면). 이것도 레이아웃을 바꾸는 게 아니라 글자만 작아지는 정도.
- 1024px 이상 도구(`from-desktop`), 427px 이하 전용 도구(`only-mobile`), 고화질 전용 도구(`retina`) — **쓰는 곳이 한 곳도 없다.**

정리하면: **화면 폭에 따라 다르게 그리는 도구는 만들어져 있는데, 그 도구를 써서 실제로 레이아웃 구조 자체를 바꾸는 화면은 사실상 없다.** 있는 건 글자 크기 미세조정과 서랍메뉴 위치 보정 정도다.

## 지금 PC에서 열면 어떻게 보이나

`web/src/global/styles/base/_base.scss` 에서 페이지 전체(`body`)에 최대 폭 480px + 가운데 정렬을 걸어놨다. 화면 뼈대를 감싸는 틀(`page-layout`, `web/src/global/styles/mixins/_layout.scss`)에도 같은 480px 제한이 한 번 더 걸려 있다 — 주석에 "이중 안전망"이라고 명시돼 있다.

즉 **지금 PC 브라우저로 사이트를 열면, 화면 한가운데 스마트폰 폭(480px) 그대로의 좁은 기둥 하나만 보이고 양옆은 배경색(짙은 보라 계열 `#0f0a14`)만 채워진다.** 가로 스크롤은 막아놨다(`overflow-x: hidden`).

서랍메뉴만 768px 이상에서 여닫는 방식이 살짝 바뀌지만(고정 위치 → 절대 위치, 애니메이션 처리 방식 변경), 이것도 480px 기둥 안에서 벌어지는 일이라 화면이 넓어 보이는 것과는 무관하다.

관리자 화면(`AdminDashboardScreen`) 등 개별 화면 몇 곳에도 480px 제한을 따로 한 번 더 박아둔 곳이 있다(위키 관리자 화면 다수 포함) — 전역 제한과 중복이다.

## 그대로 쓸 수 있는 재료

**색상** — 원색 모음(`_colors.scss`)과 의미별 이름 모음(`semantic/_color.scss`) 두 단계로 나뉘어 있고, 컴포넌트는 의미별 이름만 쓰도록 규칙이 잡혀 있다.
- 배경: 최하단 `#0f0a14` → 서브 `#140f1f` → 오버레이 `#18141f` → 카드 `#1f1a29` → 뜨는 요소 `#332947` (5단계)
- 브랜드 보라: 연한 `#ede0ff` ~ 진한 `#3c1e50` (4단계)
- 글자: 진하게 92% 흰색, 보통 60%, 흐리게 38%, 코드용 회색
- 상태색: 성공(초록 `#03c75a`), 위험(빨강 `#e84141`), 주의(노랑 `#e8d541`) — 각각 옅은 배경용 버전도 있음

**간격 · 글자 크기** — 8의 배수 간격 체계(4px~48px, 9단계), 글자 크기 9px~28px(9단계), 굵기 4단계, 줄간격 3단계가 전부 정의돼 있다.

**모서리 · 레이어 순서** — 모서리 둥글기 7단계(0~9999px, 알약버튼/아바타 포함), 겹침 순서 9단계(바텀시트·토스트 자리도 미리 잡혀 있음 — 다만 실제 부품은 없음).

**화면 뼈대(레이아웃 틀)** — 상단바 + 서랍메뉴 + 스크롤되는 본문, 이 세 조각을 하나로 묶은 틀이 이미 있다(`web/src/app/wrapper/mobile/MobileLayout.jsx`). 상단바는 형태가 3가지다: 기본(로고+메뉴버튼+로그인), 뒤로가기형(제목+뒤로가기, 관리자 화면이 이걸 그대로 가져다 씀), 메뉴버튼형(제목+메뉴버튼). **관리자 화면도 이 뼈대를 그대로 쓴다 — 관리자 전용 뼈대는 따로 없다.** 앱 전체가 이 틀 하나로만 화면을 감싸므로(`web/src/app/wrapper/AppWrapper.jsx`), PC 폭 대응이 필요하면 이 하나의 틀을 손봐야 한다.

## 없어서 새로 만들어야 하는 것

> ⚠️ 아래 중 일부는 PC 화면 폭과 무관하게 **지금 모바일 재설계에도 필요**하다. "지금 필요 / 나중에 필요"로 나눠 표시한다.

| 필요 시점 | 부품 | 현황 |
|---|---|---|
| **지금 (모바일 재설계)** | 공용 버튼 부품 | 없음. 전부 화면마다 각자 `<button>` 을 새로 꾸며 씀 |
| **지금 (모바일 재설계)** | 공용 입력창 부품 | 없음. 전부 화면마다 각자 `<input>` 을 새로 꾸며 씀 |
| **지금 (모바일 재설계)** | 범용 모달 틀(창 자체를 감싸는 공통 틀) | 없음. 관리자 쪽 모달들(게시판/게시글/태그 등록·수정 창)도 전부 화면마다 따로 만듦 |
| **지금 (모바일 재설계)** | 아래에서 올라오는 창(바텀시트) 부품 | 없음. 자리(레이어 순서)만 미리 잡아둔 상태 |
| 나중 (PC 폭 지원 시) | PC 폭에서 쓸 화면 뼈대 | 없음. 상단바/서랍메뉴/본문 뼈대가 모바일 전용 1종뿐이고, 관리자 화면도 예외 없이 이걸 그대로 씀 |
| 나중 (PC 폭 지원 시) | 표(가로세로 칸으로 나열하는 화면)를 꾸미는 스타일 | 표를 그리는 코드 자체는 커뮤니티 관리자 화면 4곳(게시판/댓글/게시글/태그 관리)에 있지만, 그 표를 꾸며주는 스타일 파일 내용이 전부 주석으로 꺼져 있어 사실상 브라우저 기본 모양 그대로 나온다. 별도로 "PC용 표 / 모바일용 목록"을 나눠 놓은 파일들(`community` 게시글 목록 쪽)도 있으나, 이 파일들을 불러 쓰는 화면이 프로젝트 어디에도 없다 — 만들다 만 채로 방치된 코드다. |

## 정해야 할 것

> 아래 질문은 모두 PC 폭 지원이 나중으로 미뤄짐에 따라 **지금 당장 결정할 필요가 없는, 나중 사안**이다.

- 관리자 화면의 폭을 480px 에서 얼마까지 넓힐지 (예: 태블릿 폭까지만 / PC 폭까지 / 제한 없음) — 아직 코드에 근거가 없어 **미확인**
- PC 폭 대응을 관리자 화면에만 적용할지, 이후 일반 사용자 화면까지 넓힐지
- 표(가로세로 칸 나열)를 실제 `<table>` 태그로 만들지, 지금 있는 카드형 목록을 폭만 넓혀 쓸지
- 새로 만들 버튼 · 입력창 · 모달 틀을 지금처럼 화면마다 따로 꾸미는 방식으로 둘지, 하나로 통일할지
- 지금의 320px 축소 대응 방식과 새로 넣을 PC 폭 대응 방식을 같은 도구 체계 안에서 같이 관리할지
