# 관리자 화면 명세

> 화면별로 "무엇이 들어가고 무엇을 할 수 있는지"를 확정한다. 배치·부품 이름은 `admin-ui-design.md`를 따른다. 입력 항목·필터는 실제 코드(`web/src/domains/*/mobile/admin/*.jsx`, 위키는 `web/src/domains/wiki/admin/mobile/*.jsx`)를 읽어 확인한 값이다. 커뮤니티 관리는 범위 밖 — 설계안에서 맨 마지막 순서로 밀려 있고 라우터에도 연결돼 있지 않다.

## 공통 규칙

모든 관리자 화면은 같은 순서로 쌓는다: **글로벌 상단바 → 머리말(제목·설명·건수·등록버튼) → 검색·필터 → 목록 → (겹쳐 뜨는) 입력창/확인창.** 예외 없음.

- **누를 수 있는 요소는 최소 44px 높이.** 운영자가 폰에서 한 손으로 조작한다.
- **자주 하는 일은 목록에서 바로.** 등록·수정처럼 입력이 필요한 일만 입력창을 연다.
- **삭제는 항상 확인창을 거친다** (`window.confirm` 금지). 문구는 지우는 대상의 이름을 담는다 — "삭제할까요?"가 아니라 "'여름 할인 쿠폰'을 삭제할까요?"
- **빈 목록·불러오는 중·실패는 다음 행동을 알려주는 문구로 쓴다.** 검색·필터 때문에 0건인지, 원래 없는 것인지 구분한다. 표준 3문구: 불러오는 중 — "{대상}을(를) 불러오는 중입니다..." / 실패 — "{대상} 목록을 불러오지 못했습니다. [다시 시도]" / 검색·필터 0건 — "조건에 맞는 {대상}이(가) 없습니다. 검색어나 필터를 확인해 보세요." / 전체 0건 — "등록된 {대상}이(가) 없습니다. 위 [+ 등록]으로 새로 추가하세요." 아래 화면별로는 이 표준과 다른 점만 적는다.
- **목록 카드 한 장에 다 담기지 않으면 우선순위로 자른다.** 첫 줄(제목 역할)은 13px·600(Body Bold), 보조 정보는 한 줄에 이어 붙인다(가운데 점 `·`로 구분).
- 노출 on/off는 목록 카드의 배지를 눌러 바로 전환한다(`VisibleToggle`). 지금은 공지만 이렇게 동작하고 나머지는 폼 안 체크박스로만 바뀐다 — 전 화면 동일하게 맞춘다.

## 쿠폰 관리 (기준 화면)

> **2026-08-20 정정** — 이 화면은 **사이트가 발행하는 쿠폰이 아니다.** 다른 사이트에서 발행한 쿠폰을 옮겨 적는 구조다(사용자 확인).
> 따라서 할인타입·할인값·최소주문금액은 **애초에 존재하지 않는 개념**이다. 이전 판(`discountType`/`discountValue` 를 "데이터는 이미 있다"고 적었던 서술)은 **사실이 아니었다** — DB·엔티티·DTO 어디에도 없다.

**목록** — 1순위(항상, 첫 줄): 제목 + 노출 배지. 2순위(항상, 한 줄에 이어 붙임): `쿠폰코드 · 만료일`. 만료 7일 이내는 만료일을 주의색(코션 앰버)으로.

**찾기** — 검색: 제목+쿠폰코드 동시(부분일치). 필터: 노출여부 전체/노출/숨김, 기본값 전체. 정렬: 코드에 로직 없음(서버 순서 그대로) — **판단 필요**, 만료 임박 순 권고.

**할 수 있는 일** — 등록/수정은 입력창(중앙 모달). 삭제는 카드 버튼 → 확인창, **완전 삭제**(복구 불가). 노출 전환은 지금 배지가 표시만 하고 안 눌린다(코드에 `onClick` 없음) — 재설계 시 목록에서 바로 전환.

**입력 항목**

실제 모델 기준(`site_coupons` / `CouponEntity` / `CouponRequest` 대조 확인, 2026-08-20).

| 이름 | 종류 | 필수 | 기본값 | 검증 규칙 |
|---|---|---|---|---|
| 쿠폰코드(couponCode) | 글자 | O | - | DB 유니크. 수정 화면에서도 변경 가능(잠기지 않음) |
| 쿠폰 제목(title) | 글자 | O | - | 최대 255자 |
| 쿠폰 설명(detail) | **글자(여러 줄)** | X | - | 최대 500자. **줄바꿈 보존** — 아래 참고 |
| 만료일(expireAt) | 날짜 | O | - | `yyyy-MM-dd HH:mm` |
| 노출여부(visible) | 스위치 | - | 켜짐 | - |

**여러 줄 입력 규칙 (2026-08-20 결정)** — 쿠폰 설명은 한 줄 입력칸이 아니라 **여러 줄 입력칸**이다. 운영자가 Enter 로 넣은 줄바꿈이 **저장·조회·표시 전 구간에서 그대로 유지**돼야 한다.

| 구간 | 필요한 처리 |
|---|---|
| 입력 | `<input>` 이 아니라 `<textarea>` |
| 저장 | 줄바꿈 문자를 지우거나 공백으로 바꾸지 않는다 (trim 은 앞뒤만) |
| 표시 | `white-space: pre-wrap` — 안 주면 저장은 됐어도 한 줄로 보인다 |

같은 규칙이 **공지 내용**, **스탯 영향 설명**에도 적용된다.

⚠️ **판단 필요 — 시작일** : 사용자는 입력값에 "시작일(null 허용)"을 포함해 설명했으나, `start_at` 컬럼이 **DDL·엔티티·DTO 어디에도 없다**. 시작일을 실제로 쓰려면 컬럼 추가 + DTO 수정이 선행돼야 한다. 현재 화면 설계에는 넣지 않았다.

**삭제 확인 문구**: "'{쿠폰 제목}'을(를) 삭제할까요? 되돌릴 수 없습니다."

**노출 스위치 표기 (2026-08-20 결정)** — 스위치만 덩그러니 두지 않는다. 지금 상태를 글자로 같이 보여주고, 끄면 무슨 일이 생기는지 한 줄로 덧붙인다. 전 화면 공통.

| 요소 | 내용 |
|---|---|
| 라벨 | `노출여부` |
| 상태 글자 | 켜짐 `노출 중` / 꺼짐 `숨김` |
| 보조 설명 | "끄면 사용자 화면에서 보이지 않습니다" |

공지의 고정 스위치는 상태 글자 `상단 고정` / `고정 안 함`, 보조 설명 "켜면 목록 맨 위에 고정됩니다".

## 이벤트 관리

쿠폰 관리와 골격이 같다. 다른 점만 적는다.

**목록** — 0순위(있을 때만): 썸네일 이미지. 1순위(항상): 제목+노출배지. 2순위(항상): `이벤트 타입 칩 · 시작일~종료일`.

**찾기** — 검색: 제목만(코드 개념 없음). 필터: 타입(전체/`EXTERNAL`/`INTERNAL`/`PROMOTION`) + 노출만 보기(토글 1개, "숨김만"은 없음). 정렬: 없음 — **판단 필요**, 마감 임박 순 권고.

**할 수 있는 일**: 등록/수정(입력창)·삭제(확인창, 완전 삭제) — 쿠폰과 동일. 노출 전환도 쿠폰처럼 아직 목록에서 안 눌림.

**입력 항목**

| 이름 | 종류 | 필수 | 기본값 | 검증 규칙 |
|---|---|---|---|---|
| 제목(title) | 글자 | O | - | - |
| 이벤트 타입(eventType) | 선택(`EXTERNAL`/`INTERNAL`/`PROMOTION`) | - | `EXTERNAL` | 화면에 영문 코드 그대로 노출 — 한글화 필요(**판단 필요**) |
| 시작일(startAt) | 날짜 | O | - | - |
| 종료일(expireAt) | 날짜 | O | - | - |
| 이미지 URL(imageUrl) | 글자 | X | - | URL 텍스트 입력, 파일 업로드 아님 |
| 외부 링크(externalLink) | 글자 | X | - | - |
| 노출여부(visible) | 스위치 | - | 켜짐 | - |

**삭제 확인 문구**: "'{이벤트 제목}' 이벤트를 삭제할까요? 되돌릴 수 없습니다."

## 공지 관리

쿠폰 관리와 골격이 같다. 다른 점만 적는다.

**목록** — 0순위: 소스 칩(`SITE`/`OFFICIAL`) + 고정 배지(고정된 공지만). 1순위(항상): 제목 + 노출 배지(**눌러서 즉시 전환됨** — 유일하게 이미 구현된 화면). 2순위(항상): 게시일.

**찾기** — 검색: 제목만. 필터: 소스구분(전체/`SITE`/`OFFICIAL`), 노출만 보기(토글), 고정만 보기(토글). 정렬: 로직 없음 — **판단 필요**, 고정 공지 최상단 + 그 안에서 최신순 권고(지금은 고정 여부와 무관하게 서버 순서).

**할 수 있는 일** — 등록/수정은 입력창. **삭제 기능 자체가 없다**(코드에 버튼 없음) — **판단 필요**. 노출 전환은 목록 배지로 즉시(이미 동작).

**입력 항목**

| 이름 | 종류 | 필수 | 기본값 | 검증 규칙 |
|---|---|---|---|---|
| 제목(title) | 글자 | O | - | - |
| 내용(content) | 글자(여러 줄) | X | - | 코드상 필수 아님 |
| 소스구분(source) | 선택(`SITE`/`OFFICIAL`) | - | `SITE` | 영문 그대로 노출 — 한글화 필요(**판단 필요**) |

| 고정여부(isPinned) | 스위치 | - | 꺼짐 | - |

**삭제 확인 문구**: 해당 없음(삭제 기능 없음).

## 유저 관리

다른 화면과 골격이 다르다 — 검색·필터·목록만 있고 등록/수정/삭제가 없다(상세 화면이 다음 사이클로 미뤄져 있음, 코드 주석에 `[HITL]` 표시).

**목록** — 1순위(항상): 닉네임(왼쪽) + 역할 배지(`ADMIN`/`USER`)·상태 배지(`ACTIVE`/`BANNED`/`WITHDRAWN`)(오른쪽). 2순위: 마지막 로그인일. 목록 위에 "총 N명" 건수.

**찾기** — 검색: 닉네임만. 필터: 역할(선택 상자, 전체/`ADMIN`/`USER`), 상태(선택 상자, 전체/`ACTIVE`/`BANNED`/`WITHDRAWN`), 기본값 둘 다 전체. 정렬: 없음.

**할 수 있는 일** — 행을 누르면 창이 뜨지만 "유저 상세 기능은 다음 사이클에서 구현 예정입니다." placeholder뿐이다. 등록·수정·삭제·노출전환 없음 — 조회 전용.

**입력 항목**: 없음(폼 미구현).

**비어 있을 때·잘못됐을 때** — 불러오는 중: "불러오는 중..." (다른 화면과 문구 통일 필요, **판단 필요**). 실패: (에러 메시지) [다시 시도]. 결과 0건: "유저가 없습니다." → 검색/필터 0건과 전체 0건 구분 필요(**판단 필요**).

**삭제 확인 문구**: 해당 없음.

## 위키 관리

스탯 영향 관리 1개 화면. **검색·필터가 아예 없다**(재설계 때 붙일지는 "정해야 할 것" 참고). 지금은 화면 위 "+ 추가" 버튼과 목록만 있고, 등록·수정 창은 화면 가운데 뜨는 모달, 삭제 확인도 화면 안에 복사된 자체 모달이다 — 재설계 후 공용 부품(입력창은 중앙 모달, 확인창은 `ConfirmDialog`)으로 교체한다.

## 관리자 홈

`/admin` 메뉴 진입점. 메뉴 카드 5장(2열 그리드) — 쿠폰 관리, 이벤트 관리, 공지 관리, 유저 관리, 백과사전(위키) 관리. 카드마다 아이콘 + 2줄 라벨.

**지금 라우터에 연결돼 있지 않다.** 화면 파일은 있고 "각 관리 화면의 뒤로가기가 여기로 돌아온다"는 주석까지 있지만, 실제로 주소(`/admin`)를 열면 뜨지 않는다 — 다른 관리 화면들의 뒤로가기가 향할 곳이 없는 상태다. 재설계 때 반드시 라우터에 연결해야 완료 처리된다.

검색·필터 없음(메뉴 진입점). 커뮤니티 관리 카드는 없음 — 범위 밖.

| 목록 형태 | 카드 | 카드(+썸네일) | 카드 | 카드(행) | 카드 |

**부품 하나로 커버되는 묶음**
- 쿠폰·이벤트·공지 — 검색창(`SearchField`) + 필터칩(`FilterChipGroup`) + 입력창(`AdminFormPanel`, 중앙 모달) 한 벌로 3화면 전부. 부품 검증의 기준 화면들.
- 스탯영향 — 목록(`AdminList`) + 입력창(`AdminFormPanel`) + 확인창(`ConfirmDialog`). 화면 안에 복사된 `FormModal`/`ConfirmModal` 함수를 걷어내는 작업.
- 유저 — 검색창+선택형 필터까지는 위 부품 재사용, 등록/수정/삭제가 없어 입력창 부품은 불필요(상세 화면은 범위 밖).
- 관리자 홈·위키 관리 홈 — 메뉴 카드(`AdminMenuCard`) 한 부품으로 두 화면 다 커버.
