# Admin v2 화면 7장 — 인수인계

> 3단계 중 2단계(조립) 산출물. 1단계 부품 10종의 인스턴스를 배치해 화면 7장을 조립했다.
> 코드: `figma-plugin/domains/admin-screens-v2.ts`(신규) + `admin-components.ts`(좌표만 수정) + `code.ts`(진입점 등록)

## 사용자가 할 일

1. `cd figma-plugin && npm run watch` (또는 `npm run build` 1회)
2. Figma desktop에서 `Ctrl+Alt+P` (Run Last Plugin)
3. 이번 실행은 부품 섹션을 `x:10400`으로 재배치한 뒤 화면 7장을 새로 그린다 — 기존 admin 화면 7장(`16:xxx`)과 DS v2.0/v3.0은 건드리지 않는다.

## 화면별 — 기존 시안 대비 달라진 점

**관리자 홈** — 탭바 없음. 메뉴 카드 5장을 세로 1열로, 쿠폰·이벤트·공지·유저·백과사전만(범위 밖 게시판/게시글/태그/대시보드/선수카드 제거, 빠졌던 공지 카드 추가). 아이콘은 보라 단색 이니셜 원(무지개색 제거).

**쿠폰 관리** — 탭바·상시 로그아웃 버튼 제거. 필터를 드롭다운에서 칩(`전체/노출/숨김`)으로. 등록 버튼을 머리말 안 폭 전체 44px로, "총 4건" 표기 추가. 카드는 제목+토글(신호 1개로 통일, 좌측점·배지 제거) / `코드·할인·만료일` 한 줄 / 수정·삭제(보조·위험 버튼, 보라 없음). 만료 5일 남은 항목은 코션 앰버로, 종료 쿠폰은 카드 전체 흐림 처리.

**쿠폰 등록** — 중앙 팝업 → 바텀시트(`C/FormPanel` + 스크림 55%). 입력 7개 전부(제목·쿠폰코드·**할인타입·할인값·최소주문금액**·만료일·**노출여부**) — 기존에 빠져 있던 4개 추가.

**유저 관리** — 탭바 제거, 필터를 역할/상태 2개 칩 그룹으로. 아바타 삭제(신규 prd 명세에 아바타 항목 자체가 없어 자연히 제거). "관리" 버튼 반복 제거 — 조회 전용이라 행동 버튼 없이 역할·상태 배지 + `›`만.

**이벤트 관리** — 탭바 제거, 필터를 타입 4칩 + 노출 2칩으로. 카드에 이벤트 타입 배지 + 기간 추가. 썸네일은 "21 IMG" 같은 디버그 텍스트 대신 단색 아이콘 자리표시. 종료 임박은 코션 앰버, 종료된 이벤트는 흐림 처리.

**이벤트 등록 / 이벤트 수정** — 중앙 팝업 → 바텀시트. "파일 업로드" 탭 완전 제거, 이미지 URL 텍스트 입력만. "이벤트 출처=OFFICIAL" 오류 필드 삭제, 이벤트 타입(외부/내부/프로모션) 선택으로 교체. 시작일·종료일을 한 줄에 나란히 두지 않고 세로로 각 1행씩.

## 판단해서 진행한 것 (판단 필요 항목 처리)

- **이벤트 타입 한글화** — admin-screens.md가 "판단 필요"로 남긴 항목. `외부/내부/프로모션`으로 한글 라벨을 붙였다(영문 코드 `EXTERNAL/INTERNAL/PROMOTION` 대신). 실제 코드값 자체는 안 바꿨다는 전제 — 화면 표시 라벨만.
- **유저 아바타** — critique는 "아바타 배경색 hex 판단 필요"를 지적했지만, admin-screens.md 신규 명세엔 유저 행에 아바타 항목이 아예 없다. 아바타를 그리지 않는 것으로 critique 항목 자체를 해소했다.
- **정렬 기준(만료임박순 등)** — 정적 목업이라 실제 정렬 로직은 반영되지 않는다. 시각적 위계(코션 앰버/흐림)만 샘플 데이터로 보여준다 — 실제 정렬 동작은 FE 구현 시점 결정 사항.
- **C/ConfirmDialog 미사용** — 화면 7장 목록에 "삭제 확인" 자체가 독립 화면으로 없어서 이번 조립엔 쓰지 않았다. 컴포넌트는 그대로 재사용 가능한 상태.
- **ListStateView 빌더** — 만들어만 두고 어느 화면에도 호출하지 않았다(7장이 전부 "채워진 목록" 상태만 요구). 로딩/실패/빈 목록은 실제 화면 구현 때 이 빌더를 그대로 쓰면 된다.
