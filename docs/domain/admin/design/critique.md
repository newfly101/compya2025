## 전 화면 공통 문제

심각도 순.

**1. 화면 골격 표준에 없는 탭바 층이 7장 전부에 있다 — 상**
`admin-ui-design.md`가 정한 순서는 "글로벌 상단바 → 머리말 → 검색·필터 → 목록"이다. 그런데 상단바 바로 아래에 `빠른 이동 / 이벤트 관리 / 쿠폰 관리 / 유저 관리` 탭바가 얹혀 있다. 이 층은 명세에 없는 새 층이고, 목록 화면뿐 아니라 **모달이 뜬 04·06·07에서도 배경에 그대로 밝게 남아** 있다 — 겹쳐 뜨는 창 뒤 검은 막(55%)이 이 탭바를 덮지 않는다는 뜻이다. 나타나는 화면: 01~07 전체.

**2. 상시 켜진 보라 "로그아웃" 알약 버튼 — 중~상**
모든 화면 우측 상단에 보라로 채워진 "로그아웃" 버튼이 고정돼 있다. 조명 규칙의 취지는 "켜진 곳이 적어야 신호"인데, 이건 신호가 아니라 **항상 켜진 크롬**이다. 활성 탭 밑줄(보라)까지 겹치면 화면 상단에서만 이미 보라 신호가 2개 이상 상시 점등돼 있다. 나타나는 화면: 01~07 전체.

**3. 목록 행마다 보라 채움 버튼이 반복된다 — 상**
쿠폰 목록(02)의 "수정" 7회, 이벤트 목록(05)의 "수정" 9회, 유저 목록(03)의 "관리" 3회 — 행 수만큼 보라 버튼이 찍힌다. 조명 규칙은 "적게 쓸수록 신호"라고 못 박는데, 여기선 보라가 목록의 기본 배경색처럼 반복돼 신호로서의 힘을 잃는다. 나타나는 화면: 02, 03, 05.

**4. 노출 토글 켜짐 배경이 초록 계열 — 상**
쿠폰(02)·이벤트(05) 목록의 노출 스위치가 켜졌을 때 초록으로 채워진다. `DESIGN.md` 의미 고정 규칙: "초록은 성공과 네이버, 그 외로 재활용하지 않는다." `admin-components.md`도 이미 "시그널 딥(`#6d4ad3`) 권고"라고 적어둔 항목이다. 나타나는 화면: 02, 05.

**5. 검색줄 옆 필터가 칩이 아니라 드롭다운으로 그려져 있다 — 상**
`admin-components.md`의 `FilterChipGroup`은 "여러 값 중 하나를 고르는 알약 버튼 묶음, 검색창 아래 줄에서 가로 스크롤"이다. 그런데 02("전체 노출 ▾"), 03("전체 Role ▾"), 05("전체 상태 ▾" + "전체 노출 ▾")는 전부 검색창과 **같은 줄에 붙은 셀렉트 박스**로 그려져 있다. 특히 05는 한 줄에 검색창+드롭다운 2개가 끼어 있어 각 요소 폭이 좁아진다. 부품 자체가 다른 것으로 대체됐다. 나타나는 화면: 02, 03, 05.

**6. 등록 버튼이 머리말 폭 전체가 아니라 우측의 작은 버튼 — 중**
`AdminPageHeader` 명세: "등록 버튼은 `Button` 주요 변형, 폭 전체 44px." 02·05 모두 제목 옆 우측 상단에 작게 붙어 있다. 나타나는 화면: 02, 05.

**7. 모달이 "아래에서 올라오는 시트"가 아니라 네 모서리가 둥근 중앙 팝업 — 상**
`AdminFormPanel` 명세: "위쪽 모서리만 12px", "아래에서 올라옴", "폭은 화면 틀 폭 그대로." 04·06·07 세 모달 전부 화면 중앙에 뜬 카드이고, **네 모서리가 다 둥글며**, 좌우로 배경이 남는 좁은 폭이다. 모달 화면 3장 중 3장, 즉 100%가 이 명세를 어긴다. 나타나는 화면: 04, 06, 07.

**8. 반복 요소로 인해 목록 행 전부가 같은 시각 무게 — 상**
02·05 모두 7~9개 행이 제목 굵기·배지·버튼 배치가 동일해 어디를 먼저 봐야 하는지 단서가 없다. "AI가 대충 만든 느낌"의 핵심 원인이며, 위 3·4·5·6번이 겹쳐서 생긴 결과다. 나타나는 화면: 02, 05.

## 새 프레임에서 반드시 달라져야 할 것

- 상단바 아래 "빠른 이동/이벤트 관리/쿠폰 관리/유저 관리" 탭바를 뺀다. 화면 골격은 상단바 → 머리말 → 검색·필터 → 목록 순서만 쓴다.
- 등록·수정 창은 화면 중앙 팝업이 아니라 **아래에서 올라오는 바텀시트**로 그린다. 위쪽 모서리만 12px, 폭은 화면 꽉 채움.
- 노출 토글 켜짐 배경을 시그널 딥(`#6d4ad3`)으로 바꾼다. 초록 금지.
- 목록 행마다 반복되는 "수정"/"관리" 버튼을 보라 채움에서 보조(리프티드 슬레이트) 버튼이나 텍스트 링크 수준으로 낮춘다. 보라는 한 화면에 한두 곳만 남긴다.
- "로그아웃" 버튼을 상단에 상시 보라로 두지 않는다. 무채색 텍스트 버튼이거나 서랍(메뉴) 안으로 옮긴다.
- 검색줄 옆 필터를 셀렉트 박스가 아니라 `FilterChipGroup` 알약 칩으로 그린다. 검색창 아래 줄에 가로 스크롤로 배치한다.
- 관리자 홈 메뉴 카드를 2열 5장(쿠폰·이벤트·공지·유저·위키) 또는 세로 1열로 바꾸고, 범위 밖인 게시판·게시글·태그·선수카드 카드는 뺀다. 대신 빠진 "공지 관리" 카드를 추가한다.
- 쿠폰 등록/수정 폼에 할인타입·할인값·최소주문금액·노출여부 스위치 4개 항목을 추가한다.
- 이벤트 등록/수정 폼에서 "파일 업로드" 옵션을 없앤다(URL 입력만). "이벤트 출처" 필드를 이벤트 타입(EXTERNAL/INTERNAL/PROMOTION) 선택지로 바로잡는다.
- 이벤트 폼의 시작일~종료일을 한 줄에 나란히 두지 말고 세로로 각 1개씩 쌓는다.
- 쿠폰·이벤트 목록 카드에 할인 정보/이벤트 타입 칩을 각각 추가하고, 좌측 점+배지+토글처럼 같은 정보를 색으로 세 번 반복하지 않는다(신호 하나만 남긴다).
- 이벤트 썸네일 자리의 "21 IMG" 같은 원시 텍스트를 실제 이미지 또는 정돈된 빈 상태 아이콘으로 바꾼다.
- 등록 버튼은 머리말 안에서 폭 전체 44px로, "총 N건" 건수 표시를 머리말에 함께 넣는다.
- 목록에서 만료·종료 임박 항목은 코션 앰버 강조 또는 흐림 처리로 차등을 줘 7~9행이 전부 같은 무게로 보이지 않게 한다.

## 판단이 필요한 것

- 아바타 배경의 파랑 계열, 관리자 홈 아이콘의 무지개색 — 정확한 hex를 이미지로 확정할 수 없다. 실제 코드/토큰 값 확인 후 팔레트 밖이면 교체할지 결정 필요.
- 모달 테두리에 옅은 보라 색조가 있는 것처럼 보이나(04·06·07), 압축으로 인한 눈속임일 가능성도 있다 — 이미지로 판정 불가. 실제 CSS 값 확인 필요.
- 유저 목록(03)에 상태 필터(활성/정지/탈퇴)가 안 보이는 것이 누락인지 스크롤 밖인지 이미지로 판정 불가. 코드 확인 권고.
- 이벤트 폼의 "이벤트 출처=OFFICIAL" 값이 단순 라벨링 실수인지, 실제로 공지 관리 코드를 그대로 복사해 쓴 화면 로직 문제인지는 디자인 시안만으로는 판단할 수 없다. 코드 연동 여부 확인 필요.
- 등록/삭제 버튼 크기가 화면마다(작은 정사각형 vs 텍스트형) 다르게 보이는 것이 의도된 축소판인지 렌더링 오차인지 — 실제 컴포넌트 크기 실측 필요.
