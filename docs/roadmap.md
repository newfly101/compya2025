## 5. 계획 중인 기능 — 기획만 있고 코드가 없는 도메인

`web/src/domains/`에 폴더가 없어 `features/`로 옮길 수 없다. 원본은 `docs/domain/{account,analytics,gamification}/prd/`(git 태그 `docs-archive-2026-09`로 보존)에 있었다.

### account — 저장함 착수가 1순위

- 지금 로그인 사용자가 할 수 있는 일은 내 정보 보기·닉네임 변경·탈퇴 3개뿐이다.
- 결정 완료(2026-09-11) — 다음 확장 1순위는 **저장함**: 종류 무관 단일 저장함 + 종류별 탭. 비로그인도 담을 수 있고 로그인 시 계정으로 병합(겹치면 그대로 두고, 실패해도 브라우저 쪽은 지우지 않음). "로그인 필요" 표시 화면은 지금처럼 실제로는 막지 않는 상태를 유지. 두 번째 로그인 수단(구글 등)은 당분간 보류.
- 저장 대상 조건 3가지 — 가리킬 주소가 있고 / 담은 뒤 오래 남고 / 사라졌을 때 표시 방식이 정해져 있어야 담는다. 활동 기록(gamification, §5)과는 다른 레이어다 — 활동 기록은 지울 수 없는 원장, 저장함은 사용자가 언제든 뺄 수 있는 상태.
- 계정 테이블 개편 설계 완료·미실행 — `site_users`는 그대로 두고(id 유지) OAuth 원본만 `site_user_oauth_accounts`로 분리, 숫자 `id` 유출 방지용 `public_id`(UUID v4) 신설, 탈퇴 시각 전용 컬럼(`withdrawn_at`) 추가. SQL 4단계 작성 완료(운영 DB 승인 필요, 되돌릴 수 없는 단계 1개 — `oauth_*` 컬럼 DROP).
- 미결 — 탈퇴 시 저장물 처리 방식(§6 D-03).

### analytics — 서버 측 행동 이벤트 수집, 설계만 완료

- GA4만으로는 서버 DB 안에서 방문자 행동을 집계·조합할 수 없어 별도 설계했다. 이번 단계는 **테이블 설계뿐** — 수집 API·집계 배치·어드민 화면은 다음 단계.
- `site_user_event`(원장, 비로그인은 `anon_id` 쿠키로 식별) + `site_user_event_daily`(일별 집계) 2테이블 초안.
- 선행 조건 — 개인정보처리방침 제5조에 `anon_id` 쿠키 항목을 추가하는 개정이 필요하다. 공지 초안은 작성됐으나(시행일 2026-09-17 목표) 실제 게시·시행 여부는 미확인.
- 원본 보관 6개월 / 집계 영구 보관은 실 트래픽을 모르는 상태의 가정값 — 확정 필요.
- `statistics`(후원 클릭 집계)는 이미 완료·운영 중인 별개 도메인이니 혼동하지 않는다.

### gamification — 업적·재방문 유도, 착수 전

- 코드 0건, 기획 4편만 있다. 목표는 두 가지 — 비로그인 방문자를 가입시키기 / 가입 회원을 다시 오게 하기.
- 실측 — 좋아요·댓글·신고 테이블은 존재하나 운영 데이터가 0건이고, 트래픽 96%가 비로그인이라 참여형 기능을 걸 표면이 거의 없다.
- 도입 전 "유저 활동 기록 레이어" 선행 필요 — 원장(`site_user_activity`) + 집계 + 연속 출석 테이블, 스프링 이벤트 발행 + 비동기 소비 방식. analytics의 익명 집계와는 별개다(계정에 귀속되는지가 다름).
- 포인트·레벨·공개 랭킹은 도입하지 않기로 확정. 초기 보상은 전면광고 면제(확정, 광고 재활성화 후에야 체감) + 명예 표시 + 칭호·뱃지뿐 — 뱃지를 보여줄 진열장(마이페이지)이 아직 없어 반쪽짜리다.
- 초기 업적 12종(연속 출석 3·7·30일, 백과사전 탐구자 등 서로 다른 항목 열람 기준) 설계는 됐으나 착수 전. 커뮤니티·퀴즈 기반 업적은 각각 FE-BE 연결·제출 API 신설이 선행 조건이라 조건부로만 남겨둠.
- 미결 — 다음 구현 대상 확정(§6 D-02).

## 7. 배운 것

- Redis를 도입한 당일(2026-02-17) VM 부하로 즉시 롤백했다 — 재도입은 필요성이 확실할 때만 검토한다.
- 모바일 전환(v3.0.0)은 PC/모바일 이중 유지가 아니라 도메인별로 PC 파일을 순서대로 삭제하며 진행했다 — 단계적 삭제가 병행 유지보다 안전했다.
- 도메인은 여러 번 죽고 되살아난다 — wiki·skill·coach·kbo·스킬 시뮬레이터 등이 폐기됐다. "삭제됨"(코드가 지워짐)과 "지금 없음"(아직 안 만듦)을 구분하지 않으면 재기획 때마다 혼선이 생긴다.
- 애드센스는 2026-08-22 최초 신청 이후 반복 반려됐다(콘텐츠 없는 화면 광고, 가치 낮은 콘텐츠) — 가이드 12편 등 콘텐츠 보강으로 대응 중이나 아직 미승인 상태다.
- 공백 기간이 2회, 총 103일(2026-03-05~03-27, 06-01~08-19) 있었다 — 둘 다 취업으로 인한 중단. 1인 프로젝트 일정을 추정할 때 감안해야 한다.
- 문서보다 코드가 항상 먼저였다 — 이 프로젝트의 기본 문서화 방법은 기획서를 앞서 쓰는 것이 아니라 코드에서 거꾸로 역산하는 것(as-built)이다.
