# 검증 실측 사례 — 코드 판정과 실측이 갈린 자리

> [ai-workflow.md](ai-workflow.md) § 검증을 두 겹으로 둔 이유 에서 분리. 코드만 읽었을 때의 판정과, 화면·운영 빌드를 직접 열어본 뒤의 판정이 어떻게 달랐는지 5건.

| 사례 | 코드만 봤을 때 | 실측 결과 |
|---|---|---|
| 고정 공지가 홈 미리보기 목록에서 빠짐 | 결함 있음 | 고정된 공지 번호가 우연히 전체 중 최댓값이라 지금은 증상이 안 보임 — "결함은 있지만 지금은 조용하다"(잠재 결함) |
| 외부 공지 카드 클릭이 안 됨(오타) | 결함 있음 | 지금 공지가 전부 내부 링크뿐이라 그 카드 자체가 0건 — 위와 같은 잠재 결함 |
| 운영 홈의 회원·이벤트 건수 배지가 20으로 표시 | 확인 필요 | 브라우저로 직접 눌러 545명·37건과 다름을 확정 — 실제 결함으로 승격 |
| 관리자 화면에서 참조 오류 1회 관측 | 결함 의심 | 같은 화면을 하드 리로드 10회 재현 시 0회 — 다른 세션이 그 파일을 편집하던 순간을 밟은 오탐으로 확정 |
| 로그인 모듈 순환 참조 오류 | 결함 의심 | 개발 서버(HMR) 중에만 재현되고 운영 빌드로는 재현되지 않음 — 실제 사용자에게는 영향 없음 |

코드 읽기만으로는 다섯 건 모두 "결함"에서 멈췄을 것이다. 화면을 직접 열어보고, 나아가 운영 빌드로 다시 열어봐야 "지금 실제로 터지는가"까지 갈릴 수 있었다.
