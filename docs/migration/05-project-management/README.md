# 05. 프로젝트 관리 체계

> 기준일: 2026-09-25
> 배경: 문서가 네 곳(저장소 `CLAUDE.md` · `docs/` · `PRODUCT.md`, Notion)에 흩어져 기준일이 어긋나고([OPS-01](../02-diagnosis/ops/OPS-01-docs-drift.md)), 작업이 「확인」 에서 멈췄다([OPS-05](../02-diagnosis/ops/OPS-05-done-definition.md)). 이관처럼 수십 건이 이어지는 작업을 하기 전에 관리 규칙부터 정한다.

---

## 1. 무엇이 문제였나

| 증상 | 원인 |
|---|---|
| 두 달 공백 뒤 "문서를 믿을 수 없어 코드를 다시 셌다" | 같은 사실(도메인 목록, 스냅샷 수)을 여러 문서가 각자 적고 각자 낡았다 |
| AI 도구가 삭제된 줄 아는 도메인이 운영 중 | `CLAUDE.md` 가 사실(도메인 목록)을 담고 있었다 |
| 손댄 29건 중 완료 1건 | "무엇을 하면 완료인가" 가 작업마다 정해져 있지 않았다 |
| 기술 결정의 이유가 Notion 산문 속에 | 코드 옆에서 찾을 수 없고, 코드가 바뀌어도 함께 바뀌지 않는다 |

---

## 2. 원천(Source of Truth) 규칙

**한 가지 사실은 한 곳에만 쓴다. 다른 곳은 링크한다.**

| 무엇 | 원천 | 형식 | 다른 곳에서는 |
|---|---|---|---|
| 제품 정의(누구를 위한 무엇인가) | `PRODUCT.md` | 스키마 형식 | 링크 |
| 기획 · 기능 정의 · 컨텐츠 · 운영 정책 | **Notion** 「컴프야펀 로드맵」 | 머리말 + 번호 제목 + 근거 토글 | 저장소에서는 링크만 |
| 작업 목록 · 진행 상태 · 검증 | **Notion** 「📋 작업 보드」 | DB 행 | 결함 md 머리말 `상태` 는 요약, 원천은 보드 |
| 코드 컨벤션 | 저장소 `docs/convention/` | 규칙 표 | Notion 에서는 링크 |
| 기술 결정(ADR) · 결함 진단 · 이관 계획 | 저장소 **`docs/migration/`** | 이 폴더의 규칙 | Notion 「Next.js 이관」 페이지는 요약 + 링크 |
| AI 작업 규칙 | `CLAUDE.md` | 워크플로 규칙만 | **사실(목록 · 수치)을 쓰지 않는다** — 명령이나 문서 링크로 |

판단이 애매할 때: **코드가 바뀌면 같이 바뀌어야 하는 문서는 저장소**, 코드와 무관하게 사람이 결정하는 것은 Notion.

---

## 3. 식별자 규칙

| 대상 | 형식 | 예 |
|---|---|---|
| 결함 | `{FE|BE|OPS}-{두 자리}` | `BE-02` |
| 이관 단계 | `phase-{n}` | `phase-1` |
| Notion 작업 보드 행 제목 | `[{ID}] 한 줄 요약` | `[BE-02] 만료 토큰이면 공개 조회도 401` |
| 브랜치 | `{fix|feat|docs|migrate}/{ID 또는 단계}-{짧은-이름}` | `fix/BE-02-anonymous-on-invalid-token`, `migrate/phase-3-shell` |
| 커밋 | 기존 규칙 `[태그] [유형]` 에 ID 추가 | `[이관] [fix] [BE-02] 무효 토큰을 익명으로 처리` |
| PR 제목 | 커밋과 같은 형식 | |

ID 하나로 결함 md · 보드 행 · 브랜치 · 커밋 · PR 을 검색할 수 있게 하는 것이 목적이다.

---

## 4. 상태 어휘 — Notion 과 맞춘다

| 결함 md `상태` | Notion 작업 보드 「진행」 | 의미 |
|---|---|---|
| 열림 | 백로그 / 이번 차례 | 아직 손대지 않음 |
| 진행 | 진행중 | 브랜치가 있다 |
| 확인 | 확인 | 운영 배포됨, 완료 기준 확인 중 |
| 닫힘 | 완료 | §5 완료 정의 충족 |

---

## 5. 완료 정의 (Definition of Done)

네 가지가 모두 참일 때만 「완료」 다.

1. `master` 에 병합되고 운영에 배포됐다
2. 결함 md 의 **완료 기준** 체크리스트가 전부 체크됐고, 증거(명령 출력 · 스크린샷 · 커밋)가 PR 이나 보드 행에 링크됐다
3. 결함 md 머리말 · `docs/migration/README.md` 색인 · Notion 보드 행이 갱신됐다
4. PR 본문에 되돌리는 방법이 있다

「확인」 에 7일 넘게 머문 행은 주간 점검에서 「완료」 또는 「진행중」 으로 옮긴다.

---

## 6. 문서 수명 규칙

| 규칙 | 이유 |
|---|---|
| 모든 문서 머리말에 `기준일` | 읽는 사람이 낡았는지 판단할 수 있게 |
| 개수 · 수치는 **측정 명령**과 함께, 가능하면 명령만 | `grep -c '<loc>' web/public/sitemap.xml` 은 낡지 않는다 |
| 코드 경로는 `파일:줄` + 심볼 이름 | 줄 번호는 낡아도 심볼로 다시 찾을 수 있게 |
| 단계가 끝날 때마다 이 폴더 색인 · Notion 요약 점검 | 점검 시점을 사건(단계 종료)에 묶는다 — 달력에 묶으면 밀린다 |
| 삭제된 문서 위치는 되살리지 않는다 | `CLAUDE.md` §3 의 규칙 유지 |

---

## 7. 주간 루틴 (1인 운영 기준, 30분)

1. 작업 보드 「확인」 열 비우기 — 증거 붙이고 완료, 또는 되돌리기
2. `docs/migration/README.md` 결함 색인과 보드 행 수 대조
3. 이번 주 병합된 PR 에 결함 ID 가 없는 것 확인 — 있으면 보드에 행 추가
4. 다음 주 「이번 차례」 3건 이하로 고르기
