# 포트폴리오 정리 — CSR → Next.js 이관

> 기준일: 2026-09-25
> 원칙: **측정한 것만 수치로 쓴다.** 이관이 끝나기 전에는 "계획 · 진행 중" 으로 쓰고, 결과 수치는 6단계 관찰이 끝난 뒤 채운다.

## 1. 한 줄 (용도별)

| 용도 | 문장 |
|---|---|
| 통합 | 애드센스 반려의 원인이던 SPA 의 빈 HTML 문제를 빌드타임 prerender 로 먼저 막고, 스냅샷 폐기 · 소프트 404 등 구조적 한계를 진단해 **결함 22건을 단계별로 닫으며 Next.js 정적 export 로 이관**하는 계획을 세우고 진행 |
| 프론트엔드 강조 | React SPA 를 Next.js App Router 로 이관하며 서버/클라이언트 컴포넌트 경계, hydration 불일치를 만드는 브라우저 전용 코드를 정리하고 크롤러와 사용자가 같은 HTML 을 받도록 재설계 |
| 백엔드 강조 | 빌드 서버라는 새 API 소비자를 위해 에러 의미론(전부 500 → 4xx/5xx 구분), 공개 API 의 만료 토큰 401, OAuth state 미검증, 공지 슬러그 계약을 정리하고 콘텐츠 발행 → 정적 재빌드 트리거를 설계 |
| 프로젝트 관리 강조 | 문서 4곳의 불일치 14건과 「확인」 에 멈춘 작업 28건을 계기로 원천 규칙 · 결함 ID · 완료 정의를 도입해 1인 프로젝트의 추적 체계를 재정비 |

## 2. STAR

| | 내용 |
|---|---|
| **Situation** | 1인 개발한 게임 정보 사이트(Spring Boot + React SPA, S3 + CloudFront). 운영비 회수를 위해 애드센스를 신청했으나 「콘텐츠 없는 화면의 광고」 「가치 없는 콘텐츠」 로 반려(2026-08-30) |
| **Task** | 크롤러가 실제 본문을 받게 하되, 1인 · 짧은 기한에서 운영 위험을 키우지 않을 것 |
| **Action** | ① 원인 실측: 모든 주소가 같은 빈 HTML, sitemap 2개, JS 클릭 링크 ② 1차 대응: 빌드타임 prerender + CloudFront 경로 보정 + 정책 페이지 + 수동 광고 슬롯 ③ 한계 진단: `createRoot` 로 스냅샷 폐기, 소프트 404, 셀렉터 기반 대기의 취약성 ④ 렌더링 방식 5종 · 프레임워크 5종 비교 후 Next.js 정적 export 선택(인프라 유지, 이후 SSR 로 확장 가능) ⑤ 이관 전 선결 결함(BE 에러 매핑, 공개 API 401, OAuth state, 공지 슬러그)을 현행 앱에서 수정하는 8단계 로드맵 수립 |
| **Result** | (측정 후 기입) sitemap 주소 2 → 27+α(prerender 단계 실측) · 소프트 404 · LCP/CLS 전후 · 빌드 시간 · 애드센스 재심사 결과 |

## 3. 면접 예상 질문과 답의 뼈대

| 질문 | 답의 뼈대 | 근거 문서 |
|---|---|---|
| 왜 처음부터 SSR 로 안 했나? | 3주 · 1인 기한에서 라우터 · 스토어 · 인프라를 한 번에 바꾸는 위험. prerender 로 목표(본문 노출)를 먼저 달성하고, 한계를 실측한 뒤 다음 단계를 정했다 | `01-background/prerender-stopgap.md` |
| 왜 SSR 이 아니라 정적 export 인가? | 공개 페이지가 전부 인증 없이 그려지고 변경 빈도가 낮다. 인프라를 바꾸지 않으면서 같은 코드로 나중에 SSR 을 붙일 수 있다 | `01-background/rendering-options.md` |
| hydration mismatch 를 어떻게 막나? | 첫 렌더에 브라우저 전용 값(storage · 인증 · 시간)을 쓰지 않는다. 인증 의존 UI 만 마운트 후 렌더 | `04-deep-dive/frontend-fullstack.md` §2 |
| 이관하면서 백엔드는 왜 고쳤나? | 빌드 서버가 새 소비자 — 404 와 500 을 구분해야 페이지를 생략할지 배포를 멈출지 정할 수 있다 | `04-deep-dive/backend-fullstack.md` §1, §3 |
| 쿠키 SameSite 를 왜 바꾸나? | 두 도메인이 같은 사이트라 Lax 로 충분하고, None 은 CSRF 노출면만 넓힌다(CSRF 필터 꺼짐) | `02-diagnosis/backend/BE-04-cookie-model.md` |
| 새 공지는 정적 페이지에 어떻게 반영되나? | 커밋 후 이벤트 → GitHub `repository_dispatch` → 재빌드, 연속 발행은 concurrency 로 마지막만 | `03-roadmap/phase-5-seo-parity.md` §2 |
| 가장 어려웠던 점? | "빌드는 성공했는데 빈 표가 배포되는" 조용한 실패. 실패를 빌드 실패로 드러나게 바꾸는 것이 이관의 핵심 동기 중 하나 | `02-diagnosis/frontend/FE-03-prerender-fragility.md` |
