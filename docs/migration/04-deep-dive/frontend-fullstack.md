## 1. 렌더링 스펙트럼과 이 프로젝트의 위치

```
빌드 때 HTML ◀────────────────────────────────────▶ 요청 때 HTML
   SSG            ISR              SSR               CSR(HTML 없음)
   ▲ 이관 1차      ▲ 7단계 후보     ▲ 7단계 후보       ▲ 2026-08 까지
```

판단 기준은 **"이 페이지의 HTML 이 언제 틀려지는가"** 다.

| 페이지 | 데이터가 바뀌는 주기 | 틀려져도 되는 시간 | 방식 |
|---|---|---|---|
| 정책 · 가이드 | 코드 배포 때 | 무관 | SSG |
| 스킬 · 선수 · 레전드 · 히스토리 | SQL 시드 적재 때(수동, 드묾) | 다음 배포까지 | SSG |
| 쿠폰 · 이벤트 · 공지 | 하루 몇 건 | 수 분 | SSG + 발행 시 재빌드 |
| 커뮤니티(글쓰기 개방 후) | 분 단위 | 수십 초 | ISR 또는 SSR (7단계) |
| 마이페이지 · 어드민 | 사용자별 | 색인 안 함 | 정적 셸 + CSR |

## 2. Hydration — 왜 prerender 스냅샷은 이어받을 수 없었나

**Hydration** 은 서버가 만든 HTML 에 React 가 이벤트 핸들러와 상태를 **붙이는** 과정이다. 조건은 하나다: **첫 클라이언트 렌더 결과가 서버 HTML 과 같아야 한다.**

| | prerender 스냅샷 | Next SSG |
|---|---|---|
| HTML 을 만든 주체 | 헤드리스 브라우저가 실행한 앱 — 그 순간의 `localStorage` · 시간 · 네트워크 상태 포함 | 빌드 서버의 React — 입력은 props(데이터)뿐 |
| 첫 클라이언트 렌더와 같다는 보장 | 없음 | 규칙을 지키면 있음 |
| 그래서 | `createRoot` 로 버리고 다시 그림 (`main.jsx:7`) | `hydrateRoot` (프레임워크가 처리) |

불일치를 만드는 대표 원인과 처방:

| 원인 | 예 (이 코드베이스) | 처방 |
|---|---|---|
| 렌더 중 브라우저 저장소 읽기 | `useState(readSavedView)` — 선수 백과사전 보기 방식 | 첫 렌더는 기본값, `useEffect` 에서 읽어 반영 |
| 인증 상태에 따른 분기 | TopBar 로그인 버튼, `AuthProvider` 의 `null` 렌더 | 인증 의존 UI 만 마운트 후 렌더 |
| 시간 · 난수 | "N일 남음" 배지, 랜덤 퀴즈 | 서버는 날짜만, 상대 시간은 클라이언트에서 |
| 미디어 쿼리 | `window.matchMedia` 초기값 | CSS 로 처리하거나 마운트 후 |

## 3. 서버 컴포넌트 / 클라이언트 컴포넌트

App Router 에서 컴포넌트는 **기본이 서버 컴포넌트**다. `"use client"` 를 파일 맨 위에 쓰면 그 파일과 그 파일이 import 하는 것이 클라이언트 번들에 들어간다.

| 서버 컴포넌트 | 클라이언트 컴포넌트 |
|---|---|
| `async` 가능 — `await fetch()` 를 직접 | 훅(`useState` · `useEffect`) · 이벤트 핸들러 |
| 번들에 안 들어감(0 KB) | 번들에 들어감 |
| 브라우저 API 불가 | 브라우저 API 가능(단, 렌더 중엔 조심) |
| Redux 불가 | Redux 가능 |

**경계를 긋는 법** — 화면을 "데이터를 가져와 배치하는 껍데기(서버)" 와 "사용자가 만지는 조각(클라이언트)" 으로 나눈다. 이 프로젝트의 기존 컨벤션(`Screen` = 조립, `components/` = UI 단위, `hooks/` = 로직)과 잘 맞는다.

```
app/(site)/skills/page.tsx          서버: await apiGet('/player-skills/hitters') …
 └─ domains/playerSkills/mobile/PlayerSkillScreen.tsx   서버 또는 클라이언트(필터 상태가 있으면 클라이언트)
     ├─ SkillFilterBar.tsx          "use client" — 필터 상태
     ├─ SkillList.tsx               props 로 목록을 받아 그림 — 어느 쪽이든 가능
     └─ AdSlot.tsx                  "use client" — 마운트 후 push
```

⚠️ 흔한 실수: 서버 컴포넌트에서 클라이언트 컴포넌트로 **함수를 props 로 넘기기**(직렬화 불가), 클라이언트 컴포넌트에서 서버 전용 모듈(`infra/http/server.ts`) import.

## 4. 상태 관리 재배치

지금은 거의 모든 서버 데이터가 Redux 에 들어간다(리듀서 16개). 이관 후에는 **상태의 출처별로** 둔다.

| 상태 종류 | 예 | 이관 후 위치 |
|---|---|---|
| 서버 데이터(공개) | 쿠폰 목록, 스킬 목록 | 서버 컴포넌트 props. Redux 불필요 |
| 서버 데이터(사용자별) | 내 정보, 관리자 목록 | 클라이언트 조회 → Redux(기존 thunk 재사용) |
| UI 상태 | 필터, 모달, 선택 탭 | 컴포넌트 `useState` 또는 URL 쿼리 |
| 세션 | 로그인 사용자 · 역할 | Redux `auth` 슬라이스(클라이언트) |

이러면 Redux 는 작아지고, **요청마다 새 스토어**(`makeStore`)가 필요한 이유(SSR 시 사용자 간 상태 누출)도 자연스럽게 지켜진다.

## 5. 메타 · 링크 · 광고

| 주제 | 기존 | 이관 후 | 포인트 |
|---|---|---|---|
| 메타 | `useDocumentMeta` 가 `document.head` 수정 | `generateMetadata` | HTML 원문에 들어간다. JS 가 필요 없다 |
| 링크 | `<a href>` 로 수동 교체(8곳) | `<Link>` | 기본이 `<a href>` + 뷰포트 진입 시 프리페치 |
| 404 | 클라이언트 라우터 `*` | `not-found.tsx` → `404.html` + CloudFront 404 | 상태 코드가 진짜 404 |
| 광고 | `AdSlot` + `ADS_ENABLED` | 같음, `"use client"` | 본문이 HTML 에 먼저 있으므로 "빈 화면 광고" 가 구조적으로 불가능 |

## 6. Core Web Vitals 로 보는 효과 (측정 계획)

| 지표 | 지금 나빠지는 이유 | 이관 후 기대 | 측정 |
|---|---|---|---|
| LCP | JS 로드 → `/users/me` → 데이터 조회 → 렌더 | HTML 에 본문이 있어 첫 페인트에 표시 | PageSpeed 모바일, 대표 3페이지, 0단계 기준선 대비 |
| CLS | 스냅샷 → 빈 화면 → 완성 화면 | hydrate 는 DOM 을 바꾸지 않음 | 같음 |
| INP | 큰 목록(선수 11,668건) 렌더 | 영향 적음 — 가상 스크롤은 별개 과제 | 참고만 |

수치는 **측정 후에만** 문서와 포트폴리오에 쓴다. 기대치를 결과처럼 쓰지 않는다.
