# 04. 깊게 보기 — 프론트엔드 풀스택 / 백엔드 풀스택 관점

> 기준일: 2026-09-25
> 대상 독자: 이 이관을 면접 · 코드 리뷰에서 설명해야 하는 주니어 풀스택 개발자

---

## 1. 두 관점의 차이

같은 "Next.js 이관" 을 두 자리에서 보면 질문이 다르다.

| 질문 | 프론트엔드 풀스택 관점 | 백엔드 풀스택 관점 |
|---|---|---|
| 무엇을 렌더하나 | 어느 컴포넌트가 서버에서, 어느 것이 브라우저에서 도는가 | 빌드 서버라는 **새 API 소비자**가 생긴다 — 그 소비자가 요구하는 계약은? |
| 언제 데이터가 바뀌나 | 빌드 · hydrate · 클라이언트 재조회 중 어디서 최신 값을 보이나 | 데이터가 바뀌었다는 사실을 누가 누구에게 알리나(재빌드 트리거, 캐시 무효화) |
| 실패는 어떻게 보이나 | 404 페이지 · 에러 경계 · 빈 상태 · 로딩 | 상태 코드의 의미(4xx vs 5xx), 로그 레벨, 빌드 실패 조건 |
| 인증은 어디에 | 쿠키는 JS 가 못 읽는다(HttpOnly) — UI 는 무엇으로 로그인 여부를 아나 | 쿠키 속성(Domain · Path · SameSite · Max-Age)이 어떤 요청에 실리는가 |
| 성능 | LCP · CLS · 번들 크기 · hydration 비용 | 빌드 때 몰리는 요청, ETag · Cache-Control, N+1 |

## 3. 한 문단 요약 (면접용)

> SPA 라서 크롤러가 빈 HTML 을 받았고 애드센스에서 반려됐다. 먼저 빌드 때 헤드리스 브라우저로 스냅샷을 떠서 급한 불을 껐지만, React 가 그 스냅샷을 hydrate 하지 않고 버렸고 스냅샷이 없는 주소는 홈 HTML 을 200 으로 돌려주는 소프트 404 가 남았다. 그래서 React 가 직접 HTML 을 만들고 같은 React 가 이어받는 Next.js 정적 export 로 옮기기로 했다. 옮기기 전에 백엔드에서 에러를 전부 500 으로 돌려주던 것, 만료 토큰 때문에 공개 API 가 401 나던 것, OAuth state 를 검증하지 않던 것, 공지 슬러그를 프론트가 제목으로 만들던 것을 먼저 고쳤다. 빌드 서버가 API 의 새 소비자가 되면서 404 와 500 의 구분, 슬러그 같은 식별자, 변경 알림(재빌드 트리거)이 계약의 일부가 됐다.
