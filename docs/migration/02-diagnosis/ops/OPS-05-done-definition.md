# OPS-05 "확인" 에서 멈춘 작업 — 완료 정의 부재

> 상태: 열림
> 심각도: 🟠 이관 중 해결
> 닫히는 단계: 0단계 — [`phase-0`](../../03-roadmap/phase-0-baseline.md)
> 관련: OPS-01, `05-project-management/README.md`

## 현상
Notion 「📋 작업 보드」 에서 손댄 29건 중 **28건이 「확인」 에 멈춰 있고 「완료」 는 1건**이다(2026-09-10 집계). 코드는 고쳤지만 "직접 돌려보고 검증 칸을 채우는" 단계가 계속 밀렸다.

## 근거
| 출처 | 내용 |
|---|---|
| Notion 「프로젝트 보드」 3장 | "이 중 「완료」 는 운영자 정보 확보 1건뿐이다. 나머지 28건은 「확인」 에 멈춰 있다" |
| Notion 「작업 히스토리」 4장 | 검증 칸은 사람이 직접 채우는 칸으로 정의 — 무엇을 하면 통과인지는 항목마다 적혀 있지 않다 |

## 영향
- "끝났다고 적혀 있지만 확인 안 된 것" 이 쌓여, 이관 착수 시점에 **무엇이 실제로 동작하는지** 다시 세야 한다.
- 이관은 결함 수정 · 페이지 이전이 수십 건 이어지는 작업이라, 같은 방식이면 「확인」 칸만 더 길어진다.

## 해결 방향
1. **완료 기준을 작업을 만들 때 적는다.** 이 폴더의 모든 결함 md 는 마지막에 `## 완료 기준` 체크리스트가 있다 — 명령 · 응답 코드 · 화면처럼 **누가 해도 같은 결과가 나오는 문장**으로.
2. **완료 정의(DoD)** — 네 가지가 모두 참일 때만 「완료」:
   - 코드가 `master` 에 병합되고 운영에 배포됨
   - 완료 기준 체크리스트가 전부 체크되고, 증거(명령 출력 · 스크린샷 · 커밋)가 링크됨
   - 관련 문서(결함 md 상태, 색인, Notion 행)가 갱신됨
   - 되돌리는 방법이 PR 본문에 적힘
3. 0단계에서 기존 28건을 한 번에 훑는다: 증거를 붙일 수 있는 것은 「완료」, 없는 것은 「진행중」 으로 되돌린다. 하루를 넘기지 않도록 **건당 10분 제한**.

## 완료 기준
- [ ] Notion 작업 보드의 「확인」 상태가 7일 넘게 머문 행 0건
- [ ] 작업 보드에 「완료 기준」 칸(텍스트)이 추가됨
