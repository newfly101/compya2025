# events — 변경 이력

## 2026-09-30 — 이벤트 상세 모달 + 관리자 수집함·지금 수집 (화면)

- 버전: 2.0.0 (major — 이벤트 상세 화면 허용으로 정책 변경, spec-delta 기준)
- 커밋: `32d0cc0`(sql) · `7fcbeff`(be) · `7f94669`(web)

**고친 것**

- 이벤트 카드를 누르면 본문이 있는 이벤트는 사이트 안 상세 창(배너·기간·남은 날·본문·출처 표기·[원문 보기])이 열린다. 본문이 없고 링크만 있으면 예전처럼 새 탭, 둘 다 없으면 눌러도 반응이 없다. 본문은 화면에 그리기 직전 DOMPurify 로 한 번 더 정제한다.
- 관리자 이벤트 탭에 "수집함" 필터, 수집 초안 행의 배지(구간 못 찾음·원문 변경·마감 미확인), 본문 미리보기, 승인(기존 노출 토글), 본문 갱신, "지금 수집" 버튼(결과 건수 알림)을 추가했다.
- 수집·본문 갱신 요청을 store 의 admin endpoints·api·thunks·slice 에 추가했다.
- 서버 수집 기능을 새로 만들었다(수정 라운드 1). 매일 11:01(한국 시간)과 관리자 "지금 수집"이 같은 코드를 부르고, 공식 카페 진행 중 Event 게시판에서 GM드리미 새 글의 제목·본문·쿠폰 표를 읽는다. 이미 끝난 이벤트와 모아보기 글은 건너뛴다.
- 새 이벤트는 노출을 꺼 둔 초안으로 저장한다(공식 이벤트, 원문 주소를 외부 링크로). 본문은 "이벤트 기간" 문단부터 "감사합니다" 직전까지 허용한 태그로 다시 쓰고, 배너와 본문 이미지는 서버가 받아 S3 의 `events/{글번호}/` 로 다시 올린다. 구간을 못 찾으면 본문 없이 초안만 만든다.
- 관리자 API 2개를 추가했다 — `POST /api/admin/cafe-sync`(지금 수집, 실행 중이면 409)와 `POST /api/admin/cafe-sync/events/{id}/refresh`(본문 갱신). 둘 다 ADMIN 전용이고 결과는 `created`·`updated`·`failed`·`skipped`·`coupons` 건수다.
- 이벤트 응답에 `contentHtml`·`sourceArticleId`·`sourceChanged`·`deadlineUnconfirmed` 를 추가했고 관리자 목록에 `collected=true` 필터(수집 초안만)를 넣었다. FE 가 가정한 필드명과 그대로 맞췄다.
- 진행 중 수집 이벤트는 같은 배치에서 원문을 다시 읽어 비교하고, 달라졌으면 본문을 덮지 않고 "원문 변경" 표시만 한다. 마감을 알 수 없으면 2099-12-31 자리표시 값으로 두고 "마감 미확인" 배지로 알린다(별도 컬럼 없음).
- 새 글의 쿠폰 표에서 발행된 번호만 바로 공개로 등록한다(기한 지난 행·"공개 예정" 같은 미발행 행·칸 수가 어긋난 행은 건너뜀, 번호 중복은 무시). 카페 주소·게시판·작성자 키 설정은 application properties 에 넣었다.
- 네트워크 없이 실제 본문·쿠폰 표 구조로 제목 해석·구간 추출·쿠폰 표·원문 변경 감지를 확인하는 테스트 18개를 추가했고 모두 통과했다.
- 자가 테스트에서 본문 보상표의 병합 칸이 풀려 칸이 밀리던 것을 고쳤다 — 칸마다 rowspan·colspan 을 보존한다(`a65c4b7`). 이미 수집된 이벤트는 관리자 "본문 갱신" 으로 다시 만들면 반영된다.
- 자가 테스트 요청으로 상세 모달을 **상세 페이지 `/events/:id`** 로 바꿨다 — 본문이 있으면 페이지, 없으면 외부 링크 새 탭. 목록·홈 응답은 본문 대신 `hasContent` 만 싣고, 본문은 새 공개 API `GET /api/events/{id}` 가 준다(`b29e4dd`·`ce7ed7f`).
- 수집 이미지 S3 업로드가 전부 403 이던 것을 고쳤다 — 업로더 권한이 `uploads/images/` 아래만 있어 저장 경로를 `uploads/images/events/{글번호}/` 로 옮겼다. 본문 갱신은 이미지 한 장이라도 못 올리면 아무것도 저장하지 않는다(기존 본문·이미지 유지).
- 자가 테스트 요청으로 수집 규칙을 바꿨다 — 쿠폰 글(쿠폰 표 또는 제목에 "쿠폰")은 이벤트가 아니라 쿠폰으로만 등록하고, 본문 구간을 못 찾았거나 마감을 알 수 없는 글도 이벤트 행을 만들지 않는다. 행 없는 글은 45일 동안 매일 다시 읽어 새 쿠폰 번호를 잡는다. 손으로 등록한 이벤트와 외부 링크 글번호나 이름이 같으면 새 행 대신 그 행에 본문을 넣는다(제목·기간·노출은 그대로). 관리자 표에 본문 있음/없음 배지·필터, 수정 창에 본문 미리보기를 넣었다(`c1ee0d8`·`410e512`).

**손대지 말 것**

- 카드 클릭 시 분석 이벤트(`event_clicked`)는 모달 진입 때도 그대로 보낸다.
- 관리자 저장 payload(`baseEventDTO`)에는 본문을 싣지 않는다 — 본문은 서버 수집 전용이다.

**미결**

- 서버 응답 필드명은 서버 구현으로 확정됐다(위 고친 것 참고). 통합 단계에서 실제 화면과 대조.
- 운영 DB 에 컬럼 4개(`sql/v.2.0.0/applied/site_events_source_columns.sql`)가 적용되기 전에 서버가 뜨면 이벤트 조회가 전부 실패한다. 운영자가 DDL 을 먼저 적용해야 한다. 이 환경은 네이버 접속이 막혀 실제 카페 호출은 검증하지 못했다.
- 수집함 필터는 목록 전량을 받아 화면에서 거른다(`?collected=true` 미사용).
- `npm run build` 의 prerender 단계는 이 환경에서 공지 API 403 으로 중단됐다(`vite build` 자체는 통과).

- 버전: 1.0.1 (patch)
- 커밋: `22b247bf`

**고친 것**
