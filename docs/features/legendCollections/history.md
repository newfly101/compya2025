## 2026-09-30 — 표 머리 글자 정리 · 내 목표 기본 정렬 유지 · 액자 뱃지 모양 고정 · 꺼진 토글 회색

- 버전: 1.0.4 (patch)
- 커밋: `9d291bec`(web)

**고친 것**

- 표 머리의 "액자 먼저" 같은 글자와 표 위 정렬 설명 줄("모은 칸 많은 순")을 없앴다. 정렬 표시는 머리 한 곳뿐이고 legendStats 처럼 작은 `▼`/`▲` 만 붙는다. 상태 머리는 방향 표시 없이 글자가 굵고 밝아지기만 한다.
- 내 목표는 처음 들어왔을 때 선호 순위순이다. 머리(레전드·상태·보유)를 누르면 그 정렬을 화면 안에서 계속 쓰고(탭을 옮겨도 유지), 새로 들어오면 다시 선호 순위다. 전체 탭 기본(보유 많은 순)은 그대로다.
- `액자`·`보유중`·`오늘` 뱃지가 좁은 칸에서 눌리던 것을 고쳤다. 폭·높이를 글자 크기 기준으로 고정하고 줄어들지 않게 해, 표·펼침 머리·내 목표 카드·선호 창 어디서나 같은 크기다.
- 꺼진 `액자`·`보유중` 토글(선호 창·편집 머리)의 면을 검은색 대신 회색으로 바꿨다. `--color-lc-toggle-off-bg/-border/-text` 로 전역 중립 회색(`--color-cat-neutral-dim`)·테두리·보조 글자색에 연결해 밝은톤에서도 옅은 회색이다.

**손대지 말 것**

- 정렬 상태는 탭별이 아니라 "사용자가 눌렀는가" 하나로 판단한다. 탭 전환 때 초기화하지 않는다.

## 2026-09-30 — 선호 창 후보 줄 폭 · 내 목표 재료 8칸 · 진행 막대 빈 칸 · 표 머리 정렬

- 버전: 1.0.3 (patch)
- 커밋: `9d291bec`(web)

**고친 것**

- 선호 레전드 창 아래쪽 후보 줄이 창 밖으로 튀어나가던 것을 막았다. 줄 폭을 검색창과 같은 좌우 범위 안에 두고, 긴 구단·포지션(예 `KIA · SS · CF`)과 긴 이름은 말줄임으로 줄인다. 액자 뱃지가 없어도 `n/8` 은 오른쪽 끝에 붙는다.
- 내 목표 카드의 버튼을 "재료 보기 ▾ / 접기 ▴" 로 바꾸고, 펼치면 전체 탭 펼침과 같은 재료 선수 6칸 + 코치 2칸을 같은 화면 부품으로 보여준다. 삽입(삽입 ✓ + 보라 면)·보유(보유 뱃지 + 보라 테두리)·미보유(기본)의 색 규칙도 전체 탭과 똑같다.
- 진행 막대의 빈 칸이 배경과 같은 색이라 삽입 5칸만 보이던 것을 고쳐, 빈 칸까지 항상 8칸이 보인다. 빈 칸 색은 `--color-lc-progress-track` (전역 글자색 토큰을 옅게 섞음)이라 다크·밝은톤 모두 따라간다. 전체 탭 펼침과 내 목표 카드가 같은 부품이다.
- 전체 탭·내 목표 편집 표의 머리를 눌러 정렬한다. 레전드는 이름 오름차순 ↔ 내림차순, 상태는 미보유 먼저 → 액자 먼저 → 보유중 먼저 → 처음으로, 보유는 많은 순 ↔ 적은 순이다. `#` 는 정렬 없이 결과 순서대로 번호를 매긴다. 지금 정렬 중인 머리에는 `▼▲`(상태는 먼저 오는 상태 글자)가 붙고 `aria-sort` 를 넣었다. 표 위 "모은 칸 많은 순" 글자는 현재 정렬 설명으로 바뀐다. 편집 중에는 저장된 값 기준으로 정렬해 칸을 눌러도 줄이 튀지 않는다.

**손대지 말 것**

- 내 목표 편집의 기본 정렬은 선호 순위 그대로이고 머리 표시가 없다. 머리를 누르면 그때부터 정렬이 바뀌고 `#` 도 1부터 다시 매긴다.
- "보유" 정렬은 오름·내림 어느 쪽이든 보유중 레전드(재료 0/8)를 뒤로 보낸다.

## 2026-09-29 — 색을 레전드 재료 검색과 같게 · 탭 순서 · 순서 바꾸기 · 바깥 눌러도 안 닫힘

- 커밋: `9d291bec`(web)

**고친 것**

- 표 머리·펼친 줄·재료 카드·팀 태그·칩·탭·없음/보유/삽입 버튼의 색을 레전드 재료 검색 화면과 같은 톤으로 맞췄다. 다크·밝은톤 모두 같은 전역 색 이름을 따라가서 두 화면이 나란히 봐도 같다. 선택된 칩과 버튼은 진한 보라 채움 대신 옅은 보라 면 + 보라 테두리다.
- 위 탭 순서를 "전체 → 내 목표" 로 고정했다.

- 이 화면의 모든 창(확인·나가기·로그인 안내·충돌·선호 고르기)은 바깥(배경)을 눌러도 닫히지 않는다. 버튼·✕ 로만 닫고, Esc 는 그대로 동작한다.

**손대지 말 것**

- 색 이름은 `legendCollections.tokens.scss` 한 곳이 legendStats 와 같은 전역 토큰에 연결한다. 값(hex)을 여기서 새로 만들지 않는다 — 다시 따로 칠하면 두 화면 톤이 갈라진다.
- 나가기 확인창의 Esc 는 "나가기" 가 아니라 "머물기"(이동 취소)로 동작한다. 바깥 눌러 닫기를 없앤 것과 별개다.
- 위 1.0.1 의 "채움 버튼 위 글자는 `--color-bg-card`" 는 저장·편집 같은 큰 버튼에만 남는다. 선택 칩·작은 토글은 옅은 보라 면 위 `--color-chip-on-text` 를 쓴다.

## 2026-09-29 — 내 목표 편집 고침 · Figma 디자인대로 화면 다시 맞춤 · 팝업 연결

- 버전: 1.0.1 (patch)
- 커밋: `9d291bec`(web)

**고친 것**

- "내 목표" 탭에서 편집을 눌러도 목록이 그대로 읽기 전용이던 것을 고쳤다. 이제 전체 탭과 같은 목록·펼침·재료 버튼·액자/보유중 토글이 나오고, 대상만 선호 레전드로 좁혀진다. 두 탭이 같은 임시값(탭 안 임시 보관)과 같은 저장 요청을 쓰므로 탭을 바꿔도 고치던 값이 남는다.
- 화면 모양을 Figma 설계(열람·편집·내 목표·주기 일정·선호 고르기·팝업)대로 다시 맞췄다. 둥근 칩, 팀 태그와 이름'연도가 한 줄인 재료 카드(편집 때도 같은 크기, 카드 안 오른쪽에 없음·보유·삽입), 8칸 진행 막대, 순위 카드를 다크·밝은톤 두 테마 모두 전역 색 이름으로만 칠했다.
- 팝업을 모두 연결했다: 비로그인 편집 → 로그인 안내, 삽입이 든 저장 → "삽입 n건" 확인, 전체 초기화 → 확인, 저장 안 하고 사이트 안 이동 → "나가기 / 저장하고 나가기", 새로고침·닫기 → 브라우저 확인창, 다른 기기 수정(409) → "내 값 유지 / 서버 값 가져오기", 첫 저장 직후와 "선호 편집" → 선호 고르기. 보유중 전환은 확인창 없이 바로 바뀐다.
- 선호 고르기 창에서 손잡이를 끌어(키보드는 위아래 화살표) 순서를 바꾸고, 뺄 때는 ✕ 를 누른다.
- 편집 중에는 저장된 값 기준으로 줄을 세워, 칸을 누를 때마다 펼친 줄이 자리를 옮기던 것을 없앴다.
- 서버가 준 재료-레전드 연결값과 화면이 받은 값의 형(숫자/글자)이 달라 진행률이 0 으로 보일 수 있던 비교를 고쳤다.

**손대지 말 것**

- 편집 상태는 `useLegendCollections` 훅 하나가 두 탭에 공통으로 갖는다. 탭마다 따로 두면 탭을 바꿀 때 임시값이 갈라진다.
- 채움 버튼·뱃지 위 글자는 Figma 대로 `--color-bg-card` 를 쓴다. 두 테마에서 채움과 반대 밝기가 되어 대비가 맞는다 — 흰색 리터럴로 바꾸면 다크에서 옅은 보라 위 흰 글자가 된다.

**미결**

- "이번 주기 일정" 상단 고정이 실제로는 붙지 않는다. 전역 레이아웃(`MobileLayout` 본문 영역)이 높이 제한 없이 늘어나 문서 전체가 스크롤되기 때문으로, 레전드 재료 검색 화면의 필터 고정도 같은 이유로 안 붙는다. 전역 레이아웃 수정이 필요하다(이번 범위 밖).
- 편집 카드 안 3칸 버튼·액자/보유중 토글의 누르는 높이가 Figma 대로 24~32 로, 규칙의 44 보다 작다.
- 액자·보유중 뱃지는 Figma 대로 브랜드 보라를 쓴다. 공용 뱃지(분류 축 색) 규칙과 다르다 — 어느 쪽으로 맞출지 결정이 필요하다.
## 2026-09-29 — 레전드 재료 보유 현황 서버 기능 추가

- 버전: 1.0.0 (신규)
- 커밋: `c1d7b2c7`(sql) · `67f2afa1`(be) · `9d291bec`(web)

**고친 것**

- 화면이 통째로 없던 것을 새로 만들었다. `/legend-collections` 에서 "전체" 탭(검색·구단·타자/투수·액자 필터, 상태·보유 n/8 표, 행을 누르면 재료 2열 카드와 코치 2칸)과 "내 목표" 탭(접힌 주기 일정, 선호 순위 카드, 남은 재료)을 볼 수 있다.
- 편집 모드에서 재료를 없음·보유·삽입으로, 레전드를 액자·보유중으로 바꾸고 저장 버튼을 눌러야만 서버에 보낸다. 임시값은 탭 안에만 보관하고, 삽입 저장 확인·전체 초기화 확인·저장 안 하고 나가기·비로그인 안내·충돌(다른 기기 수정) 안내 팝업을 넣었다. 선호 레전드 고르기(미보유만, 최대 10, 순위, 액자 토글)는 가운데 모달이다.
- 라우트·상단바 제목·스토어 등록을 마쳐 빈 페이지가 뜨지 않고, 기존 "레전드 재료 검색" 화면에 이 화면으로 가는 링크를 달았다. 화면 빌드 통과.
- 서버 쪽이 통째로 없던 것을 새로 만들었다. 로그인한 이용자 본인의 레전드 상태(미보유·액자·보유중), 재료 칸 상태(보유·삽입), 선호 레전드 순위를 읽고 저장하는 주소 4개(`/api/legend-collections`, `/changes`, `/preferences`, `/schedule`)가 생겼다.
- 저장할 때 서버가 규칙을 다시 검사한다: 저장된 삽입은 되돌릴 수 없고, 보유중 레전드의 재료는 바꿀 수 없으며, 없는 레전드·재료 번호는 거절한다. 보유중으로 바뀐 레전드는 재료 8칸이 모두 지워지고 선호에서 자동으로 빠져 뒤 순위가 당겨진다. "전체 초기화" 대상 레전드는 삽입까지 지운다.
- 다른 기기에서 먼저 저장했으면 저장을 막고 충돌(409)로 알린다. 선호는 미보유 레전드만 최대 10명까지 담을 수 있다.
- 오늘 일차(2026-09-28 = 1일차, 한국 시간 자정 기준 14일 주기)와 선호 레전드의 미보유 재료가 히스토리 모드 어느 일차·라운드에서 나오는지 알려 주는 일정 조회를 만들었다. 코치 세트는 선수 이름이 없어 제외했다.
- 재료·레전드 마스터 테이블은 읽기만 하고 수정하지 않는다. 자동 테스트 8건 통과.
- 저장 테이블 3종을 만드는 DB 스크립트를 `sql/v.2.0.0/applied/legend_collection_tables.sql`(작성 당시 `sql/draft/legend-collections/`, 운영 반영 후 이동) 에 작성하고 `sql/v.2.0.0/01_site.sql` 에도 동기했다(이미 있으면 건너뛰는 방식, 탈퇴 시 연쇄 삭제, 재료 마스터에는 연결을 걸지 않음). 이 환경엔 DB 접속 정보가 없어 실제 반영과 저장·새로고침 복원 재검증은 못 했다 — 사용자가 스크립트를 실행한 뒤 확인이 필요하다.

- 재료 "보유" 상태 값을 화면(OWNED)과 서버(HAVE)가 다르게 쓰던 것을 화면 쪽을 HAVE 로 맞췄다. 이제 보유로 바꿔 저장해도 서버가 거절(400)하지 않고, 서버가 준 보유 재료가 카드·요약(보유 n/8)에 제대로 나온다.

**손대지 말 것**

- 재료 마스터를 지우고 다시 넣지 않는다. 이용자 기록이 재료 번호로 연결돼 있어 재적재하면 기록이 끊어진다.
- 탈퇴 처리 코드는 그대로 둔다. 기록은 사용자 테이블 삭제 시 함께 지워지도록 DB 연결(연쇄 삭제)에 맡긴다.

**미결**
