# error(화면 오류 처리) — 변경 이력

> 없는 주소로 들어갔을 때의 404 안내 화면과, 화면 렌더 중 예외가 나면 잡아서 "문제가 생겼습니다"로 바꿔치는 안전망(ErrorBoundary)을 다루는 기능. 화면 코드(`web/src/domains/error/**`) 자체는 이번 라운드에도 결함이 없어 한 줄도 고치지 않았다.

## 2026-09-28 — 없는 주소로 들어가면 404 대신 500이 떴음

- 버전: 1.0.1 (patch)
- 커밋: `8b697772`

**고친 것**

- 존재하지 않는 API 주소를 호출하면 "그런 주소 없음"(404)이 아니라 "서버 오류"(500)로 응답해, 이용자가 실제로는 멀쩡한 서버를 고장난 것으로 오인할 수 있었다.
- 서버 전역 오류 처리기의 마지막 그물(모든 예외를 500으로 받는 부분) 앞에 "주소 없음" 전용 처리를 추가해 404로 분리했다.
- 같은 커밋이 깨진 요청·허용 안 된 방식·업로드 용량 초과 등 다른 오류 응답도 함께 정리했지만, 그 부분은 화면 오류 처리(error) 기능이 아니라 서버 공통 코드 영역이라 이 문서에서는 세지 않는다.

**손대지 말 것**

- `ErrorBoundary`가 상단바·드로어·Footer는 감싸지 않고 본문 영역만 감싸는 것 — 의도된 설계다. 전체를 감싸면 예외가 나도 새로고침 버튼까지 함께 사라질 수 있다.
- 404 화면의 이동 링크가 일반 페이지 이동(`<a href>`)인 것 — 라우터 자체가 깨진 상황을 가정한 의도된 방어다.
- 오류 화면에 원인 문구(스택트레이스)를 노출하지 않는 것 — 상세는 콘솔 로그로만 남기고 화면엔 고정 안내만 보여준다.
- 404·오류 화면에 광고가 없는 것 — "로그인·콜백·오류 화면에 광고 금지" 규칙과 일치하는 의도된 설계다.

**미결**

- 없음 — 이번 라운드에서 유일한 미결이었던 이 항목이 해결됐다.
