# gamification 변경 이력

## 2026-10-08 — 마이페이지 활동 화면 개편 (화면 쪽, 2차)

- 버전: 1.1.0 (minor, 서버 쪽 조회 API 와 같은 릴리스)
- 커밋: e03c7bc5

**고친 것**

- 마이페이지: 등급 카드(탭 불가)와 이동 행 3개(등급표 보기 · 대표 칭호 바꾸기 · XP·포인트 내역)로 교체. 옛 요약 카드는 삭제.
- 등급표 모달: 10단계 목록, 열면 내 등급 위치로 스크롤, 끝에 XP 얻는 법·전체 안내 링크.
- 칭호 등록 모달: 보유 칭호 라디오, 현재 대표와 같으면 [등록] 비활성, 대표 해제 링크, 못 받은 칭호는 자물쇠와 조건 문구, 실패 시 안내 문구.
- 활동 내역 `/mypage/history`: XP·포인트 탭, 20건씩 [더 보기].
- 서랍 프로필·마이페이지 닉네임 옆에 등급·대표 칭호 칩(칭호 없어도 같은 높이). 출석 토스트 3초(등급이 오르면 변형 문구).
- 서랍 카드 Figma 대로 정정: 세로 배치(아바타 56 + 티어 링 · 닉네임 · 등급 · 대표 칭호 칩), 다음 등급까지 XP 줄과 XP 바 추가, 이메일·› 제거.
- 관리자 이용자 탭: 유저 상세 모달에 "칭호" 섹션(보유 칩·운영자 지급 칭호 지급/회수·확인 창), 탭 상단에 "얼리어답터 일괄 지급" 패널(대상 확인 후에만 지급 버튼).
- 가이드 `gamification` 추가(목록에는 안 보이고 링크로만). 등급 색 토큰 `--color-tier-*` 와 직접 그린 야구공·자물쇠 SVG 추가. 여전히 관리자만 노출.

**손대지 말 것**

- `ponytail: 시범 운영` 관리자 한정 조건(MyPageScreen · AuthProvider · Drawer). 전체 공개 시 함께 제거.
- 기존 색 토큰 값은 바꾸지 않았다(추가만).

**미결**

- `npm run build` 의 사전 렌더 단계는 개발 서버(포트 3000)가 떠 있어 실행 못 함 — `vite build` 까지만 통과 확인.
- 화면 육안 확인(두 테마 · 320px)과 등급 모달 미래 등급 공의 다크 탁함은 미확인.
- 마이페이지 프로필 카드는 티어 카드 전체가 아니라 칩 줄만 공유한다.

## 2026-10-08 — 조회 API 3개 추가, 출석 응답에 등급 정보 (서버 쪽, 2차)

- 버전: 1.1.0 (minor, 2차 화면과 같은 릴리스)
- 커밋: f9eedea3, c20ecab0

**고친 것**

- 운영자 칭호 지급 버그 2건: 회수 뒤 재지급하면 보너스가 안 들어가던 것(원장 키 중복)을 관리자 지급 경로만 호출마다 새 키로 바꿔 고쳤고, 중복 지급 방지는 칭호 보유 여부로 판정한다(자동 지급은 기존 키 유지). 지급·회수 원장 사유에 "by 관리자 publicId" 를 남긴다(로그인 정보에서 취득). 재지급 원장 합계 테스트 추가.
- 운영자 칭호 지급·회수(`/api/admin/gamification`): 유저 칭호 목록 `GET /users/{publicId}/titles`, 지급 `POST /titles/grant`, 회수 `POST /titles/revoke`. 수동(MANUAL) 칭호만 가능(아니면 400), 이미 보유면 지급 무시(멱등), 회수는 칭호 삭제+보너스 음수 원장. GM 은 대상이 관리자일 때만(아니면 403). 시범 운영 중 관리자 계정이 아닌 대상은 400(칭호·포인트 불일치 방지, 가드는 한 곳). 서비스 테스트 7건 추가.
- 칭호 전체 목록(`GET /api/gamification/titles`): 잠긴 칭호 포함, 보유·대표 여부와 얻는 조건 문구를 함께 준다.
- 등급 10단계 목록(`GET /api/gamification/levels`).
- 내 XP·포인트 내역(`GET /api/gamification/me/history?type=XP|POINT&page=0`): 20건씩, 다음 페이지가 있으면 `hasNext`. type 이 잘못되거나 page 가 음수면 400.
- 출석 응답에 `level`, `levelName`, `leveledUp` 추가(기존 `xp`, `point` 유지). 오늘 이미 받았으면 레벨업 아님.
- 칭호 4종(얼리어답터·개근상·철인·버그 헌터)+운영자 전용 GM 으로 축소. 얼리어답터 가입 기간·보너스는 DB 값을 읽는다(코드 상수 제거). 일괄 지급 응답에서 springCampCount 삭제(화면 쓰는 곳 없음). 정의 없는 칭호 코드는 예외 대신 건너뜀+경고 로그. 정의 없는 수동 칭호 조건 문구는 "운영자가 지급".
- 서비스 단위 테스트 5건 추가(내역 20/21건 경계·잘못된 입력·레벨업 판정).

**손대지 말 것**

- 칭호 조건 문구는 서비스 안 표다. 컬럼을 늘리지 않았다(DDL 없음). 칭호를 추가하면 표에도 한 줄 추가.
- 시범 운영 가드(관리자만 적립)는 그대로. 조회 API 는 본인 기록만 읽는다.

**미결**

- 내역 조회는 기존 인덱스로 충분한 시범 규모다. 사용자 수천 명·내역 수만 행이 되면 인덱스 추가(DDL, 승인 필요).

## 2026-10-08 — 등급·포인트·칭호 서버 (원장 적립, 체크인, 저장 XP, 얼리어답터 지급)

- 버전: 1.0.0 (minor, 화면 쪽 항목과 같은 첫 릴리스)
- 커밋: 92d16fde, f9eedea3, c20ecab0

**고친 것**

- 하루 첫 방문 체크인(10XP·100P, 한국 시간 자정 기준 1회), 7일 연속마다 100P, 개근상·철인 칭호를 자동 지급한다.
- 컬렉션 변경 저장·레전드 스킬 저장 시 2XP(하루 5회까지), 첫 저장 20XP, 누적 50·200·500회 칭호를 저장이 끝난 뒤에 지급한다. 지급이 실패해도 저장 결과는 그대로다.
- 모든 증감은 원장에 한 줄씩 쌓이고 같은 보상은 두 번 들어가지 않는다. 등급이 오르면 보너스 포인트가 한 번씩 붙는다.
- 마이페이지용 조회(등급·포인트·칭호·최근 20건)와 대표 칭호 장착/해제 API를 만들었다.
- 운영자용: 얼리어답터 일괄 지급(기본은 시험 실행, 대상 수와 샘플만 표시), 지급/회수, 유저 원장 조회.
- 테이블 6개와 초기 설정값은 `sql/draft/gamification/` 초안으로만 두었다. 아직 DB에 적용하지 않았다.

**손대지 말 것**

- 테이블 생성은 운영 DB와 같은 인스턴스라 사용자 재승인 뒤에만 실행한다. 적용 전에는 새 API가 오류를 낸다.
- 얼리어답터 일괄 지급은 실제 실행(dryRun=false)하지 않았다. 시험 실행 건수를 실측 63명(창단 27, 스프링캠프 36)과 대조한 뒤에만 실행한다.
- 저장 이벤트는 커밋 이후 별도 처리다. 저장 서비스에서 보상 로직을 직접 부르지 않는다.

**미결**

- 저장 XP 하루 횟수(5)와 개막전 마감일(없음)은 설정 표 값이라 배포 없이 바꿀 수 있다. 설정 변경은 캐시 없이 바로 반영된다.
- 버그 헌터 칭호를 운영자가 주는 전용 API는 없다. 현재는 지급/회수(adjust)로 포인트만 가능하다.
- 서버 확인 필요: 실제 DB 적용 후 체크인·저장·일괄 지급 시험 실행 실측.

## 2026-10-08 — 마이페이지에 등급·포인트·칭호 표시, 로그인 시 출석 체크인 (화면 쪽)

- 버전: 1.0.0 (minor)
- 커밋: e03c7bc5

**고친 것**

- 마이페이지 프로필 카드 아래에 등급 칩·경험치 진행바·포인트·칭호 칩(눌러 장착/해제)·최근 활동 20건을 보여준다.
- 로그인 확인이 끝나면 출석 체크인을 자동으로 한 번 요청한다. 실패해도 로그인에는 영향이 없다.
- 로딩·오류·"아직 활동 기록이 없어요" 빈 상태를 모두 처리했다. 칭호 장착 실패는 칩 아래 안내 문구로 보인다.

**손대지 말 것**

- 서버가 응답 필드를 `titles[{code,name}]`, `recent[{reason,xpDelta,pointDelta,rewardDate}]` 로 준다고 가정했다. 서버와 이름이 다르면 화면이 비어 보인다.
- 체크인은 서버가 하루 1회로 막으므로 화면에서 중복 호출을 따로 막지 않는다.

**미결**

- 서버 응답 필드명 실측 대조(통합 단계).
