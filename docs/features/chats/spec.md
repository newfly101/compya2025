# chats (펀톡 — 플로팅 단체 채팅, compyafun + talk)

## 1. 무엇을 하는 기능인가

사이트 우측 하단의 둥근 버튼을 누르면 채팅 패널이 열리고, 접속한 모든 팬이 하나의 방(lobby)에서 함께 이야기한다. 1:1 대화는 없다. 누구나 읽을 수 있고, 네이버 로그인을 한 사람만 글을 보낼 수 있다. 대화는 서버의 메모리 저장소(Valkey, Redis 와 같은 방식)에 최근 100개만 잠시 보관하며, 데이터베이스(MariaDB)에는 남기지 않는다. 이후 `@봇` 으로 AI 봇이 같은 방에서 답하는 기능을 붙일 예정이며, 이번 범위에서는 메시지 구조만 대비한다.

## 2. 화면과 진입 경로

모바일 우선. 화면 ID(SC)는 구현 단계에서 `overview/domain.md` 에 채번한다.

| 화면 | 주소 | 어디서 들어오나 |
|---|---|---|
| 플로팅 버튼 | 주소 없음 (모든 공개 화면 우측 하단에 겹침) | 사이트 어디서나. 안 읽은 새 글이 있으면 점 표시 |
| 채팅 패널 (로그인 상태) | 주소 없음 (버튼 위로 열리는 패널, 모바일은 화면 하단에서 올라오는 시트) | 플로팅 버튼 누름. 입력창 + 전송 버튼 |
| 비로그인 상태 | 패널 안 | 읽기만 가능. 입력창 자리에 "로그인하고 대화에 참여하기" 안내와 로그인 버튼 |
| 연결 끊김 상태 | 패널 안 | 상단에 "연결이 끊겼어요. 다시 연결 중…" 띠. 입력창은 잠기고 마지막으로 받은 내용은 그대로 보임 |
| 빈 상태 | 패널 안 | 보관 중인 글이 0개일 때 "아직 대화가 없어요. 첫 인사를 남겨보세요" |

## 4. 데이터

| 무엇 | 저장소 · API | 비고 |
|---|---|---|
| 방 내역 | Valkey LIST `{env}:chat:lobby` (최근 100, LTRIM) | `{env}` = `dev` 또는 `prod`. TTL 없음, 100개 상한이 용량을 제한 |
| 새 글 전달 | Valkey Pub/Sub 채널 `{env}:chat:lobby` | 서버 간 전파 후 각 서버가 WebSocket 으로 전달 |
| 최근 내역 조회 | `GET /api/chats/messages` | 인증 불필요, 최대 100개 |
| 실시간 연결 | WebSocket `/ws` (STOMP) — 구독 `/topic/chat.lobby`, 전송 `/app/chat.send` | 구독은 누구나, 전송은 로그인 필요 |
| 관리자 삭제 | `DELETE /api/admin/chats/messages/{messageId}` | ADMIN. 글에 id 부여 필요 |
| 이름 | FE `web/src/domains/chats` · BE `domain/chat` · API `/api/chats` | 복수 규칙 그대로 (결정 2026-10-08) |
| 의존(ops) | 운영 nginx `/ws` 의 WebSocket Upgrade 설정 | ops 트랙. 없으면 운영에서 연결 불가 |
| 의존(기능) | 기존 네이버 OAuth 로그인 · 사용자 닉네임 | |

## 5. 하지 않는 것

- 1:1 대화·방 여러 개 — 단일 방으로 시작해 운영 부담을 줄인다.
- DB·디스크 영구 저장, 검색, 지난 대화 더보기 — 휘발이 의도다.
- AI 봇(`@봇` → Ollama) — 별도 기획. 이번엔 메시지 구조의 `bot` 종류만 열어 둔다.
- 신고 기능 — 이번 범위 밖 제안. 관리자 삭제로 먼저 대응한다.
- 사용자 채팅 금지(제재) 구현 — 권한·개인정보 판단(§6 🔴) 후 별도 작업.
- 이미지·이모티콘 첨부, 멘션 알림, 읽음 표시, 입력 중 표시 — 필요가 확인되지 않았다.
- 푸시 알림 — 패널이 닫혀 있을 땐 버튼의 새 글 점 표시까지만.
