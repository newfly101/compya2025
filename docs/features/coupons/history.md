## 2026-09-28 — 등록·수정 시각 컬럼을 서버 시간대에 안 흔들리는 형식으로 바꿈

- 버전: 유지 (ops — 스키마 타입만, 동작 불변)
- 커밋: 미커밋 (SQL 은 사용자가 직접 실행)

**고친 것**

- `site_coupons` 의 `created_at`·`updated_at` 을 TIMESTAMP 에서 DATETIME 으로 바꿨다. TIMESTAMP 는 서버 세션 시간대에 따라 값이 달리 읽히는데, DATETIME 은 저장한 벽시계 그대로라 서버 이전·설정 변경에도 시각이 밀리지 않는다. `expire_at` 은 원래 DATETIME 이라 이제 세 컬럼이 같은 방식이다. [ADR 0007](../../decisions/0007-kst-timezone.md) 3단계.

**손대지 말 것**

- 변환은 세션 시간대 `+09:00` 을 먼저 맞춘 상태에서 실행했다 — 그래야 기존 값이 KST 벽시계 그대로 보존된다. 같은 작업을 다시 할 일이 있으면 순서를 지킨다(`applied/kst_timestamp_to_datetime.sql` 주석).

**미결**

- 서버 전역 타임존·`my.cnf`·앱 설정 배포는 아직 — `sql/draft/kst-timezone/README.txt`

## 2026-09-28 — 일괄 처리 부분 실패, 삭제 문구, 렌더 오류 등 6건 일괄 수정

- 버전: 1.0.1 (patch)
- 커밋: `7c1e67b5`

**고친 것**

- 쿠폰 여러 개를 골라 한 번에 삭제·노출변경하면 일부만 처리돼도 화면은 "전부 처리됐다"고 보여줬다. 서버가 이미 구분해서 내려주는 성공/실패 목록을 화면이 반영하도록 고쳐, 실패한 건은 목록에 남고 "N건 처리 실패" 배너가 뜨게 했다.
- DB 제약 위반이면 원인과 무관하게 항상 "쿠폰 코드가 중복됩니다"라고 떴다. 진짜 코드 중복일 때만 그 문구가 뜨고, 글자 수 초과 등 다른 원인은 그에 맞는 오류가 뜨도록 좁혔다.
- "삭제" 확인창이 "되돌릴 수 없다"고 경고했지만 실제로는 화면에서 숨기는 것뿐이었다. 문구를 "숨김"으로 정정하고, 숨긴 코드를 재등록하면 왜 막히는지 안내를 추가했다.
- 관리자·공개 화면의 만료 판정 기준이 날짜 단위/분 단위로 서로 달라, 같은 쿠폰이 화면마다 다르게 보일 수 있었다. 더 정밀한 분 단위 기준으로 통일했다.
- 상세 설명(detail)이 없는 쿠폰 카드를 그리면 화면이 오류를 일으킬 수 있어 방어 코드를 추가했다.
- 관리자용과 공개용 쿠폰 데이터가 프런트 상태 저장소의 같은 자리를 공유하고 있어, 실수로 섞일 위험이 있었다 — 별도 자리로 분리했다.

**손대지 말 것**

- `@PreAuthorize("hasRole('ADMIN')")`가 URL 규칙과 함께 이중으로 걸려 있는 것 — 정상이다. 하나만 남기면 오히려 방어가 줄어든다.
- 만료 시각의 응답 형식(`yyyy-MM-dd HH:mm`)을 바꾸지 말 것 — 화면의 문자열 비교 로직이 이 형식에 맞춰져 있다.
- 저장 완료 뒤 캐시를 비우는 처리(`CacheEvictAfterCommitAspect`) — 정상 동작이며 캐시 키가 실제 사용 중인 키와 일치한다.
- `dateUtils.expired`는 어디서도 쓰이지 않는 죽은 코드로 확인됐지만, 이번 라운드에서는 삭제하지 않고 삭제 후보로만 남겨뒀다.

이 기능은 검증 API 자체(서버가 입력값을 실제로 걸러내는 기능)와 응답 규약(공개/관리자 요청 함수가 응답을 꺼내는 방식) 통일도 함께 적용받았다 — 두 항목 모두 이 기능 하나만의 문제가 아니라 전 기능 공통 문제라 전역 커밋(`46ef6cb8`, `8369971a`)으로 해소됐다. 이 문서에서는 중복 기록하지 않는다.

**미결**

- 없음
