# players

## 1. 무엇을 하는 기능인가

컴투스 프로야구의 모든 선수 카드(11,668건)를 구단·연도·포지션·카드종류로 찾아보는 조회 전용 백과사전이다. 등록·수정·삭제 기능은 없고 카드형(그리드)·리스트형(표) 두 방식으로 볼 수 있다. 레전드 카드 재료인 카드는 배지로 표시된다.

## 2. 화면과 진입 경로

| 화면 | 주소 | 어디서 들어오나 |
|---|---|---|

## 4. 데이터

| 무엇 | 테이블 · API | 비고 |
|---|---|---|
| 카드 원형 | `data_player_card` · `GET /api/player-cards` | 11,668건, NORMAL만 적재. UNIQUE(구단,연도,포지션,선수명,카드종류). `cardId`는 응답에 안 넣음(용량 절감) |
| 태생 스탯 | `data_player_card_stat` · `GET /api/player-cards/{teamCode}/stats` | 구단 1개(전 연도) 단위 조회. OVR은 응답에 없고 FE가 5스탯 평균으로 직접 계산(DB STORED 컬럼과 같은 식) |
| 투수 보유 구종 | `data_player_card_pitch` (위 API에 포함) | 보유 구종만 행 생성, 미보유는 행 없음 |
| 구종 마스터 | `data_pitch_type` | `legendStats` 도메인과 공유하는 10종 마스터. players 자체 구종 마스터 API는 없음 |
| 레전드 재료 여부 | `data_player_legend_material` (LEFT JOIN) | "L"/"LN" 배지 출처. players는 표시만 하고 CRUD는 `legendStats` 도메인 소유 |
| 선수명 오기 정정 대상 | 시드 SQL 21건(하동현 8·정세현 6·김우찬 3·이도율 2·신건우 1·화이즈S 1) | 엑셀(정본)-DB 이름 대조 결과 확정된 오기 목록. 운영 DB 반영 여부는 §6 참조 |
| 캐시 | `@Cacheable`(`playerCard`/`playerCardStat`) + ETag + `Cache-Control: max-age=1h` | TTL 0. 무효화는 admin 캐시 동기화 버튼(수동)뿐 |

## 5. 하지 않는 것

- 등록·수정·삭제 API가 없다 — 데이터는 운영자가 DB에 직접 입력하거나 시드 SQL 재실행으로만 바뀐다.
- 코치(C) 탭은 서버가 코치 역할 데이터를 주지 않아 항상 카운트 0으로 비활성이다.
- 부포지션을 담을 별도 컬럼이 없다 — 저장 방식은 아직 결정되지 않았다(§6).

## 6. 확인 필요

🟨 가정 — 카드 종류 확장분(국가대표·골든글러브 등 6종)의 데이터 적재 시점은 미정이며, 적재 전까지 필터는 비활성 상태를 유지한다.

확정(2026-09-30) — `has_signature=1` 건수는 시드 스냅샷 5,129건(전체 11,668건 중 44%, 2026-09-27 실측)으로 충분하다. 추가 확인이 필요 없다.

확정(2026-09-30) — 선수명 오기 21건(엑셀-DB 대조 결과)은 운영 DB에 전부 반영됐다. 시드 문제 없음.

확정(2026-09-30) — 주포지션이 엑셀과 어긋난 3건(MBC 1983 송영운·신언호 맞바뀜, NC 2021 김다율)도 운영 DB에 정정 반영됐다.

❓ 미정 — 부포지션 저장 방식(카드에 부포지션 칸 추가 A안 권고 / 별도 표 B안 / 슬래시 결합 C안) — A안이 권고되었으나 아직 만들지 않았다.
