# home — 변경 이력

## 2026-10-02 — 바로가기 편집 · 오늘 히스토리 · 내 컬렉션 · 비로그인 유도 카드

- 버전: 1.1.0 (minor)
- 커밋: 41b42cbf

**고친 것**

- 로그인하면 홈 바로가기를 서랍 메뉴 전체에서 최대 8개 골라 끌어서 순서를 바꿀 수 있다. 저장은 이 브라우저에만 된다(REQ-HM-14).
- 홈에 선호 레전드의 "오늘 히스토리" 카드와 "내 컬렉션" 요약 카드(보유·액자·스킬 수)가 생겼다. 비로그인은 같은 자리에 로그인 유도 카드를 본다(REQ-HM-11~13).
- 홈 섹션 순서를 히어로 → 바로가기 → 공지 → 오늘 히스토리 → 내 컬렉션 → 기존 섹션으로 바꿨다. 서랍 "레전드 재료" 아래에 하위 메뉴 3개가 붙었다(REQ-HM-15).
- `QUICK_MENUS.js` 를 지우고 `quickShortcuts.js` 로 대체.
- 홈에 "이번 주기 일정" 섹션을 더한다(오늘 히스토리 아래, 내 컬렉션 위. 로그인 + 선호 있을 때만, 실패 시 숨김, REQ-HM-16). 요구에 있었으나 앞선 정리에서 빠졌던 것을 보완했다.
- 보유 현황에서 "이번 주기 일정" 카드를 빼서 일정은 홈 섹션(로그인)으로만 본다(콘텐츠 영역 분리). 홈 오늘 히스토리 카드의 링크는 "내 선호 보기 →" `/legend-collections?tab=mine`(REQ-HM-16, `legendCollections` REQ-LCOL-20).

**손대지 말 것**

- 비로그인·로그아웃 상태는 항상 기본 구성이다. 저장값에 없는 항목 키는 무시한다.
- 바로가기 순서 변경은 드래그만 두고 화살표 버튼은 두지 않는다(Figma 05).

**미결**

- 키보드로 순서를 옮기는 방식(항목 포커스 후 방향키)은 가정(🟨) 상태.
- 바로가기 서버 저장, 클릭 집계는 이번에 하지 않았다.

## 2026-09-28 — 홈 첫 렌더 요청 4회 → 1회 통합 + 오류 표시·고정 공지·스켈레톤 문제 해소

- 버전: 1.0.1 (patch)
- 커밋: `3bf7ba69`

**고친 것**

- 홈에 들어올 때마다 쿠폰·이벤트·공지·퀴즈를 각각 따로 호출하던 것을 `GET /api/home` 요청 1번으로 묶었다. 기존 4개 API·화면은 다른 곳에서 그대로 쓰이므로 없애지 않고, 그 위에 조합 계층만 얹었다. 한 섹션이 실패해도 나머지는 정상 표시되는 구조는 그대로 유지.
- 요청이 실패해도 옛 데이터가 남아 있으면 오류 표시 자체가 없었다 — 쿠폰·이벤트 섹션에 오류 표시를 새로 추가하고, 퀴즈 섹션은 값이 남아 있어도 오류가 보이도록 조건을 고쳤다.
- 관리자가 공지를 상단 고정해도 홈 미리보기 3건에는 반영 안 될 수 있었다 — 공지 목록 화면의 정렬 로직은 그대로 두고, 홈 미리보기에서만 고정 공지를 우선 노출하도록 고쳤다(공지 목록 화면에 영향 없음).
- 홈에 재방문할 때마다 로딩 표시(스켈레톤)가 다시 깜빡였다 — "이미 불러왔는지" 상태를 쿠폰·이벤트 저장소에도 추가해 첫 로딩에만 스켈레톤이 뜨게 했다.

**손대지 말 것**

- 이벤트 목록에서 화면(FE) 쪽 정렬이 서버 정렬 결과를 다시 정렬하는 것 — 결함이 아니라 프로젝트 컨벤션이다. 정렬의 주인은 화면 쪽이고 서버 정렬은 안전망이다.
- 홈이 마운트될 때마다 캐시 확인 없이 다시 요청을 보내는 것 — 성능 개선 여지는 있지만 순서 문제는 없어 이번 라운드에서는 결함으로 다루지 않았다.

**미결**

- 홈의 유일한 광고가 쿠폰 목록이 1건이라도 있어야 뜨는 구조라, 쿠폰이 0건이 되면 광고가 조용히 사라지고 데이터 도착 순서에 따라 레이아웃이 밀리기도 한다 — 다음 라운드 처리 대상.
- 홈 미리보기 건수 제한이 공지에만 걸려 있다(공지는 3건만, 쿠폰·이벤트는 전체 노출) — "전부 노출"이 확정된 방향인데 코드는 공지만 다르게 자르고 있어 기획 쪽 결정이 필요하다. 이 문서에서는 어느 쪽이 맞는지 판단하지 않는다.
