# mileage — 변경 이력

## 2026-09-28 — 조회 전용 서비스 주석이 실제 동작과 달라 정정

- 버전: 유지 (주석만, 1.0.1 기준)
- 커밋: `d4dd5511` (mileage·legendStats·playerSkills·players 4개 도메인을 한 커밋에서 함께 정정. mileage 변경 파일은 `MileageServiceImpl.java` 1개)

**고친 것**

- "운영자가 DB를 직접 고치면 서버를 재시작해야 반영된다"던 클래스 주석이 거짓이었다. 실제로는 관리자 화면의 캐시 동기화 버튼을 누르면 `mileageSniperTarget` 캐시를 비우고 다시 채운다. 이 거짓 주석을 근거로 과거 리뷰 문서가 "캐시 무효화 경로 없음"이라는 틀린 결론을 낸 적이 있어, 주석을 실제 동작으로 정정했다.

**손대지 말 것**

- 캐시 동기화는 자동이 아니라 관리자가 버튼을 직접 눌러야 하는 수동 갱신이다. 만료 시간(TTL)이 없어 그 버튼이 유일한 갱신 수단이라는 점도 그대로 유지.

**미결**

- 없음.

## 2026-09-28 — 저격 대상 목록 동시 마운트 시 중복 조회 방지

- 버전: 1.0.1 (patch)
- 커밋: `873c4236`

**고친 것**

- 레전드 평점표(마일리지 배지 포함)와 마일리지 목록 탭이 같은 순간에 함께 열리면 저격 대상 목록 조회(GET)가 두 번 나갈 수 있던 문제를 고쳤다. `store/public/thunks.js`의 중복 요청 방지 조건이 "이미 불러왔는지"(`!loaded`)만 검사하고 "지금 불러오는 중인지"(`!loading`)는 검사하지 않아서 생긴 문제였다. legendStats가 이미 쓰던 `!loaded && !loading` 검증 패턴을 그대로 가져와 적용했다.

**손대지 말 것**

- DP(동적 계획법) 알고리즘 `solve`/`ePick`/`weightsFor`는 코드 최상단에 "그대로 옮겼다 — 최적화·리팩터 금지"가 명시돼 있다. 실행 검증으로 수식 오류 없음도 확인됨 — 건드리지 말 것.
- `ePick`/`weightsFor`의 `N=0` 방어 코드 미적용은 의도적으로 그대로 뒀다 — 실데이터 기준(연도당 최소 6구단, 구단당 최소 3연도)으로는 후보 수 0 자체가 발생하지 않는 것을 실행으로 확인했고, 금지 대상 함수를 굳이 건드릴 이유가 없었다.
- 동명이인 선수명은 `data_player_card.player_name`이 접미사(예: "김성한B")로 이미 구분해 저장하므로 유일성 판정에 오판 위험이 없다.

**미결**

- 카드 하나가 주포지션·부포지션 모두에서 유일한 경우가 실제로 있는지 FE 주석과 BE DTO 주석이 서로 다른 값을 말하고 있다(FE: 0건, BE: 있음) — DB 접속 금지로 재확인 못 함. 만약 실제로 있다면 화면이 항상 주포지션 하나로만 좁혀 부포지션 저격 가능성을 안내하지 않는 상태다. DB 접속 가능한 세션에서 실측 후 필요 시 기획 결정.
- `loaded` 재요청 차단을 매 진입 재조회로 바꿀지는 성능 트레이드오프라 도메인별 판단 필요.
- 캐시 만료 시간(TTL) 없음 — 운영 설정(`spring.cache.type`) 변경은 별도 승인 사안.
