## 2026-09-28 — 운영 화면 전용 상태 표시 컴포넌트 통합

- 버전: 유지 (refactor, 1.0.4 기준)
- 커밋: `a3612fc5` (여러 도메인 화면 공통 커밋, 이 문서는 운영 전용 상태 컴포넌트 삭제 부분만)

**고친 것**

- 운영 화면 전용 상태 표시 컴포넌트(`AdminStateBox`)와 공개 화면용(`StateBox`) 두 벌이 있었다 — 스타일시트를 줄 단위로 대조한 결과 실질 차이가 기본 문구 하나뿐이라 운영 전용 컴포넌트를 지우고 공용 `StateBox` 하나로 합쳤다. 운영 화면 7곳(캐시 동기화·쿠폰·이벤트·공지 2곳·퀴즈·회원)은 호출 쪽에서 기존 문구를 그대로 넘겨 화면 글자는 바뀌지 않았다.

## 2026-09-28 — 운영 홈 배지가 실제 회원 수보다 훨씬 적게 표시됨

- 버전: 1.0.4 (patch)
- 커밋: `eb84accc`

**고친 것**

- 운영 홈의 회원·이벤트 배지가 "전체 건수"가 아니라 "방금 불러온 20건"만 세고 있었다. 실제 회원이 545명이어도 배지는 20으로 고정.
- 회원·이벤트 목록을 최대 1000건까지 한 번에 받아와 정확히 세도록 고침. 1000건을 넘으면 틀린 숫자 대신 배지를 숨긴다.

**미결**

- 회원 545명 기준으로는 1000건 상한으로 충분하지만, 그 이상 늘어나면 총 건수를 알려주는 별도 API가 필요하다 (코드에 한계 주석으로 남김).
- 삭제한 태그 코드를 재등록하면 500 오류가 남. 실제 코드는 `community`(동결된 기능) 쪽에 있고 DB 제약 재설계가 필요해 결정 대기.
- 로컬 개발 환경 설정 파일(`application-local.properties`) 공급 방식 미정 — 코드 문제가 아니라 운영 방식 결정 사안.
- 캐시가 만료 시간 없이 계속 남는 문제(`spring.cache.type` 설정)는 운영 설정 변경 승인 대기.

## 2026-09-28 — 운영 화면 상단에 로그아웃 버튼이 두 개 떠 있었음

- 버전: 1.0.3 (patch)
- 커밋: `9ce6cf2a`

**고친 것**

- 관리자 셸 화면이 자체 로그아웃 버튼을 직접 그리고 있어서, 전역 상단바가 붙이는 버튼과 나란히 두 개가 보였다.
- 셸의 자체 버튼을 없애고 전역 상단바(`TopBar`) 버튼 하나만 남김. 로그아웃 문구도 화면마다 다르던 것을 "로그아웃" 글자로 통일했다.

**손대지 말 것**

- 도메인 화면은 자체 헤더를 만들지 않고 전역 `MobileLayout` 의 `TopBar` 하나로 통일한다는 프로젝트 규칙 — 이번 수정이 그 규칙을 지킨 사례다.

## 2026-09-28 — 공지 새로고침이 필요 이상으로 캐시를 비움

- 버전: 1.0.2 (patch)
- 커밋: `906c98e5`

**고친 것**

- 운영자가 "공지 새로고침"을 누르면 관련 캐시(임시 저장된 조회 결과) 전체를 비웠는데, 실제로 쓰는 키는 하나뿐이었다. 앞으로 키가 늘어나면 의도치 않게 함께 비워질 위험이 있어 범위를 그 키 하나로 좁혔다.

**손대지 말 것**

- 새로고침 버튼이 공지 캐시와 공지 상세 캐시를 함께 비우는 것은 버그가 아니라 의도된 설계다 — 운영자가 DB를 직접 고친 뒤 즉시 반영하기 위한 버튼이고, 쿠폰 기능의 새로고침도 같은 방식이다.
