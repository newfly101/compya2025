## 2026-09-28 — 요일 정렬 오류·정렬 화살표 방향 반대 등 4건

- 버전: 1.0.1 (patch, quiz 기능과 같은 커밋)
- 커밋: `a47859ac`

**고친 것**

- 표의 "요일" 열로 정렬하면 일요일이 항상 월요일보다 앞에 놓였다 — 화면과 서버의 요일 계산 기준이 서로 달랐던 것을 서버 기준(월~일)에 맞춰 고쳤다.
- 레전드 메타 정보(구단·타입·포지션 필터에 쓰이는 정보)를 못 불러오면 필터가 안내 없이 조용히 멈췄다 — 실패를 별도로 구분해 안내와 재시도 버튼을 보여주게 했다.
- 표 아래 "재료 N장" 문구가 표에 실제 보이는 재료 수와 다른 기준(등장 위치 수)으로 세고 있었다 — 표와 같은 기준(카드 단위)으로 통일했다.
- 정렬 화살표(▲▼)가 열마다 반대 뜻으로 쓰였다 — 모든 열이 같은 기준으로 방향을 표시하는 공용 함수로 통일했다. 실제 정렬 결과 자체는 원래도 정상이었다.

**미결**

- 캐시 만료 시간이 아예 없는 문제 — 운영 캐시 설정 변경이 필요해 운영 설정 승인 대기.
- 레전드 재료 표의 포지션 코드(`position_code`) 노출 여부 — 대상 데이터 중 0.86%가 값이 비어 있어, 어떻게 표시할지는 기획 결정이 필요하다. `legendStats` 기능의 다른 테이블과 혼동하지 않도록 주의.
- 재료 데이터 유일성 검증은 별도 미결이 아니라 운영 규칙으로 처리하기로 했다 — SQL로 재료 데이터를 직접 적재·수정한 뒤에는 정해진 검증 쿼리를 돌려 확인한다(코드 변경 없음).

**손대지 말 것**

- 약한 캐시 식별자(`W/` ETag)를 쓰는 것 — 서버가 압축을 함께 제공하기 위한 의도된 선택이다. 강한 식별자로 바꾸면 이 API만 압축이 빠진다.
- `position`/`ROSTER_GROUP_LABEL` 필드를 안 쓰는 것 — 버그가 아니라 기획 보류 상태다.
