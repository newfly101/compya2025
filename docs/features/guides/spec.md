# 가이드

## 1. 무엇을 하는 기능인가

컴프야펀이 직접 정리한 공략·활용 가이드 12편이다. 게임사 공지를 옮긴 글이 아니라 사이트 안 데이터를 바탕으로 재구성한 콘텐츠이며, DB나 API 없이 빌드 시점에 고정된 로컬 데이터로만 존재한다.

## 2. 화면과 진입 경로

| 화면 | 주소 | 어디서 들어오나 |
|---|---|---|
| SC-18-01 가이드 목록 | `/guides` | 홈 메뉴·서랍 |
| SC-18-02 가이드 상세 | `/guides/:slug` | 목록 클릭, 각 도메인 화면의 접힌 가이드에서 "더 보기" |
| SC-18-02 내부 삽입 | 도메인 화면 상단(라우트 없음, `GuideAccordion` 컴포넌트) | 9개 도메인 화면(마일리지·확률 공시·선수 백과사전·레전드 재료·히스토리 재료·스킬 백과사전·공지·이벤트·쿠폰) 방문 시 자동 노출 |

| REQ-GD-01 | 목록·상세 조회 | 비로그인 사용자가 12편을 목록/상세로 조회할 수 있다 | `content/index.js` |
| REQ-GD-02 | 도메인 접힌 가이드 | 9개 도메인 화면 상단에 관련 가이드를 접힌 형태로 노출한다 | `GuideAccordion` |
| REQ-GD-03 | 안내 문구와 실제 정책 일치 | 확률 공시 가이드의 로그인 안내 문구는 실제 `/probability` 정책(비로그인 공개)과 일치해야 한다 — 두 차례 수정(홈 가이드·확률 공시 가이드)으로 "로그인 필요" 문구를 "바로 이동"으로 정정했다 | `docs/features/guides/history.md` 2026-09-28(`e40f7bb0`, `350d1123`) |

| REQ-GD-06 | 노출 순서 | slug 등록 순서와 무관하게 우선순위로 고정 배열된다(레전드 재료 우선순위편이 1번) | `content/index.js:22-37` |

## 4. 데이터

| 무엇 | 테이블 · API | 비고 |
|---|---|---|
| 가이드 12편 | `web/src/domains/guides/content/*.js`(각 `{slug, title, seo, updatedAt, intro, sections}`) | 서버 없음, FE 전용. BE에 대응 패키지 없음 |
| 갱신 방법 | 코드 수정 후 배포 — 런타임 편집 경로 없음. `updatedAt`은 수동 관리 문자열 | 신규 콘텐츠 계획은 기획 초안(콘텐츠 계획 문서) 몫 |

## 5. 하지 않는 것

- 런타임 콘텐츠 편집·CMS 연동 — 코드 수정 후 배포로만 갱신한다
- HTML 문자열 기반 렌더링 — 구조화 객체만 받는다(REQ-GD-04)

## 6. 확인 필요

- ❓ `legendStatsGuide.js`가 인용하는 외부 단축 URL의 유효성 확인 절차 없음 — 만료 시 발견 방법이 없다
- ❓ 12편 중 6편은 구조·라우팅만 확인했고 콘텐츠 문구 원본 대조는 못 했다(사람 확인 필요)
- 콘텐츠 계획 문서(기획 초안)에 있던 향후 편 확장·구성 검토는 이 문서 범위 밖 — roadmap 몫으로 넘긴다
