## 2026-09-28 — 최신 회차 정렬 기준 변경 + 부분 수정 응답 오염 + 빈 테이블 캐시 미동작 수정

- 버전: 1.0.1 (patch)
- 커밋: `6254fd13`

**고친 것**

- 홈 화면 퀴즈 섹션이 "가장 늦게 등록한 것"(`ORDER BY id DESC`)을 최신으로 보여주던 것을, 도메인이 정한 유일한 순서 축인 회차 번호(`round`) 내림차순으로 바꿨다. 관리자가 회차를 순서 없이 등록해도 회차 기준으로 일치하도록 한 것 — 예전 리뷰가 제안한 "관리자 목록을 등록 순서에 맞추라"와는 반대 방향으로, 회차가 유일한 순서 축이라 조회 쪽을 바꿨다.
- 관리자가 퀴즈 수정 화면에서 회차만, 또는 이미지 URL만 바꾸고 저장하면 안 보낸 필드가 빈 값으로 덮어써지던 문제(둘 다 안 보내면 500 에러) — MapStruct 매핑에 "값이 없는 필드는 건드리지 않는다" 옵션을 추가했다.
- 퀴즈 수정 직후 응답의 "수정 시각"이 항상 옛 값이던 문제 — 등록 경로와 동일하게 저장 후 DB에서 다시 읽어 응답하도록 통일했다.
- 퀴즈가 0건일 때 조회 메서드가 예외를 던져 캐시가 전혀 동작하지 않던 문제 — 값이 없으면 예외 대신 `null`을 반환해 캐시에 올라가도록 하고, "없으면 404" 판정은 컨트롤러로 옮겼다.
- 저장소 전체에서 참조 0건인 `QuizVisibleRequest.java`(노출 여부 토글용 죽은 코드)를 삭제했다.

**손대지 말 것**

- `/api/admin/**` 관리자 전용 권한 규칙과 컨트롤러 메서드 권한은 이중으로 이미 걸려 있다 — 전역의 "API 기본 전체 허용" 문제는 퀴즈 관리자 경로에는 해당하지 않는다.
- quiz는 삭제 표시 컬럼 없이 행을 실제로 지우므로 "삭제 코드 재등록 충돌"이 없다 — 공지·이벤트에서 발견된 것과 같은 방어를 quiz에 추가하지 말 것.
- 퀴즈 쓰기 메서드 4곳은 이미 "트랜잭션 커밋 후 캐시를 지운다"는 안전한 순서를 쓰고 있다 — 순서를 바꿀 필요 없음.
- 참여·채점·보상 지급 코드가 없는 것은 결함이 아니다 — 저장소 전체에 참여 기록 테이블·제출 API·적립 연동이 없는 것 자체가 이 도메인의 현재 범위다. "정답 : 100스타" 문구는 화면 안내일 뿐 뒷단 구현 대상이 아니다.
- 퀴즈 전용 화면은 만들지 않기로 확정됐다 — 홈 화면 섹션 하나로 끝나는 것이 결함이 아니라 정해진 범위다. 다음 회차 자동 제안 기능도 만들지 않기로 확정됐다.

**미결**

- 정답 이미지의 공개 시점을 통제할 수단이 없음(저장 즉시 전체 공개, 화면은 "매주 금요일 12시 공개"를 약속) — 공개 시각을 담을 컬럼이 테이블에 없어 DB 구조 변경(컬럼 추가)이 필요하다. 사용자 승인 사안. 승인 전까지는 "다음 회차 정답을 미리 입력하지 않는다"는 운영 규칙으로 버틴다.
