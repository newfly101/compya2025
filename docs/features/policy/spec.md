# policy

## 1. 무엇을 하는 기능인가

개인정보처리방침·이용약관·사이트 소개·문의하기 4개의 정적 화면이다. 서버와 통신하지 않고 글이 코드 안에 그대로 담겨 있다. 구글 애드센스 심사 대비로 2026-08-31에 신설됐다.

## 2. 화면과 진입 경로

| 화면 | 주소 | 어디서 들어오나 |
|---|---|---|
| 개인정보처리방침 (SC-13-01) | `/privacy` | 이용약관·소개 화면의 링크, 마이페이지 탈퇴 안내 |
| 이용약관 (SC-13-02) | `/terms` | 개인정보처리방침·소개 화면의 링크 |
| 문의하기 (SC-13-03) | `/contact` | 소개 화면의 링크 |
| 사이트 소개 (SC-13-04) | `/about` | 전역 서랍/Footer 등에서 진입 |

## 4. 데이터

이 도메인은 서버 API·테이블이 없다. 4화면 모두 코드 안의 정적 문자열/배열만 렌더한다.

## 5. 하지 않는 것

- 법률 문구 자체를 완화하거나 고치는 것 — 법무 판단이 먼저다(§ 6)
- `EFFECTIVE_DATE`/`AMENDED_DATE`를 `new Date()` 같은 동적 계산으로 바꾸는 것 — 시행일이 매번 달라지는 회귀가 생긴다
- 소개 화면 "제공 기능" 목록에 가이드·마일리지·스킬 백과사전을 추가하는 것 — "모든 기능을 다 나열해야 한다"는 확정 규칙이 없어 결함으로 확정하지 않았다(`AboutScreen.jsx` `FEATURES`)
- 카카오톡 오픈채팅과 이메일 문의를 하나로 합치는 것 — 분리 안내가 정상 동작이다

## 6. 확인 필요

🔴 개인정보처리방침이 "탈퇴일로부터 1개월 보관 후 파기"라고 안내하지만, 실제로 그 파기 배치가 없다(`@Scheduled` 검색 0건) — 법무·기획 결정 사안. 파기 방식(행 삭제 vs 칸 비우기) 자체가 계정 기획에서 "보류"로 명시돼 있다. `users` 도메인 문서(§ 5)에도 같은 문제가 코드 관점으로 적혀 있다. 이 문서는 문구를 완화하지 않는다.

❓ 소개 화면의 "제공 기능" 목록을 지금처럼 일부만 보여줄지, 전체로 늘릴지 — 운영자 결정 사안. 결정되면 3줄 이내로 반영 가능.
