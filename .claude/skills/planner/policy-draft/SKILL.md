# Skill: planner-policy-draft

10년차 기획자 시점에서 **정책 결정 템플릿(Policy Draft)** 를 작성한다. ⭐ **확정 정책이 아니라 "결정 필요 항목 목록"**. 본 skill 은 정책을 합의하는 게 아니라, **무엇을 결정해야 하는지** 항목별로 표시한다.

## 1. 목적

- 정책 결정이 필요한 항목을 카테고리별 표 형태로 정리 (확정 X)
- 각 항목에 **마커** 부여 (🔴 강제 HITL 4 분야 / 🟨 가정 / ❓ 미정)
- 일반 항목은 합리적 default 추정으로 진행 가능
- 강제 HITL 4 분야는 🔴 마커 — 사용자 답변 전 확정 X
- requirements / feature-spec / edge-cases 에서 cite 할 수 있는 ID 부여

**산출물**: `docs/plan/{name}/policy-draft.md` (확정 X — Draft)

⭐ **promote 컨벤션**:
- `policy-draft.md` 는 사용자 / 운영자 / 법무 / 사업팀 합의 후 별도 라운드에서 `policy.md` 로 이름 변경 (promote)
- 본 skill 은 **promote 안 함** — 사용자 명시 요청 시 별도 라운드에서 처리

## 2. 입력 (input)

- **선행 산출물**:
  - `docs/plan/{name}/ia.md` (필수)
  - `docs/plan/{name}/requirements.md` (필수 — Forward 흐름 변경: requirements 가 policy 보다 먼저)
- **사용자 운영 정책 입력**: 강제 HITL 4 분야 (법무 / 결제 / 권한 / DB 파괴적) 만 사용자 답변 필수
- 호출 args:
  ```
  ia-path: docs/plan/{name}/ia.md
  requirements-path: docs/plan/{name}/requirements.md
  ```

## 3. 절차 (steps)

### Step 1 — IA + Requirements 로드
- IA 의 scope / 사용자 시나리오 추출
- Requirements 의 외부 의존 / 권한 / 보안 NFR cite
- 강제 HITL 4 분야 영향 항목 식별 (법무 / 결제 / 권한 / DB 파괴적)

### Step 2 — 정책 카테고리 점검 (체크리스트 형태)
다음 카테고리 점검 — 각 카테고리 항목별로 마커 (🔴 / 🟨 / ❓) 결정:

| 카테고리 | 예시 | 강제 HITL 분야? |
|---|---|---|
| 법적 (legal) | 개인정보 보호 / 약관 / 이용권리 | 🔴 강제 (법무) |
| 사업 (business) | 가격 정책 / 환불 정책 / 정산 | 🔴 강제 (결제 분야 한정) / 그 외 일반 |
| 운영 (operations) | 운영 시간 / SLA / 응대 정책 | 일반 (가정/미정 OK) |
| 외부 규정 (compliance) | KISA / GDPR / PCI-DSS / 전자상거래법 | 🔴 강제 (법무) |
| 사용자 권리 (user rights) | 탈퇴 / 데이터 삭제 / 알림 동의 | 🔴 강제 (법무) |
| 보안 (security) | 인증 정책 / 권한 등급 / SecurityConfig | 🔴 강제 (권한) |
| 데이터 (data) | 보관 기간 / 익명화 / 백업 / 마이그레이션 | 🔴 강제 (DB 파괴적) / 그 외 일반 |
| 쿠폰/이벤트 발급 정책 | 1인 N회 / 발급 채널 | 일반 (가정 OK) |

### Step 3 — 항목별 마커 부여 + 추정 default 작성
각 항목마다:
- ID: `POL-{도메인약어}-{번호}`
- 카테고리
- 한 줄 요약
- **마커** (🔴 / 🟨 / ❓)
- **추정 default** (있는 경우 — 일반 항목)
- **사용자 확정 답변** (받은 경우 — 그 외 빈 칸)
- 결정자 / 근거

⭐ **자동 진행 가능 여부**:
- 🟨 (가정) / ❓ (미정) 항목 → **추정 default 표시 후 진행 OK** — 후속 산출물에서 cite 가능 (단 마커 유지)
- 🔴 (위험) 항목 → 사용자 답변 받기 전 **확정 금지** — 후속 산출물에서 "🔴 사용자 답변 대기" 명시

### Step 4 — 산출물 Write
- `docs/plan/{name}/policy-draft.md` Write
- 헤더에 "Draft — 확정 X" 명시
- 모든 항목에 마커 부여

### Step 5 — 다음 skill 안내
보고:
- 산출물 경로
- 정책 항목 수 (🔴 강제 / 🟨 가정 / ❓ 미정 분포)
- 🔴 항목 → 사용자 답변 필요 항목 목록
- 다음 skill: `planner-feature-spec` (정책 cite 보강)

## 0. 마커 컨벤션

| 마커 | 의미 | 자동 진행? |

## 1. 개요

본 문서는 {도메인} 의 정책 결정 필요 항목을 마커 기반 표로 정리한다.

용어:
- **POL (Policy)**: 정책 항목 ID — `POL-{도메인약어}-{번호}`
- **마커 상태**: 🔴 위험 / 🟨 가정 / ❓ 미정
- **합의 상태**: 확정 (사용자 답변 받음) / Draft (마커만)

⚠ **강제 HITL 4 분야** (🔴 마커):
- 법무 (개인정보 / 약관 / 이용권리)
- 결제 (PG / 환불 / 정산)
- 권한 (인증 / 권한 등급 / SecurityConfig)
- DB 파괴적 변경 (DROP TABLE / DELETE / 마이그레이션)

위 항목은 사용자 답변 받기 전 **확정 금지**. 산출물에서 🔴 마커로 명시.

## 3. 정책 상세

### POL-{ABBR}-01: 쿠폰 발급은 1인 1회 (🟨 가정)

- **카테고리**: 사업 (business)
- **마커**: 🟨 가정
- **추정 default**: 동일한 쿠폰 코드는 1 사용자 (= 1 user_id) 당 최대 1회 발급
- **사유 (추정)**: 마케팅 비용 통제 + 어뷰징 방지 (일반적 패턴)
- **사용자 확정 답변**: (사용자 검토 시 답변)
- **적용 조건**: 모든 쿠폰 발급 채널 (앱 / 웹 / 푸시)
- **예외 (추정)**: 운영팀 직접 지급 (수동 발급) 시 본 정책 미적용
- **결정자**: PO + 운영팀
- **관련 FR/NFR**: FR-{ABBR}-N (쿠폰 발급 기능)
- **자동 진행 OK**: 추정 default 로 후속 산출물 cite 가능 (사용자 검토 시 수정 받기)

### POL-{ABBR}-02: 개인정보 보관 기간 (🔴 위험 — 법무)

- **카테고리**: 법적 (legal)
- **마커**: 🔴 위험 — **강제 HITL (법무 분야)**
- **추정 default**: ❌ 추정 금지 — 법령 의존
- **사용자 확정 답변**: (대기 — 법무팀 답변 필요)
- **사유**: 개인정보보호법 제21조 (파기) — 법령 위반 시 회사 책임
- **결정 필요 사항**:
  - [ ] 보관 기간 (예: 마지막 활동일로부터 1년? 5년?)
  - [ ] 결제 정보 별도 보관 기간 (전자상거래법 5년?)
  - [ ] 자동 삭제 vs 익명화
  - [ ] 사용자 동의 철회 시 처리 절차
- **결정자**: 법무
- **외부 cite**: 개인정보보호법 제21조 (https://www.law.go.kr/...)
- **자동 진행**: ❌ 금지 — 사용자 답변 받기 전 후속 산출물 cite 시 "🔴 사용자 답변 대기" 명시

### POL-{ABBR}-03: 환불 정책 (🔴 위험 — 결제)

- **카테고리**: 사업 / 결제
- **마커**: 🔴 위험 — **강제 HITL (결제 분야)**

  - [ ] 환불 조건 (사용 전 vs 부분 사용)
  - [ ] 환불 절차 (자동 vs 수동)
  - [ ] 환불 사유 카테고리
  - [ ] PG 환불 API 연동 방식
- **결정자**: PO + CS + 법무
- **자동 진행**: ❌ 금지

### POL-{ABBR}-04: 인증 방식 (🔴 위험 — 권한)

- **카테고리**: 보안 / 권한

## 6. HITL (Human-in-the-Loop) 지점

### 강제 HITL 4 분야 (자동 진행 절대 금지)

본 skill 의 산출물 중 다음 분야는 사용자 답변 전 확정 금지:
- **법무** — 개인정보 / 약관 / 이용권리 / 외부 규정
- **결제** — PG / 환불 / 정산 / 가격 정책
- **권한** — 인증 / 권한 등급 / SecurityConfig
- **DB 파괴적 변경** — DROP TABLE / DELETE / 마이그레이션

→ 위 항목은 🔴 마커 명시. 사용자 답변 받기 전 추정 default 작성 금지.

### 일반 HITL 완화 (가정/미정 표시 후 진행)

위 4 분야 외 일반 정책 항목은:
- 합리적 default / 추정으로 진행 OK
- 산출물에 🟨 가정 / ❓ 미정 마커 명시
- 사용자 검토 시 수정 가능

자동 진행 금지 사유 (🔴 항목 한정):
- 법적 / 외부 규정 위반 시 회사 책임
- 결제 / 환불 잘못된 추정 시 정산 / 회계 영향
- 권한 잘못된 추정 시 보안 사고
- DB 파괴적 변경 잘못된 추정 시 데이터 손실

## 9. 작성 원칙 (주니어 친화)

- **Draft 명시**: 헤더 / 본문 모두 "확정 X — Draft" 명시 — 사용자 / 리뷰어가 즉시 식별
- **마커 일관성**: 🔴 / 🟨 / ❓ 모든 항목에 부여 — 누락 금지
- **강제 HITL 4 분야 항목 추정 금지**: 🔴 항목은 "사용자 답변 대기" 만 — 임의 default X
- **일반 항목은 추정 default 작성 OK**: 🟨 / ❓ 항목은 후속 산출물 진행 가능
- **결정자 명시**: 누가 결정하는지 항상 명시
- **외부 cite**: 법령 / 외부 규정은 출처 링크
- **promote 안내**: 별도 라운드에서 `policy.md` 로 promote 명시
