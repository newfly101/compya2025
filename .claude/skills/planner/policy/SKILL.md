# Skill: planner-policy

10년차 기획자 시점에서 **정책서(Policy)** 를 작성한다. 정책 = 법적 / 사업 / 운영 / 외부 규정에 따른 결정. **자동 생성 절대 금지** — 본 skill 은 **템플릿 제공 + 사용자 채움 안내** 만 한다.

## 1. 목적

- 정책 항목을 분류 / 표 형태로 정리할 **빈 템플릿** 제공
- 각 항목의 결정 사유 / 적용 조건 / 예외 명시 가이드
- 운영자 / 법무 / 사업팀 합의가 필요한 항목 표시
- requirements / feature-spec / edge-cases 에서 cite 할 수 있는 ID 부여

**산출물**: `docs/plan/{name}/policy.md`

## 2. 입력 (input)

- **선행 산출물**: `docs/plan/{name}/ia.md` (필수)
  - (선택) `docs/plan/{name}/requirements.md` 가 있으면 cite 강화
- **사용자 운영 정책 입력**: ★ HITL 필수 — 사용자가 정책 항목을 직접 알려줘야 함
- 호출 args:
  ```
  ia-path: docs/plan/{name}/ia.md
  requirements-path: docs/plan/{name}/requirements.md  # 선택
  ```

## 3. 절차 (steps)

### Step 1 — IA / Requirements 로드
- IA 의 scope / 사용자 시나리오 / Owner 결정 항목 추출
- (있다면) requirements 의 외부 의존 항목 cite

### Step 2 — 정책 카테고리 점검 (체크리스트 형태)
다음 카테고리 점검 — 각 카테고리에 해당 항목 존재 여부를 사용자에게 묻는다:

| 카테고리 | 예시 | 본 도메인 적용? |
|---|---|---|
| 법적 (legal) | 개인정보 보호, 약관 | (사용자 답변 필요) |
| 사업 (business) | 가격 정책, 환불 정책, 쿠폰 발급 정책 | (사용자 답변 필요) |
| 운영 (operations) | 운영 시간, SLA, 응대 정책 | (사용자 답변 필요) |
| 외부 규정 (compliance) | KISA / GDPR / PCI-DSS / 전자상거래법 | (사용자 답변 필요) |
| 사용자 권리 (user rights) | 탈퇴 / 데이터 삭제 / 알림 수신 동의 | (사용자 답변 필요) |
| 보안 (security) | 인증 정책 / 비밀번호 / 토큰 만료 | (사용자 답변 필요) |
| 데이터 (data) | 보관 기간 / 익명화 / 백업 | (사용자 답변 필요) |

### Step 3 — ★ HITL 2: 사용자에게 항목별 채우기 요청
- 위 카테고리 표를 사용자에게 보여주고
- 각 카테고리에 해당하는 정책이 있는지 답변 받기
- 있다면 내용 / 사유 / 적용 조건 / 예외를 받기
- **답변이 부정확하면 자동 생성 금지** — "운영팀 / 법무팀 합의 후 회신" 으로 두기

### Step 4 — 정책 ID 부여 + 표 작성
- 정책 ID: `POL-{도메인약어}-{번호}`
- 사용자 답변 기반으로 표 채움
- 미정 항목은 "★ 합의 필요" 명시 — 임의 채움 금지

### Step 5 — 산출물 Write
- `docs/plan/{name}/policy.md` Write
- 미정 항목 명확히 표시

### Step 6 — 다음 skill 안내
보고:
- 산출물 경로
- 정책 항목 수 (확정 / 미정)
- 미정 항목 → 합의 필요 안내
- 다음 skill: `planner-requirements` (미작성 시) 또는 `planner-feature-spec` (이미 작성 시 정책 cite 보강)

## 4. 템플릿 (산출물)

```markdown
# 정책서 — {도메인/기능명}

> 작성일: YYYY-MM-DD
> 선행 문서: [ia.md](./ia.md)
> 후속 영향: [requirements.md](./requirements.md), [feature-spec.md](./feature-spec.md), [edge-cases.md](./edge-cases.md)
>
> **⚠ 본 문서의 모든 항목은 운영자 / 법무 / 사업팀 합의 후 확정된 내용이다.**
> **자동 생성 금지 — planner skill 은 템플릿만 제공하고, 내용은 사용자가 채운다.**

## 0. ★ HITL (Human-in-the-loop) 안내

본 정책서는 다음 주체의 합의가 필요하다:
- **법적 항목**: 법무팀 / 외부 자문
- **사업 항목**: PO / 사업팀
- **운영 항목**: 운영팀 / CS
- **보안 항목**: 보안 담당자

planner agent 는 **템플릿 + 카테고리 점검만 제공**한다. 미합의 항목은 "★ 합의 필요" 로 표시되며, 합의 전에는 후속 산출물에서 cite 금지.

## 1. 개요

본 문서는 {도메인} 의 정책 (법적 / 사업 / 운영 / 외부 규정 / 사용자 권리 / 보안 / 데이터) 을 ID 기반 표로 정리한다.

용어:
- **POL (Policy)**: 정책 항목 ID — `POL-{도메인약어}-{번호}`
- **합의 상태**: 확정 (운영자 사인 완료) / 합의 필요 (★ 미결) / 보류 (차후 결정)

## 2. 정책 요약 표

| ID | 카테고리 | 한 줄 요약 | 합의 상태 | 결정자 | 효력 일자 |
|---|---|---|---|---|---|
| POL-{ABBR}-01 | 사업 | 쿠폰 발급은 1인 1회 | 확정 | PO / 운영팀 | 2026-01-01 |
| POL-{ABBR}-02 | 법적 | 개인정보 보관 1년 | 확정 | 법무 | 2026-01-01 |
| POL-{ABBR}-03 | 운영 | ★ 합의 필요 | 미결 | 운영팀 | TBD |

## 3. 정책 상세

### POL-{ABBR}-01: 쿠폰 발급은 1인 1회

- **카테고리**: 사업 (business)
- **내용**: 동일한 쿠폰 코드는 1 사용자 (= 1 user_id) 당 최대 1회 발급한다.
- **사유**: 마케팅 비용 통제 + 어뷰징 방지
- **적용 조건**: 모든 쿠폰 발급 채널 (앱 / 웹 / 푸시)
- **예외**: 운영팀 직접 지급 (수동 발급) 시 본 정책 미적용 — 별도 정책 POL-{ABBR}-NN 참조
- **합의 상태**: 확정 (2026-01-01)
- **결정자**: PO + 운영팀
- **관련 FR/NFR**: FR-{ABBR}-N (쿠폰 발급 기능)
- **변경 이력**: -

### POL-{ABBR}-02: 개인정보 보관 1년

- **카테고리**: 법적 (legal)
- **내용**: 사용자 개인정보 (이름 / 전화번호 / 이메일) 는 마지막 활동일로부터 1년간 보관 후 자동 삭제한다.
- **사유**: 개인정보보호법 제21조 (파기) 준수
- **적용 조건**: 모든 사용자 데이터
- **예외**: 결제 정보는 전자상거래법에 따라 5년 보관 (POL-{ABBR}-NN 참조)
- **합의 상태**: 확정 (2026-01-01)
- **결정자**: 법무
- **관련 FR/NFR**: NFR-{ABBR}-N (데이터 보관)
- **변경 이력**: -

### POL-{ABBR}-03: ★ 합의 필요 — 환불 정책

- **카테고리**: 사업
- **내용**: TBD — 환불 가능 기간 / 조건 / 절차
- **사유**: TBD
- **적용 조건**: TBD
- **예외**: TBD
- **합의 상태**: ★ 합의 필요
- **결정자**: PO + CS + 법무
- **합의 필요 사항**:
  - [ ] 환불 가능 기간 (예: 7일)
  - [ ] 환불 조건 (사용 전 vs 부분 사용)
  - [ ] 환불 절차 (자동 vs 수동)
  - [ ] 환불 사유 카테고리
- **관련 FR/NFR**: TBD
```

- [ ] 카테고리 점검 표 작성 (모든 카테고리 적용/해당 없음 명시)

- [ ] **자동 생성 금지 점검**: 임의 추측 항목 0건

## 6. ★ HITL 지점 (필수 — 모든 항목)

**HITL 2 (강제, 모든 항목)**:
- 본 skill 은 **템플릿만 제공**한다
- 모든 항목은 사용자 / 운영자 합의 필요
- planner agent 는 사용자에게 카테고리별 정책 존재 여부 / 내용 / 사유를 묻는다
- 답변 없는 항목은 "★ 합의 필요" 로 두기 — **임의 채움 절대 금지**

자동 생성 금지 사유:
- 법적 / 외부 규정 위반 시 회사 책임
- 사업 / 운영 정책은 회사별 전략 — agent 가 결정 불가
- 사용자 권리 / 보안 / 데이터 정책은 컴플라이언스 영역

## 9. 작성 원칙 (주니어 친화)

- **자동 생성 절대 금지**: agent 가 정책 추측 X — 사용자 답변만
- **결정자 명시**: 누가 결정하는지 / 누구의 합의가 필요한지 항상 명시
- **외부 cite**: 법령 / 외부 규정은 출처 링크 — 주니어가 follow-up 학습 가능
- **★ 합의 필요 명시**: 미결 항목 "TBD" 단독 X — "★ 합의 필요 + 결정자 + 합의 사항 체크박스"
- **이력 추적**: 변경 이력 표 — 누가 / 언제 / 무엇을 결정했는지 추적
