# 버전 영향 판단 · 커밋 표기

> 두 축: 기능 `vX.Y.Z`(이용자가 체감) · 플랫폼 `platform-X.Y`(개발자가 체감). 기준선 `v2.0.0 (platform-2.0)`. 태그·릴리스 절차는 `.claude/conventions/release-procedure.md`, 배경은 `docs/decisions/0002-versioning-two-axes.md`.

## 1. 판단 순서

- [ ] 이용자·운영자가 눈으로 차이를 느끼나 → 기능 축 (아니면 기능 불변)
- [ ] 새 언어·도구를 배워야 하거나 rules 문서가 바뀌나 → 플랫폼 MAJOR
- [ ] 규칙은 그대로, 빌드 구조·주요 의존성 메이저만 바뀌나 → 플랫폼 MINOR
- [ ] 둘 다 아니면 → 불변, CHANGELOG `Internal` 1줄
- [ ] 한 릴리스에 여러 변경 → 축마다 가장 큰 단계 하나

## 2. 경계표

| 변경 | 기능 | 플랫폼 |
|---|---|---|
| 신규 화면 · 기존 화면 필터/탭 추가 · 어드민 신규 탭/API · 기능 제거(`Removed`) | MINOR | — |
| 버그 · 문구 · 레이아웃 깨짐 · 체감 속도 | PATCH | — |
| 전면 UX 개편 (내비 체계 교체) | MAJOR | 보통 MAJOR |
| TS 도입 · Kotlin 추가 · 상태관리 교체 · `sql/V{N}` 세대 교체 · FE/BE 아키텍처 재편 | — | MAJOR |
| 멀티모듈 분리 · 프레임워크 메이저 업 (Boot 3→4, React 19→20) | — | MINOR |
| 동작 불변 리팩터 · 라이브러리 패치 · 배포 파이프라인 | — | — (`Internal`) |
| 기존 세대 안 테이블·컬럼 추가 | 연결된 기능 기준 | — |

커밋 type: `feat`→MINOR · `fix`/`perf`→PATCH · `refactor`→없음(위 표 해당 시 플랫폼 후보) · `chore`/`docs`→없음. 플랫폼 커밋은 설명에 `platform:` 접두.

## 3. 커밋 본문 `버전 영향:` 줄 — 자동 집계가 문자열 매칭에 의존한다

```
버전 영향: 기능 {값} / 플랫폼 {값}
```

| 축 | 닫힌 값 목록 |
|---|---|
| 기능 | `MAJOR` · `MINOR` · `PATCH (vX.Y.Z 후보)` · `무영향` |
| 플랫폼 | `MAJOR` · `MINOR` · `무영향` |

- 두 축 **항상 함께**. 값은 목록 밖 단어(`없음`) 금지. 사유는 값 뒤 괄호 — `기능 무영향 (주석만)`
- 자주 쓰는 사유: `(주석만)` `(죽은 코드 제거)` `(내부 규약 통일)` `(동반 배포 — {파일})`
- **동반 배포**: 표기상 PATCH 인데 서버·화면을 같이 올려야 하는 변경(오류 코드 문자열, 응답 status 변경)은 사유에 `(동반 배포 — client.js)` 를 적는다 ❓ 정식 규약은 미정 (0002 § 관측)
- 지난 커밋은 고치지 않는다. 과거 4갈래 표기의 해석표는 0002

예: `버전 영향: 기능 PATCH (v2.0.1 후보) / 플랫폼 무영향` · `버전 영향: 기능 무영향 (동작 불변) / 플랫폼 무영향`

## 4. 트랙별 CHANGELOG 기록

| 트랙 | 기록 |
|---|---|
| develop | 기능 변경 `Added/Changed/Fixed`, 플랫폼 변경 `Platform` → `CHANGELOG.md` `[Unreleased]` |
| planner · designer | 기록 안 함 — 코드 반영 시 develop 이 한 번만 |
| ops | 이용자 무관 `Internal`, 구조 변경 `Platform` |
