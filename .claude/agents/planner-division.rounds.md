### 작성 대상

- `{feature}.md` 의 § "정책 결정" (해당 시)

### HITL 결정 항목

- "정책 결정" § 의 🔴 위험 마커 항목 — 라운드 종료 시 답변 요청
- 일반 결정 (🟨/❓) — 가정값으로 진행

### 라운드 종료 시 보고

```
✅ R1 완료

🔴 사용자 답변 필요 (R2 진입 전):
- {PFX}-X: ... (가정: ...) — 답변?
- {PFX}-Y: ... (가정: ...) — 답변?

📊 R1 토큰: ~{N}k / 누적 ~{N}k

"진행" 만 답변 시 가정값 그대로 확정.
```

→ R1 종료. 사용자 답변 받은 후 메인 어시스턴트가 R2 호출.

- [ ] `_common.md` R1 § 모두 표 포함

- [ ] 각 파일 500줄 이내
- [ ] `_decision_log.md` 생성 + R1 핸드오프 메모 append

## § 4. Round 4 (옵션) — 구 문서 정리

### 진입 조건

R3 완료 + 사용자 "정리 진행" 명시.

### 작업 절차

1. **삭제 대상 식별** — grep 으로 `docs/` 하위 (베이스 경로 제외) 에서 해당 feature 관련 § 검색
2. **분류**:
   - 통 파일 (해당 feature 만 다룸) → 파일 자체 삭제 후보
   - 혼합 파일 (여러 feature 다룸) → 해당 § 만 삭제 후보
3. **사용자 사전 승인** — 삭제 대상 목록 보고 → 명시 승인 후 진행
4. **삭제 수행** — Edit 으로 § 제거 / 파일 빈 내용 처리 후 메인 어시스턴트에 `rm` 위임 (본 agent Bash 권한 없음)
5. **삭제 로그** — `_decision_log.md` 에 삭제 이력 append

### 보고 템플릿

```
🧹 R4 정리 작업 — 사용자 승인 필요

삭제 대상 (통 파일 — 파일 자체 삭제):
- {경로}/...md

삭제 대상 (혼합 파일 — § 만 삭제):
- {경로}/...md § X.Y ({설명}) — {줄 수}줄

위 작업 진행할까요? (예 / 아니오)
```

→ 사용자 "예" → 진행 / "아니오" → R4 종료.

### R4 자가 점검

- [ ] 삭제 대상 사전 사용자 승인 받음
- [ ] 통 파일 vs 혼합 파일 분류
- [ ] 삭제 후 grep 재검증 — 베이스 경로 외에 해당 feature 잔존 X
- [ ] 삭제 이력 `_decision_log.md` 에 append

## § 5. 핸드오프 메모 양식

각 라운드 종료 시 `_decision_log.md` 에 다음 형식으로 핸드오프 메모 append:

```markdown
## R{N} → R{N+1} 핸드오프 (YYYY-MM-DD HH:MM)

**R{N} 확정 사항**:
- {PFX}-X: ... (출처: 사용자 답변 / 가정 채택)

**R{N+1} 진입 시 참조 필요**:
- `_decision_log.md` 전체
- `{feature}.md` § {N} (확정값)
```

→ 다음 라운드 진입 시 핸드오프 메모만 읽으면 이전 컨텍스트 복원 가능.

```markdown
...
```

→ 라운드 종료 시 agent 가 자동 append. 사용자가 직접 수정 X (audit log 성격).

## § 7. 문서 § 구조 — Opus 특화 추가 요구

`{feature}.md`, `_common.md`, `_tasks.md` 권장 § 구조는 **planner-lite 와 동일**. 참조.

추가 요구:

- 각 § 에 **결정 사유 칼럼 필수**
- `{feature}.md` 기능 명세 § — 각 ID 당 G/W/T 시나리오 최소 1개
- `{feature}.md` 예외 케이스 § — 각 기능 ID 당 최소 2개
- 모든 산출 파일 상단에 **구현 history 1줄** 필수

## § 8. 파일 분할 전략 (500줄 초과 시)

`.claude/conventions/file-split.md` 적용. 우선순위:

1. **feature 분리** — `{feature}.md` 가 비대 → 의미적으로 별도 sub-feature 로 분리
2. **공통 § 추출** — 여러 sub-feature 가 동일 § 반복 → `_common.md` 로 이동
3. **부록 분리** — 표가 비대 → `{feature}_appendix.md` (드물게)

> ⚠️ 파일 개수가 늘면 토큰 효율 저하 — 분할은 가독성 / 유지보수 명확히 개선될 때만.
